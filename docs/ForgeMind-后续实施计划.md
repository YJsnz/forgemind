# ForgeMind 后续实施计划

> 文档状态：执行基线 1.0
>
> 基线日期：2026-09-08
>
> 适用范围：ForgeMind、ForgePass、ForgeCloud、ForgeHub、ForgeLab、ForgeMove，以及与其配套的 AI、语音、视觉、桌面端和硬件验证工作
>
> 权威关系：根目录《ForgeMind 项目方案.md》是唯一权威方案；《ForgeMind-当前实现总览.md》记录代码事实；本文只负责把已确认路线拆成可排期、可验收的执行任务，不得将“计划中”写成“已实现”

## 1. 文档目的

本计划回答五个具体问题：

1. ForgeMind 在现有可演示闭环基础上，下一步应优先补什么。
2. 每一阶段要交付哪些代码、数据、文档和可验证结果。
3. 各能力之间有哪些前置依赖，哪些工作不能越级开展。
4. 如何证明 Agent、What-if、RAG、语音和诊断的结果可信且可复现。
5. 如何在不夸大工业化程度的前提下，完成一个可部署、可回滚、可复盘的现场试点。

本文采用“24 周完整路线 + 前 12 周试点主线”的相对排期。周次从正式启动评审通过后的第一个工作周开始，不绑定自然日期；若人员或现场条件变化，应调整周次，但不得跳过质量门禁。

## 2. 当前基线

### 2.1 已有能力

截至基线日期，项目已经具备以下可继续演进的基础：

- 浏览器端固定步长确定性仿真、多楼层网格、设备端口、传送带、库存守恒、AGV 八方向 A*、无人机三维 26 邻域 A*、生产节拍与阻塞分析。
- 黛玉确定性规划/诊断与宝钗渲染层，支持工厂图谱、Finding、候选方案、分支副本仿真、结构校验、Patch、人工审批、应用后复核和回滚。
- Generative Factory 的 A-01/A-02 生成路径，以及节能、均衡、吞吐等 Top 3 What-if 候选对比。
- Agent 的运行、步骤、工具、事件、报告和服务端只读异步编排；写操作继续受版本、权限、校验和确认门控约束。
- 自动巡检、最小二乘趋势/ETA、瓶颈评分、能耗归因、库存预测和主动提醒。
- BT 语音唤醒、VAD 自动分轮、连续会话、BT-7274 TTS、主动播报、长上下文摘要和失败降级。
- RAG 的产品/流程/运行摘要/用户记忆分层检索，30 个助手工具契约，用户批准的长期记忆和质量指标账本。
- PCB YOLO 检测演示与结构化视觉结果桥接。
- ForgePass 统一身份；ForgeCloud 的工作空间、项目版本、资源、发布、任务、审批、设备、孪生、数据、AI、知识库、审计与 Outbox 基础；ForgeHub 的 Web CAD、STEP/B-Rep、装配、BOM 和高精细资源；ForgeLab 社区；ForgeMove 移动摘要与任务入口。

### 2.2 当前边界

以下事项尚不能作为已完成工业能力对外承诺：

- 尚无完整生产级 OPC UA/MQTT 客户端、连接器运行时和设备命令执行器。
- 设备命令默认只进入待处理审计队列，不直接驱动物理设备。
- 运行数据以 MySQL 事件和遥测窗口为主，尚未接入专业时序引擎。
- Asset Blob 默认使用本地对象存储适配层，MinIO/S3 部署适配尚未完成。
- 仿真是离散事件/规则级数字孪生，不等同于 PLC 虚拟调试或高精度物理仿真；尚缺现场节拍、故障和能耗标定。
- 多车/多机共享服务位预约与长时间窗拥堵验证仍需加强。
- AI 默认可使用规则路径；本地或远程大模型均为可选，不能决定坐标、碰撞、库存、寻路和仿真真值。
- RAG 的嵌入模型可选，仍需扩大评测集并验证知识版本、引用覆盖和错误拒答。
- 语音尚需在真实车间噪声、回声、插话和麦克风差异下验收。
- 视觉能力以 PCB 演示为主，尚未完整绑定批次、工单、质量处置和复检。
- ForgeHub 尚未完成 ForgeCloud 直接发布、公共资源治理、依赖/Fork 和多人 PDM。
- Unity/WebView2 功能保真和性能门禁尚未完全闭环；DM4310 固件未完成 ESP32 编译烧录与真机验收。
- 部分第三方工业模型的再分发许可仍需逐文件复核。

## 3. 总体目标与非目标

### 3.1 24 周目标

完成一条可审计的工业试点链路：

“设计版本发布 → 只读现场数据接入 → 孪生映射与标定 → 异常检测/诊断 → What-if 同源分支验证 → Agent 提案 → 人工审批 → 受控执行或人工处置 → 效果复核 → 版本与证据归档”。

最终交付应满足：离线核心仍可独立运行，联网能力可降级；事实来源可追踪；关键计算可复现；所有写操作可审批、可拒绝、可回滚；系统能够在一个小规模现场或高可信半实物环境中连续运行并形成验收报告。

### 3.2 明确非目标

- 不在本周期内把 ForgeMind 宣称为通用 MES、SCADA、PLM、PDM 或 PLC 工程平台的替代品。
- 不让大语言模型直接写入坐标、库存、工艺数量、碰撞结论、寻路结果或设备控制结果。
- 不在未完成安全评审和现场联锁前开放无人值守设备控制。
- 不用单次演示视频代替稳定性、性能、数据一致性和恢复验证。
- 不以接入更多模型数量作为 AI 完成度；优先评价工具正确率、证据完整性、拒答能力和业务闭环。
- 不因云端能力增加而破坏本地离线演示和确定性仿真的可用性。

## 4. 实施原则

1. **仿真与规则是真值层。** AI 负责理解、检索、解释、编排和文案，不覆盖确定性结果。
2. **先只读、后建议、再受控执行。** 现场连接先建立观测可信度，再开放工单或命令提案，最后才考虑有限执行。
3. **同源比较。** What-if 候选必须使用相同初始快照、随机种子、仿真时长、订单和评价函数。
4. **证据优先。** Finding、建议和审批必须能回到数据窗口、对象、版本、规则和仿真结果。
5. **版本优先。** 设计、资源、连接器映射、标定参数、AI 知识和 Patch 均需要版本或哈希标识。
6. **失败可恢复。** 网络、AI、语音、视觉或云端故障不能破坏本地存档；重要操作必须幂等、可重试、可回滚。
7. **最小授权。** 工作空间、项目和设备动作分别校验身份、角色、版本和确认状态。
8. **指标先于优化。** 先建立基准、日志和质量门禁，再做性能或模型调优。

## 5. 优先级与依赖

| 优先级 | 定义 | 本计划范围 |
| --- | --- | --- |
| P0 | 不完成就无法安全试点或无法证明结果可信 | 确定性基线、数据契约、只读连接器、去重与回放、权限审计、备份恢复、试点验收 |
| P1 | 显著增强诊断闭环和产品价值 | 标定、时序分析、What-if 规模化、Agent 效果复核、RAG 评测、语音噪声测试、视觉质量闭环 |
| P2 | 产品化与生态扩展 | 对象存储、ForgeHub 云端发布、移动离线队列、Unity 保真、DM4310 真机、公共资源治理 |

核心依赖顺序如下：

`可复现基线 → 统一事件/对象标识 → 只读现场接入 → 映射与标定 → 诊断证据 → What-if/Agent 提案 → 审批与受控执行 → 效果复核`。

任何涉及设备写入的任务，都依赖只读链路稳定、权限矩阵完成、幂等命令与回执可用、安全联锁评审通过四个条件。

## 6. 24 周分阶段路线

### 阶段 0：基线冻结与质量底座（第 1–3 周，P0）

**目标：** 建立所有后续优化可比较的统一基线。

任务：

- 固定三个基准项目：S-01 最小产线、S-02 多楼层物流、S-03 500+ 原始模型复杂工厂；保存项目版本、资源哈希、随机种子和仿真配置。
- 为相同存档、种子和时长建立结果摘要哈希，覆盖成品、在制品、库存、设备利用率、阻塞、运输和能耗。
- 建立前端、后端、AI、ForgeHub、ForgeMove 的分层回归清单，区分必跑、定向和人工验收。
- 为运行日志统一 `traceId/workspaceId/projectId/versionId/runId/sourceId/externalEventId` 上下文字段。
- 对已知告警、开发依赖漏洞、构建大包、WASM 内存限制建立可追踪清单，禁止在报告中写成“全量无问题”。
- 完成第三方工业模型、Panda、AGV、无人机和高精细资源的许可证、来源、修改声明与 SHA-256 复核。
- 制定试点数据最小化、脱敏、保留期限和导出删除规则。

交付物：基准存档包、回归矩阵、性能基线报告、许可证差距表、日志字段规范、试点数据治理说明。

退出条件：三套基准均可一键加载；同环境重复运行的确定性摘要一致；关键门禁命令可执行；所有未知许可资产被隔离或明确标记为不可分发。

### 阶段 1：工业数据只读接入（第 4–7 周，P0）

**目标：** 从“模拟数据/手工回放”升级到可审计的只读现场事实接入。

任务：

- 定义连接器 SDK：连接配置、健康检查、点位发现、采样、断线重连、游标/checkpoint、质量码、时间戳和错误分类。
- 实现 OPC UA 与 MQTT 只读适配器的最小可用版本；凭据只保存在服务端环境或密钥设施，不进入浏览器、日志和仓库。
- 建立外部点位到 `workspace/project/device/twin/dataPoint` 的映射界面和版本化映射记录。
- 复用现有外部事件唯一约束，补齐批量写入、乱序、重复、迟到事件和断线补传测试。
- 将连接器原始输入、标准化事件、遥测窗口和消费状态串成可回放链路。
- 为连接器增加“模拟源、文件回放、真实只读源”三种模式，试点前先用回放模式压测。
- 建立连接状态、最近成功时间、延迟、错误率、积压和丢弃原因的运维视图。

交付物：连接器契约、OPC UA/MQTT 只读适配器、映射页、回放工具、连接器运行手册和故障注入报告。

退出条件：重复事件不产生重复事实；断线后可从 checkpoint 恢复；错误质量码不进入有效指标；跨工作空间映射被服务端拒绝；连续 24 小时回放无不可解释数据缺口。

### 阶段 2：孪生映射、时序分析与现场标定（第 8–11 周，P0/P1）

**目标：** 让现场事实与仿真对象、节拍和评价指标形成可解释对应关系。

任务：

- 建立资产—设备—端口—工艺节点—点位映射，映射变更必须生成新版本并保留历史。
- 引入批次/工单关联，使物料、视觉结果、异常和产量能够追踪到同一生产上下文。
- 定义节拍、停机、等待、阻塞、故障、能耗的计算口径，明确原始值、派生值与估计值。
- 建立专业时序引擎选型实验；在未选定前保持 MySQL 窗口聚合作为兼容路径，不直接替换现有事实账本。
- 实现标定配置：设备额定周期、换型时间、故障/修复分布、运输速度、装卸时间、待机/运行功率。
- 用历史窗口对仿真输出做误差分析，记录 MAPE、偏差方向和数据覆盖；标定参数必须可版本化和回滚。
- 对 AGV/无人机补充共享服务位预约、冲突消解、超时释放和长时间窗拥堵回归。

交付物：孪生映射版本、批次/工单链路、指标口径字典、时序选型报告、标定配置与误差报告、多载具拥堵回归集。

退出条件：选定试点工艺的关键对象映射覆盖率达到 100%；同一数据窗口可重放出相同派生指标；标定前后误差有明确量化；冲突预约不造成库存复制、负库存或永久锁死。

### 阶段 3：诊断、RAG、语音与视觉增强（第 12–15 周，P1）

**目标：** 提高诊断解释质量和人机交互可靠性，同时保持事实安全边界。

任务：

- 将结构、时序、能耗、库存、质量和维护证据统一为带来源的 Finding；每条 Finding 包含严重度、对象、时间窗、规则版本、证据值和建议下一步。
- 完善诊断算法：结构瓶颈与时序瓶颈交叉验证、异常基线分层、变化点提示、置信度和数据不足状态。
- 建立 Agent/助手固定评测集，覆盖正确工具、错误拒绝、确认门控、版本冲突、动态事实重读、多轮任务和降级。
- 扩充 RAG 评测集，验证 Recall@4、MRR、知识版本过滤、引用覆盖、失效知识隔离和无证据拒答。
- 语音在安静办公、播放车间噪声和真实现场三种条件下测试唤醒、误唤醒、VAD 分轮、打断、回声和首段响应时延。
- 将视觉结果绑定相机、产品、批次、工单、检测模型版本和同源帧；补齐不合格、复检、关闭和审计状态。
- 主动提醒执行抑制、合并、升级和静默策略，避免同类事件重复轰炸。

交付物：统一 Finding 规范、诊断评测报告、助手/RAG 基准集、语音噪声测试报告、视觉质量闭环和主动提醒策略表。

退出条件：动态工厂事实违规由 AI 直接生成的次数为 0；危险或写入工具无确认执行次数为 0；知识型回答能追踪到知识版本；视觉异常能追踪到批次/工单并完成处置状态闭环。

### 阶段 4：What-if 规模化与可信 Agent 执行（第 16–19 周，P1）

**目标：** 把方案对比从演示功能提升为可复现、可排队、可复核的决策流程。

任务：

- 将 What-if 任务显式记录初始版本、初始状态哈希、种子、时长、订单、约束、算法版本和评价权重。
- 支持候选并行执行、取消、超时、进度、结果缓存和资源上限；缓存键必须覆盖所有影响结果的输入。
- 对多目标结果同时展示原始指标、归一化方法、权重和 Pareto 关系，禁止只显示无法解释的综合分。
- 对每个候选执行布局、端口、碰撞、路径、库存守恒、产能和安全约束校验；失败候选保留失败原因，不进入可应用列表。
- Agent 形成完整的“观察—证据—诊断—方案—验证—审批—应用—复核—回滚”事件链。
- 应用 Patch 前校验权限、项目版本、对象存在性、前置条件和影响范围；应用后自动在新版本执行相同窗口复核。
- 建立建议效果账本，记录预期与实际差异，但不允许模型绕过人工审批自行学习后直接控制现场。
- 只在安全评审通过的白名单动作上试验设备命令执行器；必须支持幂等键、过期时间、双人复核、回执和紧急停止。

交付物：What-if 作业模型与结果包、Pareto 对比页、Agent 全链路报告、Patch 安全矩阵、效果账本、受控命令 PoC（若安全条件满足）。

退出条件：相同输入重复运行结果一致；失败候选不可应用；陈旧版本 Patch 被拒绝；批准后的应用和回滚在固定用例矩阵中全部成功；未满足安全条件时设备执行器保持关闭且不影响阶段通过。

### 阶段 5：生态整合与部署产品化（第 20–22 周，P1/P2）

**目标：** 打通资源、项目、移动协作和部署运维，形成可交付产品包。

任务：

- 完成 MinIO/S3 适配、分片/大文件上传、哈希去重、鉴权下载、软删除、生命周期和备份恢复。
- ForgeHub 将 CAD/资源版本发布到 ForgeCloud，携带许可证快照、依赖 manifest、预览、BOM、源文件和派生文件关系。
- 建立资源 Fork/依赖冲突和下架影响分析；公共市场与多人 PDM 若资源不足，可保留为下一周期，不阻塞私有工作空间发布。
- ForgeMove 增加生产级离线队列、重试、冲突提示和推送配置；继续保持摘要/审批定位，不复制三维工作台。
- 完成 Unity/WebView2 功能保真矩阵，明确可替换渲染表面、不可替换业务界面和降级路径。
- 完成容器化部署、健康检查、日志采集、指标告警、数据库备份、对象备份、恢复演练和升级/回滚脚本。
- 完成依赖、镜像、密钥、CORS、上传文件、审计留存和跨工作空间隔离安全检查。

交付物：部署包、对象存储适配、ForgeHub 发布链、移动离线队列、桌面端保真报告、运维手册、安全检查报告和恢复演练记录。

退出条件：新环境按文档可重复部署；备份可恢复；资源发布链可追踪许可证与依赖；断网不破坏本地存档；跨工作空间访问和越权写入固定测试全部拒绝。

### 阶段 6：试点运行与验收移交（第 23–24 周，P0）

**目标：** 用真实过程和证据证明系统可用，而不是只证明页面可打开。

建议试点范围：5–10 台设备、2–3 条工艺/配方、1 条入库到成品的物料流、1 条 AGV 或无人机物流路径、1 个视觉检测点、1 组只读工业数据源。

任务：

- 冻结试点版本、资产、连接器映射、标定参数、知识库版本和回滚包。
- 先运行旁路只读模式，再运行诊断建议模式；受控执行仅在现场安全评审通过后启用。
- 执行正常生产、断网、重复数据、数据延迟、设备离线、质量异常、库存不足、路径阻塞、AI 不可用和回滚场景。
- 每日形成数据完整性、异常、建议、人工决策和恢复记录；每周复盘误报、漏报、建议收益和操作负担。
- 交付管理员、工艺工程师、操作员和维护人员四类培训材料。

交付物：试点部署记录、每日/每周报告、验收证据包、培训材料、问题清单、回滚包和下一周期建议。

退出条件：P0 验收指标全部达标；未达标项有责任人、原因、规避措施和关闭日期；现场能够在 AI、语音或云端不可用时继续执行核心只读/仿真流程。

## 7. 十条工作流的具体实施清单

### 7.1 仿真与渲染

- 为固定步长、事件顺序、随机源和浮点摘要建立确定性约束。
- 把性能指标拆成 CPU 仿真、Worker、渲染提交、显存/内存、资源加载和 UI 响应，不用平均 FPS 掩盖长帧。
- 按距离、可见性和交互状态实施 LOD/实例化/懒加载；高精细 CAD 与可编辑几何继续按需生成和缓存。
- 所有优化必须通过库存守恒、路径、设备状态和结果哈希回归，不得以降低模型正确性换帧率。

### 7.2 工业连接与数据治理

- 标准事件至少包含来源、外部 ID、采集时间、接收时间、对象、点位、值、单位、质量码和映射版本。
- 原始层不可被派生值覆盖；纠正数据使用追加记录或版本，不直接静默修改历史事实。
- 明确保留期限、压缩、聚合、冷热分层、导出和删除责任。
- 连接器凭据轮换、连接测试、错误脱敏和审计为上线必选项。

### 7.3 诊断算法

- 结构诊断回答“为什么布局/端口/物流会形成约束”。
- 时序诊断回答“何时开始恶化、持续多久、是否超过自身基线”。
- 因果链只表达规则和数据支持的依赖，不把相关性包装成已证明因果。
- 置信度由数据覆盖、质量码、样本长度、规则一致性和仿真复核共同决定；数据不足必须显式返回“不足以判断”。

### 7.4 What-if 方案分析

- 每个方案保留人类可读的变更摘要和机器可执行 Patch。
- 同时输出吞吐、周期、在制品、阻塞、运输、库存、能耗、改造成本代理指标和约束违反情况。
- 综合排名必须可切换权重并展示敏感性；不同权重导致排名变化时主动提示。
- 方案应用前后用同一评价窗口复核，并将差值写入 Agent 报告与版本记录。

### 7.5 Agent 诊断逻辑

- `Observe`：锁定项目版本和事实窗口。
- `Analyze`：运行确定性工具并产生证据。
- `Plan`：生成一个或多个受约束候选。
- `Verify`：执行结构校验和副本仿真。
- `Explain`：说明收益、代价、风险和不确定性。
- `Approve`：由具备权限的人确认。
- `Apply`：幂等应用到新版本，不覆盖原版本。
- `Review`：以相同指标复核实际结果。
- `Rollback`：恢复原版本并保留全过程审计。

### 7.6 RAG、记忆与工具使用

- 产品知识、工艺知识、运行摘要和用户记忆保持分区；实时数值不进入长期记忆真值。
- 文档入库保存来源、版本、权限、哈希、有效期和归档状态。
- 用户偏好只有在明确批准后写入，支持查看、纠正和删除。
- 工具契约继续使用白名单、参数 schema、风险级别和确认门控；服务端再次校验，不能只信任前端。
- 评测不仅检查回答文本，还检查是否选对工具、参数是否正确、是否读取新鲜事实、是否在失败时降级。

### 7.7 语音交互

- 主动：只播报满足策略的 warning/critical 事件，支持合并、冷却、静默和确认。
- 唤醒：测试不同说话人、距离、环境声和相似词，分别统计漏唤醒与误唤醒。
- 回应：展示文本与 TTS 内容分离，继续避免不适合中文播报的英文 ID；失败时文字结果必须保留。
- 连续会话：处理 VAD 分轮、30 秒免重复唤醒、插话、取消、超时和回声自激。
- 语音不得直接绕过危险动作确认；确认内容应包含对象、影响和可回滚性。

### 7.8 视觉质量闭环

- 保存模型版本、阈值、类别映射、同源帧哈希、相机和时间戳。
- 检测结果与批次、工单、物料和处置记录关联。
- 低置信度进入复核，不直接判废；阈值变更需重新评测。
- 统计精确率、召回率、漏检、误检和数据漂移，避免只展示单张成功截图。

### 7.9 Forge 生态

- ForgePass 负责身份，不在产品间传递明文凭据。
- ForgeMind 负责设计、仿真、诊断和决策证据。
- ForgeCloud 负责版本、资源、运行事实、审批和审计。
- ForgeHub 负责工业资源与 CAD，不承担生产仿真真值。
- ForgeLab 负责社区传播，不自动把帖子内容写入正式项目或知识库。
- ForgeMove 负责摘要、提醒和受限审批，不承载完整三维编辑。

### 7.10 硬件与客户端

- DM4310 按“主机协议回归 → ESP32 编译 → 空载单轴 → 限位/急停 → 六轴低速 → 场景联动”顺序验收。
- 真机参数必须按设备批次核对，禁止直接沿用示例量程和增益。
- Unity/WebView2 先验证消息协议、生命周期、焦点、输入、尺寸和崩溃降级，再比较渲染性能。
- 硬件或桌面端验证失败不得影响 Web 核心版本发布，但必须明确标记能力边界。

## 8. 数据模型演进计划

现有 `cloud_runtime_event`、遥测窗口、工单、质量、维护、Agent、审批、版本和审计表继续作为基础。后续表名与字段必须在实施前与《ForgeMind-后端数据库设计.md》复核，以下名称为规划占位，不代表迁移已经存在：

| 规划对象 | 关键字段 | 目的 |
| --- | --- | --- |
| `connector_checkpoint` | workspace、connector、partition、cursor、event time、status | 断线恢复和消费审计 |
| `connector_mapping_version` | source point、twin/data point、unit transform、valid from/to、hash | 点位映射版本化 |
| `lot_batch` | lot、work order、recipe、material、quantity、state | 串联生产、视觉和质量事实 |
| `simulation_calibration_profile` | project version、parameter set、source window、error metrics、status | 保存可回滚标定参数 |
| `whatif_job/result` | base version、state hash、seed、horizon、algorithm version、metrics | What-if 排队与复现 |
| `agent_effect_review` | run、proposal、expected、actual、window、verdict | 建议效果复核 |
| `device_command_receipt` | command、idempotency key、expires at、approvals、ack、result | 受控执行回执 |

数据迁移要求：

- 采用新的 Flyway 版本递增迁移，不重写已发布迁移。
- 所有唯一约束和索引先通过历史数据检查；大表变更必须评估锁表时间。
- 新字段先兼容空值并完成双读/回填，再切换必填或新逻辑。
- 删除或归档前先验证审计、审批、发布和回滚引用。
- 每次迁移提供前向验证、失败恢复和备份恢复证据。

## 9. 规划 API 与契约

以下是建议契约方向，均属于规划项，路径可在实现评审时调整：

| 能力 | 建议接口 | 核心约束 |
| --- | --- | --- |
| 连接测试 | `POST /api/v1/connectors/{id}/test` | 不返回凭据；记录测试审计 |

| 标定任务 | `POST /api/v1/simulation-calibrations` | 记录输入窗口、参数与算法版本 |
| What-if 作业 | `POST /api/v1/what-if/jobs` | 固定版本、种子、时长和资源上限 |

所有写接口共同要求：Bearer 会话、工作空间/项目权限、幂等键、乐观版本、输入 schema、审计事件、敏感字段脱敏和明确错误码。

## 10. 量化验收指标

下表数值是本周期目标，不代表当前已经达到。若现场硬件或工艺特征要求调整，必须在试点启动前书面冻结口径。

| 维度 | 指标与目标 | 测试口径 |
| --- | --- | --- |
| 确定性 | 相同版本、状态、种子和时长的摘要哈希一致率 100% | 三套基准各重复不少于 10 次 |
| 库存正确性 | 负库存、无来源增量和重复批次为 0 | 正常、拥堵、断点恢复和回滚场景 |
| 数据幂等 | 相同 workspace/source/external ID 重放不重复入账，成功率 100% | 至少 10 万条含重复/乱序事件 |
| 连接恢复 | 断线后从 checkpoint 恢复，无不可解释缺口 | 1、5、30 分钟三档断线故障注入 |
| 数据质量 | 无效质量码不进入正式指标，错误单位可识别并隔离 | 固定异常数据集 |
| What-if 公平性 | 所有候选初始条件完全一致，可复现实验比例 100% | 每种目标不少于 20 组任务 |
| Patch 安全 | 越权、过期、陈旧版本、非法对象和校验失败 Patch 拒绝率 100% | 固定攻击与错误矩阵 |
| 应用/回滚 | 已批准合法 Patch 应用与回滚成功率 100% | 关键 Patch 类型逐项验证 |
| 工具调用 | 固定评测集正确工具与参数成功率不低于 95% | 包含多轮、歧义、失败和降级样本 |
| 动态事实安全 | 未经工具读取而由模型生成实时数值的违规数为 0 | 助手与 Agent 全评测集 |
| RAG | Recall@4 不低于 0.85，MRR 不低于 0.75 | 版本化问题集；按知识类别分别统计 |
| RAG 证据 | 需要知识依据的回答引用有效来源比例不低于 95% | 排除闲聊和纯工具结果 |
| 语音唤醒 | 安静条件召回不低于 95%，目标现场噪声条件不低于 90% | 冻结说话人、距离和噪声测试集 |
| 语音误唤醒 | 连续 8 小时背景音测试每小时不高于 0.2 次 | 真实或录制现场背景音 |
| 语音响应 | ASR 确认结束到首段可听响应 P95 不高于 3 秒 | 热态本机链路；网络模型单独统计 |
| 视觉 | 试点缺陷集的 Precision/Recall 达到业务评审阈值 | 阈值由质检责任人冻结，不用演示集替代 |
| 性能 | S-03 参考工作站 P95 帧时不高于 16.7 ms，交互长帧单独统计 | 固定分辨率、显卡、浏览器和视角脚本 |
| 隔离 | 跨工作空间读取/写入和越权审批拒绝率 100% | API 自动化权限矩阵 |
| 恢复 | 试点环境 RPO 不高于 24 小时、RTO 不高于 4 小时 | 实际数据库和对象恢复演练 |
| 稳定性 | 只读试点链路连续运行 72 小时无 P0 故障 | 含网络波动和服务重启 |

## 11. 测试与发布门禁

### 11.1 每次可交付变更

- 运行受影响模块的单元、协议或回归脚本。
- 根前端执行 `npm.cmd run build`；后端改动执行 `mvn.cmd test` 与必要的 package/启动检查。
- AI/语音 Python 改动执行 `py_compile` 和对应回归；协议变化执行 `assistant:protocol`。
- ForgeHub 改动在子项目执行 lint、定向测试和 build；WASM/CAD 大回归按串行配置运行并记录环境限制。
- 数据迁移必须在新库和含历史数据的升级库各执行一次。
- 文档和脚本执行 `git diff --check`，已知失败必须写入交付记录。

### 11.2 阶段发布

- P0 缺陷为 0；P1 缺陷必须有规避方案和关闭日期。
- 验收证据包含命令、版本、环境、输入、输出摘要和负责人，不只写“测试通过”。
- 对外演示使用的项目、模型、知识和视频资产均完成许可与隐私复核。
- 回滚包、备份和恢复步骤在发布前实际演练。
- 新增 AI 能力必须证明关闭 AI 后确定性核心仍可运行。

## 12. 风险与处置

| 风险 | 影响 | 预警信号 | 处置 |
| --- | --- | --- | --- |
| 现场协议和点位差异大 | 接入延期、数据不可比 | 点位命名混乱、单位缺失、质量码不一致 | 先文件回放和映射版本；连接器做插件化；缩小首批点位 |
| 仿真与现场偏差过大 | What-if 结论失真 | 节拍/在制品误差持续超阈值 | 显示置信度；暂停优化建议；回到参数与工艺口径标定 |
| 多载具拥堵或死锁 | 物流指标失真 | 预约长期不释放、路径频繁重算 | 服务位预约、超时释放、优先级和死锁回归；保留人工调度 |
| 大模型工具选择波动 | 错误动作或用户不信任 | 评测正确率下降、重复工具调用 | 确定性 IntentRouter 兜底、白名单、确认门控、失败回退模板 |
| RAG 旧知识污染 | 错误解释 | 命中过期版本、无来源回答 | 版本/权限过滤、归档隔离、引用门禁和无证据拒答 |
| 车间噪声和回声 | 语音不可用或误操作 | 误唤醒、回声自激、VAD 截断 | 物理按键/文字兜底、回声抑制、冷却策略、危险动作二次确认 |
| 视觉数据漂移 | 漏检/误检 | 类别分布或置信度持续变化 | 数据漂移监控、抽检、复标和模型版本回退 |
| 对象存储/大文件故障 | CAD 和模型不可用 | 上传中断、哈希不一致、孤儿 Blob | 分片、校验、引用计数、生命周期、双份备份和恢复演练 |
| 权限或多租户漏洞 | 数据泄露 | 跨 workspace 返回非 403/404 | 服务端强制隔离、固定权限矩阵、安全评审、审计告警 |
| 资产许可不清 | 无法分发或参赛交付 | 缺少来源/许可证/SHA | 隔离资产、替换或取得授权；不得以原创名义发布 |
| 范围膨胀 | 核心试点无法按期完成 | 同时推进公共市场、PDM、真机控制等 | P0 优先；P2 不阻塞试点；变更进入范围评审 |

## 14. 前 12 周具体执行清单

### 第 1–2 周

- 产出确定性摘要哈希工具和首份结果。

- 冻结试点对象、工艺、点位和禁止接入范围。
- 完成资产许可证缺口分级。

### 第 3–4 周

- 冻结连接器事件 schema、错误码和日志上下文。
- 完成模拟源与文件回放适配器。
- 建立点位映射原型和 checkpoint 数据设计。
- 执行重复、乱序、迟到和错误质量码测试。

### 第 5–6 周

- 完成 OPC UA 只读适配器最小链路。
- 完成 MQTT 只读适配器最小链路。
- 建立连接器健康、延迟、积压和重连状态板。
- 完成跨工作空间、凭据泄漏和输入限流安全检查。

### 第 7–8 周

- 完成资产/设备/点位/仿真对象映射版本。
- 接入试点批次与工单上下文。
- 冻结吞吐、停机、阻塞、能耗和质量指标口径。
- 运行首轮历史回放与数据覆盖分析。

### 第 9–10 周

- 完成标定配置和首轮参数拟合/人工校准。
- 形成标定前后误差对比。
- 完成多 AGV/无人机预约与拥堵用例。
- 完成时序引擎对比实验并作出采用/暂缓决定。

### 第 11–12 周

- 运行 24 小时只读回放或旁路接入。
- 完成数据完整性、重连、去重和回放验收。
- 将现场窗口输入现有诊断与 What-if，但只输出建议，不执行设备命令。
- 召开第一阶段试点评审：决定进入增强诊断，或先继续修复数据/标定问题。

## 15. 交付物目录建议

每个试点版本应形成独立证据包，至少包含：

```text
release-evidence/
  manifest.md                 # 版本、提交、构建、环境和负责人
  baseline/                   # 基准存档、种子、资源哈希
  schemas/                    # 事件、映射、API 和工具契约
  migrations/                 # 迁移验证和恢复记录
  tests/                      # 自动化输出与已知失败
  performance/                # 帧时、仿真、Worker、接口和资源指标
  ai-evals/                   # 工具、RAG、记忆、语音和视觉评测
  security/                   # 权限矩阵、密钥和上传检查
  operations/                 # 部署、监控、备份、恢复和回滚
  pilot/                      # 每日记录、周报、验收和遗留项
  licenses/                   # 资产来源、许可、修改声明和 SHA-256
```

证据包可以由脚本生成，但不得把密钥、真实个人信息、未脱敏生产数据或受限制资产打包进入仓库。

## 16. 变更管理

- 新增或删除产品范围、改变核心架构、AI 边界、数据模型、资产规则或路线时，先更新《ForgeMind 项目方案.md》。
- 已完成任务只有在代码、测试和文档三者一致后，才能同步到《ForgeMind-当前实现总览.md》。
- 每个阶段结束更新本文的状态、实际周次、偏差、遗留项和下一阶段入口条件。
- 需求变更按“收益、P0 依赖、工期、风险、退出方案”五项评审；未给出退出方案的高风险实验不得进入试点主线。
- 宣传稿、PPT 和视频只能引用已经通过验收的状态；规划能力必须明确标注“计划中/试点中”。

## 17. 完成定义

本计划不是以“所有页面完成”作为结束，而以以下结果作为完成定义：

1. 至少一个小规模试点范围内，设计版本、现场只读事实、孪生映射、诊断、What-if、Agent 提案、人工决策和效果复核能够串成可追踪证据链。
2. 相同实验可复现，关键数据不重复、不越权、不被 AI 编造或覆盖。
3. AI、语音、视觉、网络或云端任一可选链路故障时，本地确定性核心和存档仍可使用。
4. 所有写操作都有权限、版本、确认、审计和回滚；物理设备写入在安全条件不足时保持关闭。
5. 部署、备份、恢复、培训、许可证和遗留项均有实际记录，可由项目成员以外的验收人员复核。

达到以上条件后，ForgeMind 才可从“功能完整的数字孪生与智能诊断原型”进入“经过小规模工业试点验证的平台版本”；更大规模商业化、公共资源市场、多人 PDM 和无人值守控制应作为下一周期单独立项。

## 1. 目标定位

ForgeMind 智能助手 2.0 不再只是“查询状态、控制仿真倍率”的语音助手，而是面向工厂设计、验证和运行观察的智能中枢：

```text
自然语言 / 语音 / 页面操作
              ↓
      上下文理解与任务记忆
              ↓
       工厂事实与界面感知
              ↓
    诊断、规划、仿真和结果解释
              ↓
       面板调度 / 任务执行
              ↓
      主动巡检、提醒与复盘
```

目标体验是“BT-7274 式工厂智能管家”，唤醒关键词固定为 **BT**，不使用 Jarvis 作为产品称呼或唤醒词。工业事实仍以确定性系统为准。大语言模型负责理解、编排和表达；仿真、碰撞、寻路、库存、产能、Patch 校验和权限继续由现有确定性内核与服务端门禁负责。

## 2. 当前基础与主要缺口

当前已经具备：

- 规则助手、可选远程模型链路和已接入的本地 Ollama `qwen2.5:7b` provider；
- 30 个受协议约束的助手动作，其中包含面板并排比较、Agent 任务查看、生态产品深链接、视觉结果读取、主动提醒查询/依据解释/同类关闭、楼层、对象定位、任务取消/重试、任务历史、提醒策略和用户偏好管理；
- Agent 工厂图谱、Finding、Patch、分支仿真、审批和回滚；
- 生成式工厂候选布局、What-if 仿真和经济性比较；
- 自动巡检、趋势/ETA、瓶颈和能耗归因；
- ASR、TTS 和 PCB YOLO 视觉检测入口；
- ForgeCloud AI 规则任务队列和审计基础。

主要缺口不是缺少一个聊天框，而是：

1. 助手已能统一调度 Agent 和巡检首批入口；诊断类复杂请求会按领域拆成最多 4 个可追踪只读子任务并合并结果，方案设计类请求按基线、约束、候选、Patch 四阶段推进。
2. 助手已能打开、关闭、聚焦、切换楼层、定位对象、并排比较面板、查看 Agent 任务、读取/解释/关闭主动提醒和跳转 ForgeMind/ForgeHub/ForgeLab/ForgeCloud；更深的产品内上下文联动仍待补齐。
3. 已有当前页面、楼层、对象、会话、页面任务状态、当前项目最近版本摘要、最近 Finding/方案摘要和服务端 Agent run 摘要上下文；用户批准的偏好已支持本地缓存与 V28 MySQL 持久化。
4. 自动巡检已形成主动提醒、会话级去重、严重度升级、免打扰、用户策略云端持久化、跨会话 claim 去重，以及本地与 V29 云端多来源聚合；助手现在可列出开放事件、解释来源/时间/次数并确认关闭同类提醒；趋势、质量等更多来源接入仍待补齐。
5. 已补齐 Agent 步骤进度写回和事件通道；只读任务现在具备服务端异步编排入口、失败落库、SSE/轮询观察和统一报告，方案设计仍保留浏览器确定性规划与人工审批边界。

## 3. 目标能力矩阵

| 能力域 | 2.0 目标 | 执行边界 |
| --- | --- | --- |
| 对话理解 | 支持多轮追问、代词指代、目标拆解、约束冲突提示 | 未识别的约束不得静默猜测 |
| 面板调度 | 打开、关闭、切换、聚焦、并排比较和定位业务面板 | 面板动作本身不修改工厂事实 |
| 工厂感知 | 读取当前楼层、选中对象、仿真状态、库存、物流、诊断和云端信号 | 每条结论标注仿真、回放或现场来源 |
| 任务编排 | 将复杂请求拆成读取、分析、方案、仿真、审批和复核步骤 | 每一步可取消、超时和追踪 |
| 方案决策 | 调用 Agent 和生成式工厂生成候选并解释差异 | 只能推荐，不能绕过校验和审批 |
| 主动巡检 | 监测瓶颈、库存、产能、质量和设备异常并主动提醒 | 支持静默、合并、升级和免打扰策略 |
| 记忆 | 记住项目目标、用户偏好、历史决策、故障和方案效果 | 记忆必须可查看、修改、删除和审计 |
| 多模态 | 语音对话、三维对象定位、检测结果解释、后续支持截图/设备数据 | 视觉模型结果不能直接伪造生产事实 |
| 执行控制 | 低风险配置可确认后执行，高风险 Patch 进入审批 | 真实设备控制单独受服务端策略保护 |

## 4. 面板调度设计

### 4.1 助手可调出的面板

第一批面板统一注册为可发现的 `PanelRegistry`：

- `factory-overview`：工厂总览、当前楼层和关键运行信号；
- `simulation`：仿真时间、倍率、产出、消耗、在途和设备状态；
- `object-detail`：当前设备、货架、仓库、AGV 或无人机详情；
- `production`：物品、配方、工艺链和机器绑定；
- `logistics`：传送带、端口、车辆任务和物流阻塞；
- `warehouse`：货架库存、入货/出货边界和库存阈值；
- `agent-diagnosis`：结构诊断、Finding、证据和建议；
- `generative-planner`：候选布局、What-if 和经济性比较；
- `inspection`：视觉检测视频、缺陷框、类别、置信度和耗时；
- `cloud-runtime`：设备、孪生、遥测、质量、维护和 AI 任务；
- `activity-history`：进入 ForgeCloud“活动与审计”页，查看已落库的活动、审批和执行责任链；助手任务的页面会话状态仍在 ForgeMind 当前页面上下文中维护。

### 4.2 面板动作

助手应支持以下只读 UI 动作：

```text
open_panel(panelId)
close_panel(panelId)
focus_panel(panelId)
select_floor(floorId)
locate_object(objectId)
compare_panels(leftPanelId, rightPanelId)
show_task(taskId)
```

示例：

- “打开物流面板，看看哪里堵了。”
- “把二楼的 CNC-02 定位出来并打开详情。”
- “同时打开当前产能和上一次巡检结果对比。”
- “进入生成式工厂，展示三个方案的能耗差异。”
- “打开视觉检测面板，查看最近一帧的缺陷。”

面板动作必须经过页面注册表和权限检查。助手只能请求合法面板、合法对象和合法项目上下文，不能通过自然语言构造任意路由或访问其他工作空间。

### 4.3 面板与回答联动

每次回答采用统一结构：

1. **结论**：直接回答当前问题。
2. **证据**：列出指标、对象、时间窗口和数据来源。
3. **动作**：告诉用户已经打开了什么面板或下一步可执行什么。
4. **风险**：如果涉及修改、仿真时间不足或现场数据缺失，明确说明。

例如：

> 当前主要瓶颈是 CNC-02，过去 60 秒利用率为 42%，其输入端有 3 次供料等待。已打开“物流诊断”和“CNC-02 详情”面板。该结论来自固定种子仿真证据，不是现场传感器数据。是否生成两个重布线候选？

## 5. 对话智能化设计

### 5.1 多轮上下文

助手上下文分为四层：

| 层级 | 内容 | 生命周期 |
| --- | --- | --- |
| 当前界面上下文 | 当前路由、打开面板、选中对象、楼层、筛选条件 | 页面会话 |
| 当前任务上下文 | 用户目标、约束、已完成步骤、待确认动作 | 任务结束前 |
| 项目上下文 | 工厂版本、配方、设备、历史 Finding、项目目标 | 项目级 |
| 用户记忆 | 偏好语言、提醒频率、常用指标、确认习惯 | 用户可管理 |

助手应理解“它、这里、刚才、这个方案、上一轮、不要增加设备”等指代，并在上下文不明确时主动追问，而不是选择一个对象静默执行。

### 5.2 意图路由

建议将请求路由为六类：

1. `navigate`：调出或操作面板；
2. `observe`：读取状态、指标、对象和历史；
3. `diagnose`：启动结构诊断、自动巡检或异常分析；
4. `plan`：生成布局、调整方案或 What-if；
5. `execute`：执行已确认的低风险配置或提交审批；
6. `monitor`：创建、修改或关闭主动巡检与提醒。

复杂请求进入任务编排器，不由一个 LLM 回复直接完成。例如“找出产能下降原因并给出不增加设备的方案”应拆成：读取指标 → 运行证据 → 诊断 → 生成候选 → 分支仿真 → 汇报比较。

### 5.3 模型使用策略

- 规则模式负责基础意图、面板动作、常用查询和离线降级。
- 本地 Ollama `qwen2.5:7b` 作为助手 2.0 的首选理解与编排模型，负责自然语言理解、复杂问题拆解、工具选择、解释和文案表达。
- DeepSeek 等远程模型只作为明确配置后的可选替代，不作为本方案的默认路径。
- 所有模型输出必须转换成结构化意图或工具调用，不能直接执行任意代码。
- 模型无法确认的对象、数字、来源和约束必须显式标记“不确定”。
- 远程模型不可用时，保留已完成的确定性结果，不能把网络异常显示成“工厂异常”。

### 5.4 本地 Qwen2.5:7b 适配方案

本方案以用户本机已有的 `qwen2.5:7b` 为默认开发和离线运行模型。推荐通过 Ollama 的本地 HTTP 接口接入 `ai-service`，不让浏览器直接访问模型服务：

```text
浏览器 / 语音
      ↓
  ai-service
      ↓
Ollama 127.0.0.1:11434
      ↓
qwen2.5:7b
```

建议环境变量：

```powershell
$env:FORGEMIND_LLM_PROVIDER = 'ollama'
$env:FORGEMIND_OLLAMA_BASE_URL = 'http://127.0.0.1:11434'
$env:FORGEMIND_OLLAMA_MODEL = 'qwen2.5:7b'
$env:FORGEMIND_LLM_TIMEOUT = '60'
```

当前实现第一步需要补齐 `ollama` provider，而不是在前端增加第二套调用方式。适配器至少需要支持：

- `/api/chat` 流式文本回复；
- 受限工具目录和结构化工具调用；
- JSON 输出约束与解析失败重试；
- 模型未启动、超时、上下文过长和 Ollama 不可用时的规则降级；
- `/api/ai/health` 返回模型名、连接状态、响应延迟和降级原因；
- 同一上下文摘要、提示词和工具目录的可复现测试夹具。

本地 Qwen 是“推荐运行 profile”，不是新的默认启动门禁。根入口可以提供显式 `-IncludeLocalAI` 或环境变量开关；未启用时，项目仍应按现有规则模式正常启动。模型服务不能影响建造、仿真、寻路、诊断和存档基本功能。

### 5.5 是否微调：先做行为适配，再做 LoRA

不建议把工厂实时数据直接训练进模型权重。设备状态、库存、产能和 Finding 会变化，应通过实时上下文、工具读取和事件记忆提供。微调只优化“行为”，不替代事实查询：

1. **第一阶段：提示词与工具调用校准**。整理 ForgeMind 工具 schema、角色口吻、面板意图、确认规则和拒答样例，配合 JSON schema、少样本示例和错误重试，先验证 Qwen 在现有硬件上的稳定性。
2. **第二阶段：LoRA/QLoRA 行为微调**。使用脱敏且可审计的中文数据，覆盖面板调度、对象指代、多轮任务拆解、诊断解释、主动提醒、风险确认和不确定性表达。训练目标是结构化意图/工具调用正确率，不是让模型背诵某条工厂数据。
3. **第三阶段：偏好与回归优化**。收集用户接受、拒绝、改写和重新提问的记录，建立“准确、少打扰、证据充分、动作安全”的偏好评测；每次模型更新都跑工具协议、越权、幻觉对象、错误确认和上下文丢失回归。

当前本机显卡查询约为 4 GiB 专用显存，而 `qwen2.5:7b` 模型文件约 4.7 GB；本地推理和浏览器/三维场景同时运行时需要控制上下文长度、并发和缓存。QLoRA 是否能在本机稳定训练应先做显存实测，不把“可以微调”写成已经完成。若本机训练预算不足，优先采用提示词、工具 schema、检索上下文和小规模离线评测。

### 5.6 BT 人格与唤醒策略

- 唤醒词固定为 `BT`，语音监听、按钮提示、测试样例和文档统一使用“BT”；不引入 Jarvis 唤醒词，也不允许模型自行改变称呼。
- 助手正式身份使用“BT-7274 工厂智能管家”，默认称呼用户为“驾驶员”；用户可以在设置中关闭称呼，但不能改变安全策略。
- 人格表现为沉稳、冷静、专业、简洁、有任务感：先报告事实，再给判断和下一步；异常时明确告警，不用夸张或拟人化语言掩盖不确定性。
- BT 可以表现出任务记忆、主动提醒、追问澄清、复盘和轻量幽默，但这些是表达层特质，不能改变权限、事实来源和审批门禁。
- “BT，打开物流面板”“BT，继续刚才的诊断”“BT，为什么你提醒我这个问题”都应进入同一套文本/语音意图路由。

## 6. 上下文、RAG 与 Agent 特质

### 6.1 分层上下文

助手不能只把当前页面 JSON 全量塞给 Qwen，而应使用上下文管理器按任务分层装配：

| 上下文层 | 内容 | 处理方式 |
| --- | --- | --- |
| 当前感知 | 当前路由、面板、楼层、选中对象、仿真状态 | 每轮动态注入，优先级最高 |
| 对话记忆 | 最近多轮问答、用户纠正、未完成指代 | 保留最近窗口并压缩摘要 |
| 任务记忆 | 目标、约束、已完成步骤、待确认动作、失败原因 | 任务结束前持续维护 |
| 项目记忆 | 工厂版本、配方、设备角色、历史方案和审批记录 | 按当前项目检索 |
| 运行记忆 | 巡检样本、异常事件、质量/维护结果和方案效果 | 按时间、对象和事件类型检索 |
| 用户记忆 | 常用指标、提醒偏好、语言和确认习惯 | 用户可查看、修改和删除 |

上下文管理器必须支持摘要、裁剪、优先级和过期时间，避免 Qwen 因上下文过长而丢失当前对象或安全约束。动态数值优先通过工具实时读取，不能依赖旧对话记忆。

### 6.2 RAG 知识分层

RAG 用来补充“解释和知识”，不能替代实时工具事实。检索源分为四类：

1. **产品知识库**：ForgeMind 用户手册、模块技术文档、工具协议、权限和操作说明；
2. **工艺知识库**：当前项目物品、配方、机器定义、端口语义、物流规则和许可说明；
3. **运行知识库**：已确认的 Finding、巡检报告、工单、质量结果、维护记录和已评价方案；
4. **用户记忆库**：用户明确要求保存的偏好、项目约束、常用叫法和已确认决策。

检索策略采用“结构化过滤优先、关键词检索兜底、向量检索增强”：

- 对象、项目、版本、楼层、时间和权限先做结构化过滤；
- v1 可使用 MySQL/本地索引进行关键词和字段检索，不增加新的模型依赖；
- 当前以零依赖哈希词元向量增强关键词排序，避免新增本地模型依赖；后续再增加专用 embedding 模型和向量索引，用于手册、故障经验和长文本语义召回；
- Qwen 只对召回片段进行理解和组织，不自行扩展未召回的工厂事实；
- 回答必须带“依据”来源，如文档章节、对象 ID、仿真窗口、事件时间和版本号；
- 检索不到可靠依据时，BT 必须明确说“当前资料不足”，并建议打开面板或启动诊断。

RAG 不把整份存档当作知识文档反复喂给模型。存档中的实时状态、坐标、库存、路线和指标必须通过工具查询；文档和历史经验才进入检索上下文。

### 6.3 Qwen、Agent 与确定性内核的分工

本地 Qwen2.5:7b 可以发挥的独特特质包括：

- 理解自然中文、口语、省略句和多轮指代；
- 将模糊目标拆成结构化约束和任务步骤；
- 在多个工具之间选择下一步动作；
- 综合当前指标、RAG 片段和用户目标给出有依据的解释；
- 识别对象歧义、约束冲突和证据不足，并主动追问；
- 把复杂结果压缩成适合屏幕和 BT 语音播报的表达；
- 根据用户偏好调整信息密度，但不改变事实和风险等级。

Agent 层负责模型本身不稳定的长任务能力：

```text
Observe → Retrieve → Plan → Act → Verify → Reflect → Continue / Ask
```

- `Observe`：读取当前工厂与任务状态；
- `Retrieve`：检索相关文档、历史和用户记忆；
- `Plan`：生成有限步骤和成功条件；
- `Act`：调用只读工具、面板工具或受控 Agent 工具；
- `Verify`：检查返回值、版本、权限和确定性仿真结果；
- `Reflect`：判断是否完成、失败、需要重新规划或需要用户确认；
- `Continue / Ask`：继续下一步，或向驾驶员提出一个明确问题。

“反思”只允许重新检查证据、改写计划和触发 replan，不能让模型推翻确定性校验或自行宣布仿真通过。

### 6.4 RAG 与回答格式

BT 的标准回答应包含：

```text
结论
依据（工具事实 / RAG 来源 / 数据时间窗）
当前已完成的面板或任务动作
不确定性与风险
下一步建议或确认问题
```

例如：

> 驾驶员，CNC-02 是当前主要约束。依据是最近 60 秒确定性仿真中利用率 42%、输入等待 3 次；历史维护记录显示该设备曾出现供料端堵塞。已打开“设备详情”和“物流诊断”，但尚未修改工厂。是否生成不增加设备的重布线方案？

## 7. 主动性设计

### 7.1 主动事件来源

助手主动性由事件和策略驱动，不由模型自由猜测：

- 产能低于目标或相对基线持续下降；
- 瓶颈设备利用率异常、供料等待增加；
- 货架、入货仓库或关键物品达到库存阈值；
- 传送带断线、端口不匹配、下游堵塞；
- AGV/无人机在证据窗口内持续等待；
- 视觉检测出现缺陷趋势；
- 设备心跳、遥测质量或数据源发生异常；
- Agent 方案应用后效果低于预期；
- 审批、任务或长时间规划需要用户处理。

### 7.2 主动提醒策略

每条提醒包含：事件、严重度、证据窗口、影响对象、建议动作、数据来源和有效期。提醒系统需要：

- 同类事件去重和合并；
- 低、中、高三级严重度；
- 用户可配置的免打扰时段和频率；
- 未处理提醒升级；
- 已恢复事件自动收敛；
- 一键打开关联面板；
- 一键启动只读诊断；
- 任何修改动作仍进入确认或审批。

默认行为是“主动发现、主动解释、主动准备方案、等待授权执行”。

### 7.3 主动性示例

> “检测到过去三轮仿真中产能较基线下降 18%，主要原因是 CNC-02 输入等待增加。已打开运行趋势和设备详情。可以为你生成‘不增加设备’的调整方案。”

> “入货仓库中的冷轧钢板预计 12 分钟后低于安全库存。当前为仿真/回放数据，尚未接入现场库存。需要我打开仓储面板并创建补料任务草案吗？”

## 8. 技术架构

建议在现有助手、Agent、自动巡检和 ForgeCloud 之上增加七个模块：

```text
Assistant UI / Voice Surface
          ↓
Conversation Context Manager
          ↓
Intent Router + Task Orchestrator
   ↙       ↓         ↓          ↘
Panel   Tool Bus   RAG/Memory  Notification
Registry             Store       Policy
                    ↓
      Deterministic Agent / Planner / Simulation
                    ↓
          Policy Gate + Approval Gate
                    ↓
          Patch / Task / Notification / Audit
```

建议的职责边界：

- `ConversationContextManager`：维护当前页面、楼层、对象、对话和任务状态；
- `PanelRegistry`：声明面板、可用动作、参数 schema、打开方式和权限；
- `IntentRouter`：规则优先识别常用指令，复杂请求再调用可选模型；
- `TaskOrchestrator`：管理多步骤任务、Worker、SSE、取消、重试和超时；
- `RagMemoryStore`：保存文档索引、结构化工厂知识、已确认运行经验和用户记忆，并负责权限过滤、召回、来源标记和过期；
- `NotificationPolicy`：负责阈值、去重、升级、免打扰和恢复；
- `PolicyGate`：执行 workspace、项目、角色、风险、审批、版本和幂等门禁；
- `EvidencePresenter`：统一标注确定性仿真、历史回放、现场数据和模型解释来源。

建议在现有 `assistantProtocol.ts` 和 `contracts/forgemind-assistant-tools.json` 基础上新增 `navigate`、`observe`、`diagnose`、`plan`、`monitor` 五类工具命名空间；原有工具保持兼容，协议版本通过向后兼容方式升级。

## 10. 验收指标

### 功能验收

- 用户用一句话可以打开、切换和定位所有已注册业务面板；
- 连续三轮对话能够保持当前对象、楼层和任务目标；
- 一个复杂请求能够显示完整的计划步骤、进度、证据和最终结果；
- 诊断、方案、仿真、审批和应用之间不丢失上下文；
- 主动提醒可以打开关联面板、查看证据和启动只读分析；
- 语音和文字调用同一工具协议，结果一致。

### 可信性验收

- 面板动作不能越权访问其他 workspace 或项目；
- 模型不能直接写入坐标、库存、寻路结果或仿真指标；
- 所有修改都能看到确认、审批、版本和回滚记录；
- 同一事件重复到达不会产生重复提醒；
- 现场、回放、仿真和模型解释来源清晰可见；
- AI 服务不可用时，规则查询、面板调度、仿真和诊断仍可用。
- 本地 `qwen2.5:7b` 在同一组提示词和工具目录下，工具调用成功率、对象 ID 正确率和拒答正确率达到发布门槛；模型不可用时自动回到规则模式。
- BT 唤醒词、BT-7274 身份和驾驶员称呼在文字/语音/主动提醒中保持一致，不出现 Jarvis 称呼。
- RAG 回答能够返回来源和时间边界，动态工厂数字优先来自实时工具而不是过期记忆。
- 连续三轮以上对话能够保持目标、对象、楼层、方案和待确认动作；上下文超限后压缩仍不丢失安全约束。
- Agent 在工具失败或证据不足时能够重试、重新规划或追问，不得编造“已完成”。

### 体验验收

- 助手回答先给结论，再给证据和下一步；
- 主动提醒默认不刷屏，同类问题可合并；
- 长任务可取消，页面不会无限显示“执行中”；
- 操作完成后助手主动说明“做了什么、结果如何、是否需要下一步”；
- 用户可以查看、修改和删除助手记忆与提醒策略。

## 11. 明确不做的事情

- 不把“Jarvis”实现成一个可以随意执行代码的超级管理员；
- 不允许 LLM 直接控制三维坐标、碰撞、库存、路线和仿真指标；
- 不以漂亮的自然语言包装缺少证据的预测；
- 不在没有真实工业数据时宣称预测维护已经完成；
- 不在没有权限、审批、仿真和回滚的情况下自动修改正式工厂；
- 不用持续弹窗或语音打断制造“主动性”的错觉。

## 12. 第一批建议落地的用户故事

1. “打开当前工厂总览，告诉我现在最严重的问题。”
2. “把二楼所有生产设备和物流面板打开，定位断线位置。”
3. “为什么产出下降？先给证据，不要修改任何东西。”

6. “批准平衡方案，执行后持续观察 10 分钟。”

8. “记住我以后优先看产能、堵塞和能耗，不要先看装饰信息。”

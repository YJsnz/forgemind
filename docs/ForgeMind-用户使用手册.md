## 1. 准备与启动

### 1.1 环境要求

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows 10/11 |
| Node.js | ≥ 18（前端构建与开发服务器） |
| JDK | 17（后端 Spring Boot） |
| Docker Desktop | 运行 MySQL 8.4 项目实例（可用 `-SkipMySql` 跳过） |
| 浏览器 | Edge / Chrome 现代版本 |

### 1.2 一键启动（推荐）

双击项目根目录的 **`启动ForgeMind.cmd`**。它会依次：

1. 启动 MySQL 8.4 容器并执行 Flyway 数据库迁移；
2. 编译并启动 Spring Boot 后端（`http://127.0.0.1:8080`）；
3. 启动 AI 服务 FastAPI（`http://127.0.0.1:8000`）；
4. 启动前端 Vite 开发服务器（`http://127.0.0.1:5173`）并自动打开浏览器。

每个服务都在独立窗口中运行；已监听的端口会被复用而不会重复启动。全部就绪后你会看到各窗口打印端口信息。

常用变体（在命令行执行 `scripts\start-forgemind.ps1` 时附加参数）：

| 参数 | 作用 |
| --- | --- |
| `-SkipSpring` | 不启动后端与数据库（纯前端演示，无法注册登录保存） |
| `-SkipMySql` | 跳过数据库容器（后端仍启动但需要已有数据库） |
| `-NoBrowser` | 不自动打开浏览器 |
| `-ForceRebuild` | 强制重新安装依赖/构建 |

### 1.3 停止

关闭方式二选一：

- 直接逐个关闭各服务窗口；
- 或运行 **`scripts\stop-forgemind.ps1`**，它会结束 Vite、Spring、FastAPI 进程并释放 5173 / 8080 / 8000 端口。数据库容器不会被删除，下次启动复用。

> 提示：直接关机前建议先跑一次停止脚本，避免残留 node/java 进程占用端口。

### 1.4 首次进入的样子

浏览器打开 `http://127.0.0.1:5173` 后先看到**产品介绍页**（顶部导航：产品工业 / 技术核心 / 运行流程 / 文档发布）。点击任意 **进入工作台 ↗ / 进入数字工厂 ↗** 按钮，进入认证页。

## 2. 注册登录

认证页标题为 **舰桥通行认证**。

1. 第一次使用请点 **02 首次登记** 标签。
2. 填写两个字段：
   - **驾驶员 ID**（即用户名）：至少 2 个字符；
   - **访问密钥**（即密码）：至少 6 位。
3. 点击 **登记并进入基地**。成功后播放欢迎音效并过渡到工厂界面；之后再用 **01 已有身份 → 授权并开启舱门** 登录同一账号即可。

常见错误提示：

| 提示 | 含义 |
| --- | --- |
| `驾驶员 ID 至少需要 2 个字符` | 用户名太短 |
| `访问密钥至少需要 6 位` | 密码太短 |
| `认证链路中断，请检查基地连接` | 后端 8080 没起来，回到第 1 节检查启动 |

> 登录成功后还会弹出**项目弹窗**（见第 11 节），必须新建或打开一个工厂才会真正进入可编辑的工作台。

- **智能管家球**（AssistantOrb）：状态 待命/聆听中/分析中/播报中/链路异常；旁边是语音输入按钮（详见第 12 节）。
- **右侧数据面板**：设施 / 物品 / 配方 / 物流四个小统计 + SimPanel（见第 9 节）。
- **顶栏 ⚙ 设置**：包含 **渲染目标帧率**（60 FPS 画质优先 / 120 FPS 流畅优先），帧率选项保存在本机；其余界面设置仅当前会话生效。
- **视口工具条**：坐标读数、GRID/1M、相机操作提示（可在设置里关闭）。

## 4. 十分钟上手：第一条产线

空白工厂是真正的零设备开局——物品、配方、机器都要自己建。跟着做一遍就理解全流程了。本教程做一条最简单的线：**入货仓库供铝锭 → 数控机床加工成支架 → 出货仓库收货**。

**第 1 步：建厂**
登录后在项目弹窗输入名称，点 **＋ 新建空白工厂**（此时它只是未保存草稿）。

**第 2 步：创建两种物品**
打开底部 **07 物品详情** → 在模型库里搜索 `ingot`（或任意原料模型）→ 点 **使用此模型创建物品**：
- 专属 ID `alu_ingot`，名称 `铝锭`，分类选基础形状类，保存；
- 同样再创建 `bracket` / `支架`（可换一个零件模型）。

**第 3 步：定义工艺**
打开 **06 生产路线** → **＋ 新建工艺**：
- 路线 ID `r_bracket`，名称 `支架加工`，加工时长 `6` 秒，勾选启用；
- INPUT 侧选择物品 `铝锭`、数量 1，点 **＋ 添加**；
- OUTPUT 侧选择 `支架`、数量 1，添加；
- 点 **加入生产路线**。

**第 4 步：定义机器**
打开 **05 机械制造** → **＋ 新建机器**：
- 机器 ID `cnc_1`，名称 `数控车床`，模型来源选内置 `数控加工中心`（占地 3×2）；
- 蓝色入货口数量 `1`、黄色出货口数量 `1`（每侧接口数不能超过占地深度 2）；
- 在右侧 **录入已有工艺路线** 勾选 `支架加工`；
- 保存。现在建造菜单的「B 基础加工」分类里就会出现这台机器。

**第 5 步：摆放与连线**
切到 **02 建造** 视图：
1. 「A 货物仓储」放一台 **入货仓库**（3×3）；「传送物流」再放 **出货仓库**（3×3）和你的 `数控车床`，三者留出间隔。
2. 选 **滚筒输送线**，从入货仓库前方开始**按住左键沿网格拖绘**到机床的蓝色入口旁松手（靠近兼容端口会自动吸附对齐）。
3. 再拖一条从机床黄色出口到出货仓库的带子。方向不对的段落：选中后用详情窗 `TRANSFORM 旋转 90°` 或重画。
4. 点一下入货仓库，在设备详情窗 **INBOUND SUPPLY 无限供应物品** 里选择 `铝锭`。

**第 6 步：绑定配方并开机**
点击机床 → 设备详情窗 **生产配方 RECIPE** 下拉选择 `支架加工` → 回到总览 → 右侧 SimPanel 点 **启动**。

**第 7 步：看结果**
- KPI 条出现产出速率；右侧 OUTPUT 列表开始累积 `支架`；
- 打开 **08 货物仓储 → 物料台账**：入货仓库取出量记为消耗，出货仓库入库量记为产出；
- 满意后点顶栏 **手动保存存档**。

## 5. 建造详解

### 5.1 进入与通用操作

底部视图坞点 **02 建造**，左侧弹出 BuildMenu 目录。顶部提示原文：

> 网格 = 1 m · 蓝色端口为入口 · 琥珀端口为出口 · 平面输送带左键拖绘自动转弯 · 跨层与平面输送带靠近兼容端口时自动吸附

| 操作 | 效果 |
| --- | --- |
| 选一个设备卡 | 出现半透明预览（ghost），跟随鼠标吸附网格 |
| 移动鼠标 | ghost 绿框=可放置，红框=越界/重叠/非法 |
| `R` | 旋转 90° |
| 左键 | 确认放置 |
| 右键 | 取消当前建造工具 |
| `Esc` | 退出建造模式 |

### 5.2 可放置对象全表

**A 货物仓储**

| 对象 | 占地 | 说明 |
| --- | --- | --- |
| 货物存取站 | 4×4 | 三面各有一个 2×2 货架泊位，站内自带短传送带，负责货架↔传送带双向装卸 |
| 货物仓储架 | 2×2 | 普通有限容量货架，AGV/无人机可直接取放 |
| 入货仓库 | 3×3 | 无限供货起点，取用量计入消耗台账 |
| 出货仓库 | 3×3 | 无限接收终点，入库计入产出台账且不可取回 |

**B 基础加工**：你在机械制造里定义的机器都会出现在这里；目录为空时提示先去机械制造新建。

**C 精密装配**

| 对象 | 占地 | 说明 |
| --- | --- | --- |
| 机器人装配单元 | 3×3 | 多输入合并为一输出的装配站，7 轴 Panda 机械臂 |
| 双臂视觉质检单元 | 2×2 | 双臂质检，可进独立 360° 检测工作台 |

**D 传送物流**

| 对象 | 说明 |
| --- | --- |
| 滚筒输送线 | 平面传送带，左键拖绘，自动补格转点 |
| 向上跨层输送线 / 向下跨层输送线 | 跨层坡道，需与其他带或端口同向吸附对接 |
| 三向分流器 / 汇流节点 | 分发与合并物料流 |
| AGV 叉车搬运车 | 地面八方向寻路运输车 |
| 货运无人机 | 26 邻域三维 A* 任意跨层飞行运输 |

### 5.3 传送带拖绘规则（重要）

1. 选中输送线后，**按住左键拖动**即开始绘制，经过的格子自动补齐；
2. 拖绘路径同时改变了行列两个轴时，按上一轴优先补出直角转弯；
3. **往回拖过上一格 = 擦除那一格**（可以边画边改）；
4. 拖回早前的格子会**裁掉中间形成闭环**的多余段，不会自叠；
5. 松开左键时整条路径统一校验后落位；
6. 带端靠近机器蓝/黄端口或其他带的兼容接口时**自动吸附对齐**；
7. 跨层坡道只能在与平面带兼容的方向上对接，上下楼层各有一段落地端。

### 5.4 放置后的调整

点击任意设备打开右侧**设备详情短窗**，可：查看占地/朝向/吞吐、绑配方、改仓储设置、`TRANSFORM 旋转 90°`、`REMOVE UNIT 拆除设备`。多选时出现 `MULTI SELECT 已选择 N 个对象` 徽章，`DELETE 批量删除`，点击空白取消。

## 6. 楼层系统

右侧（或左侧竖轨下方）的 **VERTICAL GRID** 楼层面板：

- **切换楼层**：直接点击 `L1/L2/…` 行。被点的楼层立即变为活动层并成为**唯一可编辑层**，同时清除当前建造工具与选中。
- **加层**：点底部 `＋ 添加楼层`，上限 12 层（达上限按钮禁用）。
- **命名楼层**：每行的名称就是输入框，直接改名即时生效；默认名依次为 生产层 / 工艺层 / 装配层，之后是 扩展层 N。
- **上下文显隐开关**（眼睛图标）：把其他层设为「只读上下文」——只显示简化建筑轮廓和承托平台，无网格、不可选、不可改，用于跨层对位参考。当前层的开关在切走后才生效。

活动层有唯一的 1m 玻璃网格地面；层高 5.25m，向上/向下跨层靠第 5.3 节的坡道输送线连接。AGV 只在各自楼层的平面移动；无人机可以在任意楼层之间直线三维飞行（见 8.6）。

## 7. 生产配置：物品 / 路线 / 机械制造

三者职责严格分离：**物品详情**维护「有什么货」，**生产路线**维护「怎么变换」，**机械制造**维护「用什么机器」。后两者只能引用前者已存在的内容。

### 7.1 物品详情（07）

- **创建物品**：模型库（36 个可参数化模型，支持搜索/分类/分页）→ `使用此模型创建物品` → 填写表单。
- 表单字段：专属 ID（唯一）、业务编码、物品名称、分类、基础模型、显示颜色、单位质量 kg、最大堆叠数、说明。质量与堆叠只是业务属性，不影响网格。
- **建模参数**（右侧栏）分两组：结构与几何 / 材质与表现；部分参数有依赖条件（会提示 `需满足：…`）；`↻ 恢复默认` 一键还原。
- **删除保护**：物品被生产路线或场景设备引用时删除按钮禁用，tooltip 会列出引用处；未引用才可安全删除。

### 7.2 生产路线（06）

- 三栏布局：配方目录（参与仿真/已停用）→ 配方详情 → 当前工艺链。
- **新建/编辑**走覆盖层表单：ID、编码、名称、加工时长（秒）、说明、启用勾选，左右两侧分别是输入/输出物品列表（下拉+数量，可多条）。
- 常见校验错误对照：

| 报错 | 原因 |
| --- | --- |
| `请先在"物品详情"中创建物品` | 还没有任何物品 |
| `工艺 ID、名称、输入和输出都不能为空` | 必填缺失 |
| `同一侧不能重复选择同一种物品` | 输入或输出列表里有重复物品 |
| `工艺路线 ID 已存在` | ID 冲突 |

- 停用的路线不会出现在机器录入候选里；基础加工机器只能录入**端口容量相容**的路线（见下）。

### 7.3 机械制造（05）

- **机器仓库**：已定义机器卡片（N 入/N 出、工艺 N 条、场景中 N 台实例）；有实例时禁止删除定义。
- **新建机器**字段：专属 ID、名称、模型来源（内置 7 种或你导入的 GLB）、模型高度 m、占地宽/深（格）、蓝色入货口数、黄色出货口数、标准吞吐、额定能耗、说明；右侧勾选要录入的工艺路线。
- 规则：**每侧接口数量 ≤ 占地深度**；已录工艺的输入种类数不得超过入货口数（输出同理），不相容的路线会标 `超出接口容量` 并禁选。
- **导入自己的 GLB**：机器仓库顶部 `↥ 导入模型` 打开导入弹窗（JSON 定义 + GLB 模型，字段见弹窗提示）；登录状态下导入的资源会保存到你个人账号名下，只有你能看到和使用。

## 8. 仓储与物流

### 8.1 四种仓储设施一览

| 设施 | 库存语义 | 台账口径 |
| --- | --- | --- |
| 货物存取站 | 自身不存货；三面泊位吸附真实货架对象 | 通过它进出货架 |
| 货物仓储架（普通货架） | **有限容量真实库存**，可命名 40 字 | AGV/无人机/存取站都按实际数量取放 |
| 入货仓库 | 无限供货，物品由你指定 | 实际取出多少记多少消耗 |
| 出货仓库 | 无限接收，入库后不可逆 | 实际送达多少记多少产出 |

### 8.2 货物存取站程序

点击存取站 → 详情窗 `CARGO ACCESS PROGRAM · 3-SIDE RACK`：

1. 三面状态行显示 后侧/左侧/右侧 是否已吸附货架（`已吸附 {id}` / `未连接`）；
2. **运行模式**二选一：`取货 → 传送带`（把货架货送上带）或 `传送带 → 存货`（把带来货存上架）；
3. **存取间隔**（秒，0.25–60）控制节拍；
4. 取货模式下指定当前取货物品；
5. **物品 → 实际货架侧映射**：默认 `自动分配并同类合并`，也可手动指派到某一侧货架。
缺架时：取货会阻塞等待；存货则保留传送带来货不丢。

### 8.3 普通货架

- 详情窗设置 **货物上限** 和每种物品的 **仿真初始数量**；
- `ACTUAL INVENTORY 实际库存` 实时显示 `N / 容量`；
- 总览视角下货架上方有浮动标签（名称、物品 ×N、总量/容量）；打开任何工作区/建造/多选时标签自动隐藏避免遮挡。

### 8.4 AGV 编程

入口两处：选中 AGV 的悬浮窗，或 **08 货物仓储 → 导航控制** 页。任务结构固定为三节点：

1. `01 起点 装货位置`：下拉选择（普通货架、入货仓库等，优先显示自定义名称）；
2. `02 货物 搬运内容`：选物品 + **每趟数量**；
3. `03 终点 卸货位置`。

可选 **ROUTE DESIGNER 中间站**：添加站点并指定动作 `经过 / 装货 / 卸货`，可排序删除；动态遇障时保留任务顺序绕行重规划。

**发货设置**：

| 设置项 | 说明 |
| --- | --- |
| 供货方式 | `一直运输`（循环搬）/ `库存条件触发`（满足阈值才出发） |
| 起点库存至少 / 终点库存至多 | 阈值模式的两个触发条件（0–1000000） |
| 策略 | 平衡交通 / 最短路径 / 优先级通行 |
| 优先级 | 0–9，避让时谁让谁 |

勾选 `启用导航任务` 后点 `应用导航任务` 生效；`停用` 解除。LIVE 行实时显示相位（前往起点/前往终点/待命…）、决策（正在避让车辆/正在重新规划…）、已完成趟数与里程。

> 关键语义：普通货架必须真的有足量该物品才发车，缺货/不足时车辆原地等待，**绝不会凭空生成货物**。新放置的车保持空载待命。

### 8.5 无人机编程

同样两处入口（悬浮窗 / 导航控制页）。与 AGV 的差异：

- 取货点与卸货点都可以是**任意楼层**的仓储位置（选项带 `L{层}` 前缀）；
- 采用 26 邻域三维 A*，直接改变 X/Y/Z，不需要升降井；设施上方净空 1.2m、多机间距 3.0m 自动保持；
- `LIVE 3D PATH` 会画出当前位置→装卸安全悬停点→三维转向节点的路径；若起终点在同一层会提示选择不同楼层；
- 没有策略/优先级项；供货方式与阈值语义与 AGV 相同。

### 8.6 仓储总览页

**08 货物仓储 → 库存控制** 页给出全局台账：库存位置表（点行可跳转选中该设备）、运输层汇总、以及按物品的 `+产出 −消耗` 台账。口径提醒（页面原文）：*仿真启动后，仅从入货仓库实际取出的货物记为消耗，送入出货仓库的货物记为产出。*

## 9. 运行仿真与监控

### 9.1 控制入口

- 主控：右侧面板 **SimPanel** —— `启动/暂停`、`重置`、倍率 `×0.35 ×0.5 ×1 ×2`、逻辑时间、在途数、利用率、OUTPUT 产出与 INPUT 消耗列表；
- 生产视图（03）顶部有同样的快操按钮；
- 视口底部状态灯：`仿真运行中 / 仿真已暂停`。

### 9.2 行为须知

- 仿真引擎使用**固定随机种子**，同样的布局与操作得到完全相同的运行结果（方便对比方案）；
- **任何结构变更（增删移设备、改配置、加载存档）都会重建引擎并把仿真置为暂停**，需要重新点启动；
- 暂停时传送带滚动与货物运动同步冻结，画面静止；
- 大型工厂（>120 对象）快照频率自动降低以保帧率。

### 9.3 性能建议

- 顶栏 ⚙ → 渲染目标帧率：一般 60 FPS 足够；高刷屏且工厂不大时可切 120 FPS；
- 不需要的上下文楼层用眼睛开关隐藏；
- 空闲且暂停时渲染自动进入省电的按需模式，属正常现象（一动就恢复）。

### 9.4 视觉检测 Demo：视频实时 YOLO 识别

这是针对 PCB 等工业制成品的缺陷识别 Demo。它与右侧面板的 OpenCV 手动检测是两条独立路径。

#### 使用步骤

1. 打开独立视觉检测页 `inspection.html`。从双臂视觉质检单元的设备详情进入，或直接访问 `http://127.0.0.1:5173/inspection.html`。
2. 点击左侧 `01 ◉ DEMO YOLO 质检回放`，打开 Demo 窗口。
3. 视频会自动播放 PCB 测试画面。播放过程中浏览器定期抓取当前帧，发送给本地 AI 服务进行识别。
4. 观察窗口左上角状态：

   - `YOLOv8 / LIVE INFERENCE`：当前帧已由真实 YOLOv8 模型识别，黄色框为本次返回结果；
   - `YOLOv8 / LOADING MODEL`：正在等待模型首次加载；
   - `YOLOv8 / MODEL OFFLINE`：AI 服务或模型不可用，页面不会伪造检测框。

5. 下方“当前识别”“问题累计”和“推理耗时”分别显示最新类别、当前帧检测数量和服务端推理耗时。

当前模型识别：缺孔 `missing_hole`、鼠咬 `mouse_bite`、断路 `open_circuit`、短路 `short`、毛刺 `spur`、多余铜 `spurious_copper`。

#### 启动要求

一键启动会在 `http://127.0.0.1:8000` 启动可选 FastAPI AI 服务。实时 YOLO Demo 需要：

- `ai-service/requirements.txt` 中的 `ultralytics` 依赖；
- `ai-service/models/pcb_defect_yolov8s.pt` 模型文件；
- 浏览器可以访问 AI 服务 8000 端口。

可先检查 `http://127.0.0.1:8000/api/vision/yolo/health`。返回 `modelExists: true` 但 `loaded: false` 是正常的懒加载状态，第一次提交视频帧后才会加载模型。

## 10. AI 诊断页

底部 **04 诊断** 进入。页面右上角可在两种模式间切换：**诊断 · Agent** ⇄ **生成式工厂 · 黛玉规划**。

> 所有修改类动作都必须经你人工审批，AI 不能直接改工厂；只读动作随时安全。

### 10.1 Agent 控制室（黑白工业风）

**命令栏**（页面上方）：

- 目标输入框（≤2000 字），示例：
  - `检查当前工厂的生产、库存和物流瓶颈`（默认）
  - `吞吐提升到每小时 120 件，场地宽度不超过 30 米`
- 模式按钮：`🛡 只读分析`（不改任何东西）/ `📄 方案设计`（会产出待审批 Patch）；
- 辅助巡检：`📈 自动巡检`（跑一轮）、`🔁 定时巡检`（每 60 秒自动一轮，激活时图标旋转）；
- 主执行按钮：`▶ 开始分析`（方案设计模式下为 `生成方案`）。

**左栏 执行计划**：编译目标约束 → 读取工厂上下文 → 执行只读工具 → 汇总证据与结论（方案设计再加 校验变更方案）。工具活动区会列出实际调用的只读工具（读取工厂快照、构建依赖图、诊断瓶颈等 12 个）。

**中栏 诊断结果**：headline + 置信度 + Finding 卡片（分类 库存/物流/生产/系统，附证据与建议）；卡片上的 `◎ 定位` 按钮会跳转并选中对应 3D 对象。

**右栏 运行证据**：当前吞吐/在制品/成品/仿真时间与工厂版本计数；结构变了可点 `重新分析当前版本`。

### 10.2 方案审批闭环（Patch）

方案设计完成后出现 **方案变更** 卡片：

1. 先点 `运行双分支对比`——系统用副本分别仿真「当前版」和「候选版」，对比吞吐/累计成品/在制品/阻塞/平均运输时间/库存六项指标，给出 建议应用/建议迭代/建议放弃；
2. 同意 → `✔ 批准并应用`（应用到你的存档，可 `↩ 回滚`）；拒绝 → `✖ 拒绝` 并填写原因，之后可 `🔄 重新规划`；
3. 有分析结论但没有 Patch 时，会出现 `根据当前结论生成修复方案` 按钮。

### 10.3 自动巡检与定时巡检

- 单次 `📈 自动巡检`：后台跑一个 60 秒只读证据副本（不动你的工厂），记录吞吐/利用率/阻塞/在途的指标时序，然后输出中文报告横幅；
- `🔁 定时巡检`：每 60 秒自动重复上述过程，直到你再次点击、切换项目或离开诊断页；
- 报告内容：趋势判定（上升/稳定/下降/临界 + 预计耗尽时间）、瓶颈因果链（如「供料者 A → 约束设备 B」）、待机能耗偏高的设备、货架耗尽预警；
- 劣化判定：相比基线吞吐降幅 ≥25%、阻塞增加或交付停滞时，报告会标注劣化并预填修复目标；
- 巡检**绝不写入存档**；报告的 AI 润色失败时自动回退确定性模板，功能不会因没有 AI 而消失。

### 10.4 生成式工厂（黛玉规划）

适合「从零造一个新厂」或大改：输入自然语言需求（如“齿轮箱月产 5000 件”），系统确定性解析成约束，搜索多个候选布局并逐一跑副本仿真，最后给出 Top 方案对比；校验通过后可一键应用到当前存档。

已知限制：针对**既有产线的局部调整**（A-01 场景）有时给不出足够数量的可验证候选而报错，这是当前生成器的已知缺口（详见第 15 节），重试或换更明确的目标通常可行。

## 11. 存档与数据安全

登录后首次必现 **项目弹窗**（标题 `开始你的工厂`；以后从顶栏 `项目库` 打开）：

- **新建空白工厂**：作为未保存草稿进入会话；
- **我的工厂存档**：正式存档列表（含更新时间、版本 vN、N 层 N 设施统计）；`打开` 载入，`删除` 二次确认后不可撤销；
- **自动恢复**：置顶的特殊条目，每 60 秒静默写入一份，仅保留最新一份；崩溃/误退后从这里 `恢复`；
- **文件交换**：`导入 JSON` 把 `.forgemind.json` 导入为当前会话（不入正式存档库）；`导出当前 JSON` 下载 `{工厂名}.forgemind.json`。

顶栏 **手动保存存档** 才会把当前会话写成正式存档（状态：保存中… / 已保存 / 保存失败·重试）。**记住：新建与导入都不等于保存。**

存档当前为 v6 格式；v1–v5 旧档会自动迁移（含历史乱码楼层名修复），未来版本号会被拒绝以防损坏。

ForgeMind **默认完全不依赖任何 AI 服务**，所有仿真、建造、诊断、巡检都能离线规则运行。AI 只是增强层：

## 14. 常见问题排查

| 现象 | 原因与处理 |
| --- | --- |
| 双击启动后浏览器打不开页面 | 看 Vite 窗口是否报错；5173 被占用时先跑停止脚本再启动 |
| 登录报 `认证链路中断` | Spring Boot(8080) 未启动；检查 Java 窗口日志，确认 Docker MySQL 已起 |
| 建造 ghost 一直是红色 | 越界、与现有设备重叠或端口格被占；挪开位置或先拆除冲突物 |
| 传送带画不出来/断线 | 拖绘要在地面网格上进行；坡道需两端同向对齐兼容接口 |
| 机器放着不干活 | ①没绑配方（点设备选 RECIPE）②配方被停用 ③入料口没接到上游 ④上游无货 |
| 传送带有货但下游不吃 | 下游端口类型不符（蓝入黄出），旋转或改线路 |
| AGV 一直「等待」不发货 | 起点货架没有足量指定物品，或阈值条件未满足——这是防凭空虚发的保护，不是 bug |
| 无人机没有路径 | 起终点在同层（本就该走 AGV），或路径被建筑净空挡死；换点重试 |
| 定时巡检点了没反应 | 上一轮还在跑（Worker 串行执行），稍候；离开诊断页会自动取消 |
| YOLO Demo 一直显示离线 | 检查 AI 服务 8000 端口、`/api/vision/yolo/health` 和 `ai-service/models/pcb_defect_yolov8s.pt`；依赖缺失时安装 `ai-service/requirements.txt` |
| YOLO Demo 一直显示加载中 | 首次加载模型需要预热；若超过一段时间仍无结果，检查 AI 服务日志和浏览器是否有多个旧 Demo 标签页同时请求 |
| 生成式规划报候选不足 | A-01 既有产线调整的已知缺口（见第 15 节）；换目标描述或改用 Agent 方案设计 |
| 存档保存失败 | 后端离线或数据库断开；修复后重点 `手动保存存档`，期间自动恢复仍在工作 |
| 中文显示乱码（旧档） | v6 解析器已自动修复绝大多数历史乱码；若仍遇到请反馈样本 |

## 15. 当前已知限制

以下是**如实声明**的现状，不代表承诺修复时间：

1. 生成式规划的既有产线局部调整（A-01 回归）可能因候选不足 3 个而失败；
2. 浏览器自动化视觉验收受登录墙限制，多数轮次只做了脚本级回归，界面细节以实机为准；
3. 巡检趋势是固定窗口线性外推，不是机器学习预测；纯运行性损耗（如货架随真实时间耗尽）不在逐轮对比中体现；
4. 瓶颈归因为 5 秒采样启发式，单机厂或低负载产线不给约束链；
5. `hardware/dm4310-arm/` 真机机械臂套件的固件未经真机烧录验收，电机量程常量需按批次核对；
6. 部分导入 GLB 的第三方许可证仍在复核中（见《资产与许可审计.md》）。

## 16. ForgeLab 开源社区

ForgeLab 是 ForgeMind 的配套开源社区，使用与工作台相同的账号。主门户点击 ForgeLab 后会先进入登录验证页；已有有效工作台会话可以直接验证进入，未登录时使用工作台用户名和密码登录。

社区包含五个板块：

- 工厂存档开源：分享可复现的楼层、设备、仓储和运行结果；
- 模型资源开源：说明 GLB 的原点、包围盒、接口方向、来源与许可；
- 布局经验分享：记录网格、维护通道、坡道落点和避障检查；
- 设计经验分享：沉淀设计目标、约束、判断和验证过程；
- 设计者公告：发布社区规范、版本变化和资源治理说明。

### 16.1 阅读、下载和讨论

点击帖子卡片会进入独立文章页。正文、作者、版本信息、相关帖子和附件都在文章页展示。后端已接入的附件通过鉴权下载接口读取；仍在公共目录中的模型和视频直接使用资源路径。阅读资源时先确认许可和来源，再下载或复用。

文章底部可以喜欢帖子、跳到现场讨论、喜欢单条回复和发布新回复。回复优先写复现条件、版本、约束和证据，不要只留下无法检查的结论。

### 16.2 发布帖子

点击社区主视觉的“发布帖子”按钮打开编辑窗口，依次填写板块、标题、摘要和正文；需要时增加图片、工厂存档或资源包，并在 AI 润色提示词中说明希望调整的方向。AI 只帮助整理表达，发布前仍需人工检查事实、版本、许可和附件内容。

登录并且后端可用时，帖子与附件会写入 ForgeLab 数据库；网络暂时不可用时，页面会明确提示并保留当前会话草稿，不会把本地草稿伪装成已同步的公共资源。

### 16.3 通知与工厂助手

通知中心显示社区公告、回复和点赞事件，可单条标记已读或全部标记已读。右侧 ForgeLab 工厂助手默认使用本地规则回答发布、许可、布局和设计问题；启用可选 AI 服务后，AI 可以进一步润色解释，但不会替代工厂仿真的碰撞、寻路、库存或物料结论。

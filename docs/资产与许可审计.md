# ForgeMind 资产与许可审计

> 当前基线：2026-08-19  
> 适用目录：`public/models/`、用户导入资源及迁入的 ForgeCore 制作工具

## 1. 资产分类

| 类别 | 位置 | 规则 |
| --- | --- | --- |
| ForgeCore 原创物品 | `public/models/forgecore/items/` | 由项目生成器重建，保持稳定 modelId 和校验清单 |
| ForgeCore 第三方车辆 | `public/models/forgecore/*.glb` | 保留原作者、来源、CC BY 4.0 和修改声明 |
| ForgeMind 工业/机器人资产 | `public/models/industrial/`、`public/models/panda/`、根级机器人 GLB | 逐项确认来源和再分发权，未完成前不宣称可自由商用 |
| 用户私有导入 | 浏览器 Blob URL 与后端 `imported_resource` | 不写入公共目录，按用户隔离 |
| 历史参考 | `docs/archive/forgecore/` | 只用于追溯，不自动获得运行时或分发许可 |

## 2. ForgeCore 默认物品库

- 目录包含 36 个稳定模型，分为 basic、material、mechanical、electronic 和 package 五类。
- 36 个 GLB 与 36 张预览图已逐项和原 ForgeCore 基线对比，72/72 个文件 SHA-256 一致。
- `catalog.json` 是运行时目录，`SHA256SUMS` 是完整性清单。
- 生成器已迁入 `tools/item-models/`，默认输出适配为 `public/models/forgecore/items/`。
- GLB 契约：2.0、自包含、米制、Y-up、底面中心原点；业务质量与堆叠数量不写入几何 schema。

迁移包中曾位于目录根部的 `box.glb`、`cone.glb`、`cylinder.glb`、`disc.glb`、`ring.glb`、`sphere.glb` 实为 Git LFS 指针，并非可加载模型。它们已按原文本迁入 `docs/archive/forgemind-lfs-pointers/`；当前运行时只使用 `basic/*.glb` 的完整文件，物品库可继续执行严格 `SHA256SUMS` 校验。

## 4. 工业和机器人资产

`public/models/industrial/` 当前包含从 realvirtual WEB 示例/模型来源整理的产线、CNC、机器人单元、输送设备、安全围栏、控制柜和传感器等资产，拆分关系见 `manifest.json` 与 `docs/模型与工艺来源.md`。项目现有文档只证明其技术来源和本地演示用途，尚未为每个拆分文件提供独立、可公开再分发的许可证副本。因此：

- 可继续用于当前本地教学、开发和答辩包；
- 不得将其标记为 ForgeMind 原创、CC0 或默认可商用；
- 发布到公共资产市场或商业分发前必须逐文件复核上游条款；
- 拆分脚本只改变打包结构，不自动改变原资产许可证。

`robot_arm_6dof_white.glb` 的现有记录指向 cobot-atlas（MIT）；`panda/`、`robot_irb2400.glb`、`forklift_agv.glb` 及其他根级模型仍需在后续审计中补齐来源文件、许可证副本、原始 SHA-256 和修改说明。在审计完成前按“来源已记录或待复核、不得扩大分发”处理。

## 5. 用户导入资源

用户导入 JSON/GLB 时，前端只进行结构、GLB、包围盒和预览校验，不替用户判断版权。后端将资源绑定到当前用户并验证 `resourceId` 归属。界面和文档应提示用户仅上传拥有使用权的内容；私有存储不等于获得再分发许可。

## 6. 制作与验证流程

```powershell
node tools/item-models/build.mjs
node tools/item-models/validate.mjs
npm run models:validate:strict
```

工业资产拆分使用 `scripts/split-industrial-glb.mjs`；物品运行时预览刷新可使用 `npm run models:refresh`。修改生成器后必须同时检查 `catalog.json`、`SHA256SUMS`、GLB 结构、预览、三角面预算和运行时加载。

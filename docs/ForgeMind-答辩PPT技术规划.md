# ForgeMind 答辩 PPT 技术规划

> 文档用途：指导 ForgeMind 智能工厂数字孪生平台答辩 PPT 的内容组织、技术讲解和现场演示。
>
> 规划原则：按照产品功能和业务闭环组织内容，不按照源代码目录逐文件介绍；每个功能模块内部再说明核心算法、数据流、代码入口和验证方式。
>
> 当前事实优先级：代码与《ForgeMind-当前实现总览》高于早期方案文档。答辩中必须区分“当前已实现”“部分实现”和“后续规划”。

## 1. 答辩目标与总体叙事

### 1.1 一句话沟通目标

答辩结束时，评委应该理解：

> ForgeMind 不是静态三维工厂，而是一个可以建造、存储、运行、导航、诊断、优化和语音控制的数字工厂系统；它用确定性仿真验证生产事实，用黛玉推理层生成方案，用宝钗渲染层呈现高精度工厂。

### 1.2 推荐叙事顺序

```text
现实问题
  ↓
ForgeMind 总体闭环
  ↓
工厂如何被创建和保存
  ↓
工厂如何运行和产生状态
  ↓
物料、车辆和机器人如何移动
  ↓
视觉如何完成质量检测
  ↓
宝钗如何呈现工厂
  ↓
黛玉如何规划工厂
  ↓
诊断和 What-if 如何优化工厂
  ↓
本地 LLM 如何理解和控制工厂
  ↓
测试、性能和边界
```

### 1.3 PPT 规模建议

- 正式主讲版：约 35 页。
- 技术完整版：主讲版加 8～12 页附录。
- 现场演示：控制在 5～8 分钟，展示一条完整业务链。
- 每页只保留一个核心结论，代码和细节放在技术附录。

### 1.4 每页固定结构

每个功能页建议固定回答四个问题：

1. 这个功能解决什么问题？
2. 技术上如何实现？
3. 它和其他功能如何协作？
4. 用什么测试或现场操作证明它有效？

## 3. 35 页主讲版规划

### 第 1 页｜封面：让工厂先在数字世界里运行

**核心结论**：ForgeMind 是 AI 驱动的智能工厂数字孪生、生产路线与仿真平台。

**页面内容**：

- 项目名称和副标题；
- 真实三维工厂或生产线主视觉；
- 项目成员、答辩信息；
- ForgeMind 品牌视觉。

**建议讲法**：先用一句话说明平台的核心价值，不在封面堆技术栈。

### 第 2 页｜现实问题：工厂方案需要在投入前被验证

**页面内容**：

- 设备布局依赖经验；
- 设备与物流连接容易出错；
- 产能、拥堵和瓶颈难以提前验证；
- AI 方案如果不经过仿真，可能只是视觉上合理。

**建议讲法**：引出平台必须同时具备建模、运行、诊断和优化能力。

### 第 3 页｜平台闭环：从需求到可验证工厂

```text
生产需求
  → 工厂建模
  → 设备连接
  → 离散仿真
  → 物流导航
  → 视觉质检
  → AI 诊断
  → 方案优化
  → 用户确认应用
```

**建议讲法**：这页是全场主线，后续每个功能都回到这条链路。

### 第 4 页｜总体架构：两个引擎、三个服务、一个运行闭环

**页面内容**：

- React / Three.js：编辑器、场景和交互；
- TypeScript：仿真、导航、诊断和领域逻辑；
- 宝钗：工厂渲染和性能管理；
- 黛玉：工厂规划和方案推理；
- Spring Boot + MySQL：用户、工厂结构和资源持久化；
- FastAPI：LLM、ASR、TTS 和 OpenCV。

**必须强调**：当前实时仿真事实源是浏览器端 TypeScript；Spring Boot 不逐 tick 接管仿真；AI 不进入实时仿真循环。

### 第 5 页｜工厂建模：设备可以被放置、旋转和验证

**技术点**：

- `FactoryObject` 统一描述设备；
- 网格坐标和设备足迹；
- 0/90/180/270 度旋转；
- Ghost 合法/非法预览；
- 边界和碰撞校验；
- 设备分类和详情面板；
- 多楼层对象。

**代码入口**：`src/game/types.ts`、`src/game/grid.ts`、`src/scene/BuildPlacer.tsx`。

### 第 6 页｜物品、配方和端口：设备连接具有业务语义

**技术点**：

- `Item` 表示物品类型；
- `Recipe` 表示输入、输出和加工时间；
- `ItemLot` 表示运行中的物料实例；
- Source 绑定物品；
- Machine 绑定配方；
- 输入口、输出口和端口方向；
- Splitter 多输出、Merger 多输入。

**核心结论**：输送线不是只靠画面连上，而是通过端口和方向进行验证。

### 第 7 页｜存储功能：工厂结构可以离线和云端保存

**技术点**：

- 本地 JSON 存档；
- FactorySave v2；
- v1 → v2 迁移；
- Spring Boot 云端存档；
- 用户、物品、配方、设备和楼层持久化；
- 离线时继续使用本地工厂和仿真。

**数据边界**：高频 ItemLot、传送带槽位、机器进度和车辆坐标不逐 tick 写数据库。

### 第 8 页｜生产仿真：工厂不是播放动画

**技术点**：

- 固定步长；
- 逻辑时钟；
- 仿真倍率；
- 暂停和重置；
- 种子化随机数；
- `SimulationRunner`；
- `SimulationSnapshot`。

**核心流程**：

```text
工厂结构 → SimulationEngine → 固定步推进 → Snapshot → UI / 诊断 / 场景
```

### 第 9 页｜状态机：用离散状态管理工厂运行

**核心结论**：每个功能都有明确的开始条件、运行过程、完成条件和异常处理。

**状态机体系**：

- Source：`idle → picking → placing → idle / blocked`；
- Machine：`idle → loading → processing → output / blocked`；
- ItemLot：创建、进带、占槽、推进、转移、消耗；
- AGV：`idle / moving / waiting`，并包含让行、重规划和恢复决策；
- Drone：停靠、去仓库、升降、环线、配送、返航；
- Robot：home、approach、pick、grip、transport、place、release、return。

### 第 10 页｜传送带背压：瓶颈可以在仿真中自然出现

**技术点**：

- 离散槽位；
- 每段容量；
- 物料不能穿透；
- 下游满载；
- 头堵；
- 背压向上游传播；
- Source 和 Machine 停止输出；
- 分流和汇流容量约束。

**建议演示**：人为堵住下游，展示传送带停止、机器阻塞和诊断结果变化。

### 第 11 页｜工厂诊断：从仿真状态找到瓶颈

**诊断输入**：

- 工厂对象；
- 配方和端口关系；
- 仿真快照；
- 机器状态；
- 在途物料；
- AGV / Drone 状态；
- 楼层统计。

**诊断输出**：

- 瓶颈设备；
- 断链；
- 物流阻塞；
- 低利用率；
- 影响路径；
- 推荐调整。

### 第 12 页｜导航总览：任务驱动的动态物流系统

**核心结论**：导航不是点到点移动，而是任务、路径、障碍、交通状态和运输阶段共同决定的动态系统。

**导航对象**：

- AGV 地面导航；
- 无人机跨层导航；
- 仓储装卸任务；
- 多车辆协同；
- 仿真状态驱动；
- 三维场景只呈现导航结果。

### 第 13 页｜AGV 路径规划：带安全边界的确定性 A*

**技术点**：

- 工厂设备构造静态障碍；
- 动态车辆构造临时障碍；
- 车辆实际模型包围范围；
- 8 方向搜索；
- 欧氏距离启发函数；
- 防止斜向穿过障碍角；
- 路径回溯和转折点简化；
- 起点和终点特殊放行。

**流程**：

```text
静态障碍 + 动态障碍 → A* → 路径回溯 → 路径简化 → 仿真执行
```

### 第 14 页｜AGV 任务和多车交通调度

**核心结论**：宝钗负责“把工厂稳定地画出来”。

- AGV 路线；
- 仿真结果；
- 方案评分；
- ROI；
- 调整差异。

### 第 25 页｜诊断优化：基线、最小重布线和完整重构

**三类方案**：

1. 当前工厂基线；
2. 最小重布线；
3. 完整重构。

**应用流程**：

```text
复制工厂 → 应用改动 → 校验 → 副本仿真 → 指标对比 → 用户确认 → 应用 / 撤销
```

**边界**：当前 A-01 调整分支仍存在候选数量和可验证性问题，不能表述为全量稳定通过。

### 第 26 页｜本地 LLM：理解意图但不决定事实

**当前组成**：

- Ollama；
- Qwen2.5:7b；
- FastAPI 编排；
- 可选 DeepSeek；
- 规则解析降级。

**LLM 负责**：

- 工厂状态问答；
- 生产需求解析；
- 工艺约束提取；
- 诊断解释；
- 工具动作选择。

**LLM 不负责**：

- 直接生成未经校验的坐标；
- 直接修改工厂；
- 直接推进仿真；
- 直接决定产能事实。

### 第 28 页｜本地 LLM 安全门控与语音链路

**安全流程**：

```text
LLM 动作
  → FastAPI 校验
  → 前端协议校验
  → 对象和引用校验
  → 高风险动作确认
  → Zustand 受控执行
```

**语音流程**：

```text
麦克风 → Paraformer ASR → Ollama → 工具协议 → BT TTS
```

**降级**：Ollama、TTS 或 ASR 不可用时，系统不伪造结果，回退到规则、普通文本或 Sherpa VITS。


### 第 34 页｜当前边界与后续路线

必须如实说明：

- A-01 调整回归仍有已知问题；
- 生产效率部分仍可能是演示读数；
- Spring Boot 不负责实时仿真；
- 多输出配方运行时仍有边界；
- 视觉检测的 LLM 解读和手柄全流程待增强；
- 暂无公共资源市场和对象存储；
- 完整角色权限和限流体系待完善。

### 第 35 页｜项目创新点与结束语

**创新点**：

1. 工厂不仅能被看见，还能被运行；
2. 仿真采用固定步长和可复现随机数；
3. AI 方案必须通过连接和仿真验证；
4. 物流、机器人和视觉处于同一工厂闭环；
5. 宝钗负责呈现，黛玉负责推理；
6. 用户可以导入私有工业模型；
7. 本地 LLM 通过工具协议受控执行。

**结束语**：

> ForgeMind 让工厂从“被展示的三维模型”，变成“可以被设计、运行、理解、验证和优化的数字系统”。

## 6. 答辩表述红线

- 不要说 Spring Boot 是实时仿真服务器；
- 不要把固定演示读数称为真实 OEE；
- 不要把所有工业机器人模型都称为完整运动学仿真；
- 不要把 A-01 调整回归说成全量通过；
- 不要说 LLM 可以直接修改工厂；
- 不要把未来的 Redis、Kafka、对象存储和 Worker 说成当前依赖；
- 不要忽略用户资源和 GLB 模型的许可证边界；
- 不要把视觉检测的后续增强描述成已经完全闭环。

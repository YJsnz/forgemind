# ForgeMind 答辩 PPT 技术规划

> 文档用途：指导 ForgeMind 智能工厂数字孪生平台答辩 PPT 的内容组织、技术讲解和现场演示。
>
> 规划原则：按照产品功能和业务闭环组织内容，不按照源代码目录逐文件介绍；每个功能模块内部再说明核心算法、数据流、代码入口和验证方式。
>
> 当前事实优先级：代码与《ForgeMind-当前实现总览》高于早期方案文档。答辩中必须区分“当前已实现”“部分实现”和“后续规划”。

> 本版更新：2026-09-03。以下规划已按当前代码和最近验证结果校准；旧版 PPT 中出现的“本地 LLM 默认启动”“8 个助手工具”“Flyway V1–V6”“A-01 调整未形成稳定可应用候选”等表述均应替换。

## 1. 答辩目标与总体叙事

### 1.1 一句话沟通目标

答辩结束时，评委应该理解：

> ForgeMind 不是静态三维工厂，而是一个可以建造、存储、运行、导航、诊断、优化和协同的数字工厂系统；它用确定性仿真验证生产事实，用黛玉推理层生成方案，用宝钗渲染层呈现工厂，用规则优先的智能助手把复杂操作变成受控工具调用。

### 1.2 推荐叙事顺序

```text
现实问题
  ↓
ForgeMind 总体闭环
  ↓
工厂如何被创建和保存
  ↓
工厂如何运行和产生状态
  ↓
物料、车辆和机器人如何移动
  ↓
视觉如何完成质量检测
  ↓
宝钗如何呈现工厂
  ↓
黛玉如何规划工厂
  ↓
诊断和 What-if 如何优化工厂
  ↓
智能助手、Agent 和主动巡检如何协作
  ↓
Forge 生态和桌面客户端如何复用同一事实源
  ↓
  测试、性能和边界
```

### 1.3 PPT 规模建议

- 正式主讲版：建议约 38 页；若必须控制在 35 页，合并第 12/13 页、第 31/32 页和第 36/37 页。
- 技术完整版：主讲版加 8～12 页附录。
- 现场演示：控制在 5～8 分钟，展示一条完整业务链。
- 每页只保留一个核心结论，代码和细节放在技术附录。

### 1.4 每页固定结构

每个功能页建议固定回答四个问题：

1. 这个功能解决什么问题？
2. 技术上如何实现？
3. 它和其他功能如何协作？
4. 用什么测试或现场操作证明它有效？

## 3. 38 页主讲版规划（在旧 35 页骨架上增补 3 页）

### 第 1 页｜封面：让工厂先在数字世界里运行

**核心结论**：ForgeMind 是规则优先、AI 可选的智能工厂数字孪生、生产路线与仿真平台。

**页面内容**：

- 项目名称和副标题；
- 真实三维工厂或生产线主视觉；
- 项目成员、答辩信息；
- ForgeMind 品牌视觉。

**建议讲法**：先用一句话说明平台的核心价值，不在封面堆技术栈。

### 第 2 页｜现实问题：工厂方案需要在投入前被验证

**页面内容**：

- 设备布局依赖经验；
- 设备与物流连接容易出错；
- 产能、拥堵和瓶颈难以提前验证；
- AI 方案如果不经过仿真，可能只是视觉上合理。

**建议讲法**：引出平台必须同时具备建模、运行、诊断和优化能力。

### 第 3 页｜平台闭环：从需求到可验证工厂

```text
生产需求
  → 工厂建模
  → 设备连接
  → 离散仿真
  → 物流导航
  → 视觉质检
  → 确定性诊断 / 自动巡检
  → Agent 方案与 What-if
  → 校验、审批、应用 / 回滚
  → 版本发布与移动/社区协作
```

**建议讲法**：这页是全场主线，后续每个功能都回到这条链路。

### 第 4 页｜总体架构：一个确定性核心、一个渲染层、两类服务

**页面内容**：

- React / Three.js：编辑器、场景和交互；
- TypeScript 确定性核心：仿真、导航、诊断、生成式规划和 Agent 事实校验；
- 宝钗渲染层：静态模型/传送带批处理、动态对象接管和性能预算；
- 黛玉推理层：配方图、布局候选、校验、副本仿真和 What-if；
- Spring Boot + MySQL：身份、工厂结构、资源、云端项目版本、Agent 运行和审计；
- FastAPI 与语音服务：规则/可选 Qwen 编排、RAG、ASR、TTS 和视觉辅助；
- Windows 桌面可选 Unity：只作为 WebView2 的渲染投影，未握手时回退 WebGL。

**必须强调**：当前实时仿真、碰撞、寻路、物料守恒和权限事实源是前端 TypeScript 与服务端校验链；Spring Boot 不逐 tick 接管仿真；AI 不进入实时仿真循环，也不直接决定坐标、数量或指标。

### 第 5 页｜工厂建模：设备可以被放置、旋转和验证

**技术点**：

- `FactoryObject` 统一描述设备；
- 网格坐标和设备足迹；
- 0/90/180/270 度旋转；
- Ghost 合法/非法预览；
- 边界和碰撞校验；
- 设备分类和详情面板；
- 多楼层对象。

**代码入口**：`src/game/types.ts`、`src/game/grid.ts`、`src/scene/BuildPlacer.tsx`。

### 第 6 页｜物品、配方和端口：设备连接具有业务语义

**技术点**：

- `Item` 表示物品类型；
- `Recipe` 表示输入、输出和加工时间；
- `ItemLot` 表示运行中的物料实例；
- Source 绑定物品；
- Machine 绑定配方；
- 输入口、输出口和端口方向；
- Splitter 多输出、Merger 多输入。

**核心结论**：输送线不是只靠画面连上，而是通过端口和方向进行验证。

### 第 7 页｜存储与版本：工厂结构可以离线、云端、可追溯

**技术点**：

- 本地 JSON 存档；
- FactorySave v6，兼容旧版本迁移；
- Spring Boot 云端存档与按用户隔离；
- ForgeCloud 项目版本、不可变发布、评论和 `409 VERSION_CONFLICT` 并发保护；
- 资源 manifest、许可证、Blob 和不可变资源版本；
- Unity 与 WebGL 共用存档、楼层、坐标、端口语义；
- 后端不可用时继续使用明确标注的本地工厂与仿真。

**数据边界**：高频 ItemLot、传送带槽位、机器进度和车辆坐标不逐 tick 写数据库；数据库保存可恢复结构、版本、任务、审计和云端长期事实。

### 第 8 页｜生产仿真：工厂不是播放动画

**技术点**：

- 固定步长；
- 逻辑时钟；
- 仿真倍率；
- 暂停和重置；
- 种子化随机数；
- `SimulationRunner`；
- `SimulationSnapshot`。

**核心流程**：

```text
工厂结构 → SimulationEngine → 固定步推进 → Snapshot → UI / 诊断 / 场景
```

### 第 9 页｜状态机：用离散状态管理工厂运行

**核心结论**：每个功能都有明确的开始条件、运行过程、完成条件和异常处理。

**状态机体系**：

- Source：`idle → picking → placing → idle / blocked`；
- Machine：`idle → loading → processing → output / blocked`；
- ItemLot：创建、进带、占槽、推进、转移、消耗；
- AGV：`idle / moving / waiting`，并包含让行、重规划和恢复决策；
- Drone：停靠、去仓库、升降、环线、配送、返航；
- Robot：home、approach、pick、grip、transport、place、release、return。

### 第 10 页｜传送带背压：瓶颈可以在仿真中自然出现

**技术点**：

- 离散槽位；
- 每段容量；
- 物料不能穿透；
- 下游满载；
- 头堵；
- 背压向上游传播；
- Source 和 Machine 停止输出；
- 分流和汇流容量约束。

**建议演示**：人为堵住下游，展示传送带停止、机器阻塞和诊断结果变化。

### 第 11 页｜工厂诊断：从仿真状态找到瓶颈

**诊断输入**：

- 工厂对象；
- 配方和端口关系；
- 仿真快照；
- 机器状态；
- 在途物料；
- AGV / Drone 状态；
- 楼层统计。

**诊断输出**：

- 瓶颈设备；
- 断链；
- 物流阻塞；
- 低利用率；
- 影响路径；
- 推荐调整。

**新增可信口径**：Finding 必须绑定对象、证据窗口和确定性仿真指标；没有足够运行证据时降低置信度，不能用模型记忆替代实时事实。

### 第 12 页｜自动巡检：从一次诊断升级为持续观察

**核心结论**：系统不只在出问题后回答，还能定时采样、比较基线并主动提醒；提醒不会绕过方案校验和人工审批。

**技术点**：

- 每轮固定种子运行 60 秒只读证据副本；
- 吞吐、利用率、阻塞、在途形成 36 点环形时序；
- 最小二乘输出 rising / stable / declining / critical 与归零 ETA；
- 5 秒采样形成“供料者 → 约束设备”的瓶颈因果链；
- 能耗按运行满功率/待机 15% 做确定性归因提示；
- 用户级提醒策略、冷却去重、严重度升级与恢复后重新 claim；
- 劣化只注入 Finding/方案目标，不直接修改存档。

### 第 13 页｜导航总览：任务驱动的动态物流系统

**核心结论**：导航不是点到点移动，而是任务、路径、障碍、交通状态和运输阶段共同决定的动态系统。

**导航对象**：

- AGV 地面导航；
- 无人机跨层导航；
- 仓储装卸任务；
- 多车辆协同；
- 仿真状态驱动；
- 三维场景只呈现导航结果。

### 第 14 页｜AGV 路径规划：带安全边界的确定性 A*

**技术点**：

- 工厂设备构造静态障碍；
- 动态车辆构造临时障碍；
- 车辆实际模型包围范围；
- 8 方向搜索；
- 欧氏距离启发函数；
- 防止斜向穿过障碍角；
- 路径回溯和转折点简化；
- 起点和终点特殊放行。

**流程**：

```text
静态障碍 + 动态障碍 → A* → 路径回溯 → 路径简化 → 仿真执行
```

### 第 15 页｜AGV 任务和多车交通调度

- 数量；
- 装载；

**交通处理**：

- 让行；
- 局部绕行；
- 重规划；
- 阻塞时间统计；

### 第 16 页｜无人机：通过升降井完成跨层运输

**技术点**：

### 第 17 页｜机械臂仿真：设备具备运动和任务能力

**技术点**：

- 末端执行器；
- 夹爪；
- 自动模式；
- 手动模式；
- 抓取、搬运、装配和分拣。

**边界说明**：Panda 具备实际 IK 控制；IRB2400 当前主要承担高精度设备展示。

### 第 18 页｜机器人控制：DLS IK 与任务状态机

**运动流程**：

```text
末端目标位姿 → DLS IK → 关节角 → 限位和阻尼 → 关节树更新
```

**任务流程**：

```text
home → approach → pick → grip → transport → place → release → return
```

**控制方式**：

- 键盘；
- 手柄；
- 自动任务；
- `forgemind:robot-command` 事件；
- 夹爪和物料跟随。

### 第 19 页｜视觉检测：从相机到分拣的质量闭环

**流程**：

```text
抓取臂取件 → 相机臂对位 → 虚拟相机 → OpenCV → PASS / FAIL → 机械臂分拣
```

**技术点**：

- 双臂协作；
- WebGL 离屏相机；
- WebGLRenderTarget；
- 像素读取；
- HSV 分割；
- 轮廓和连通域；
- 划痕、毛刺和尺寸偏差；
- 合格品和不合格品路由。

### 第 20 页｜宝钗渲染层：高精度模型的运行时管理

**核心结论**：宝钗负责“把工厂稳定地画出来”。

**技术点**：

- 工厂领域渲染策略；
- 模型生命周期；
- 静态设备批处理；
- 传送带批处理；
- Panda 静止合批；
- 动态对象接管；
- 点击实例映射回业务 ID；
- 不改变原始模型资产。

### 第 21 页｜宝钗性能与桌面渲染：保持事实链不变

**技术点**：

- `cold → prewarming → ready → running`；
- 登录阶段隐藏工厂；
- Panda 模板预加载；
- 材质预编译；
- 阴影预算；
- 端口标记预算；
- DPR 调整；
- `frameloop="demand"`、阴影缓存和可见性裁剪；
- 60 / 120 FPS 本机目标档位，不等同于所有硬件的稳定承诺；
- FPS、P95、draw call、三角形、纹理和 GPU 帧时间监控；
- 超过 120 个对象时降低快照提交频率，不降低模型事实和仿真精度。

**桌面补充**：Windows WebView2 构建可在 `bridge.ready` 后切换到 Unity 原生渲染；Web 仍是业务状态和权限事实源，Unity 只接收场景/快照投影。握手失败或普通 Web 构建继续使用 WebGL。

### 第 22 页｜黛玉推理层：自动规划可运行工厂

**核心结论**：黛玉负责“想清楚工厂应该怎样运行”。

**技术流程**：

```text
生产需求 → GenerationSpec → Recipe Graph → 设备估算 → 布局 → 路由 → 校验 → 仿真
```

**输出**：

- 设备布局；
- 物料和配方；
- 输送线路；
- AGV 路线；
- 仿真结果；
- 方案评分；
- ROI；
- 调整差异。

### 第 23 页｜黛玉的需求解析与工艺规划

**输入示例**：

```text
生产齿轮箱，每小时 120 件，场地 30 × 20 米，
最多 4 台 CNC、3 台 AGV，低能耗优先。
```

**结构化结果**：

- 产品 Profile；
- 目标吞吐；
- 场地尺寸；
- 设备数量上限；
- AGV 数量上限；
- 优化目标；
- 经济参数。

**验证内容**：

- 设备边界；
- 设备碰撞；
- 上游输出连接；
- 下游输入连接；

- 副本仿真产出。

**核心原则**：没有通过校验和仿真的候选方案不能标记为可靠方案。

### 第 25 页｜黛玉的搜索、What-if 与 ROI

- 初始候选；
- Beam Search；

- 候选去重；
- Pareto 排名；
- 增加 CNC；
- 增加装配机；

- CAPEX；
- 月度收益；
- 回本期；
- 12 个月 ROI。

### 第 26 页｜诊断优化与 Factory Agent：从 Finding 到受控方案

**三类方案**：

1. 当前工厂基线；
2. 最小重布线；
3. 完整重构。

**应用流程**：

```text
复制工厂 → 应用改动 → 校验 → 副本仿真 → 指标对比 → 用户确认 → 应用 / 撤销
```

**当前实现**：A-01 调整器可返回“现状基线 / 最小重布线 / 完整重构”三类候选，其中 2 个可应用；A-02 齿轮箱生成回归 3/3 通过。候选仍必须经过对象、端口、楼层、碰撞、路线和副本仿真校验。

### 第 27 页｜Agent 可信执行：异步、可恢复、可审批

**任务链**：

```text
读取当前版本 → 工具执行 → Finding/证据 → 候选方案
→ 受控 Patch 草案 → 服务端深校验 → 人工审批 → 应用/回滚
```

**当前能力**：

- 诊断、方案、应用后复核和分支比较在 Web Worker 执行，页面可取消；
- 任务按阶段写入 `agent_step`，通过 SSE 活动流并以轮询兜底；
- 可恢复错误自动重试，停止/取消竞态保留取消意图；
- 页面刷新后可显式恢复未结束 run，服务端只读 run 超时可自动续跑；
- 服务端重新读取当前项目并校验版本、对象归属、边界、碰撞、库存和操作上限；
- `plan_design` 不自动生成或应用 Patch，任何修改都要人工审批并可回滚。

### 第 28 页｜智能助手：规则优先，模型可选

**运行原则**：

- 默认使用 `rule`，不要求启动 Ollama、Qwen 或远程模型；
- Qwen/Ollama 由服务端环境变量显式启用，密钥不进入浏览器；
- FastAPI 只负责编排、解释、RAG 和可选模型调用；
- 模型不可用时，确定性工具和规则回答继续工作。

**助手/模型负责**：

- 工厂状态问答；
- 生产需求解析；
- 工艺约束提取；
- 诊断解释；
- 工具动作选择和文档片段引用；
- 主动巡检报告润色，不改变指标和 Finding。

**明确不负责**：

- 直接生成未经校验的坐标；
- 直接修改工厂；
- 直接推进仿真；
- 直接决定产能、库存、路线、碰撞和质量事实。

### 第 29 页｜助手上下文、工具协议与语音链路

**上下文**：

- 仿真状态、在途物料、设备 ID/角色、配方和物品绑定；
- 当前页面/楼层、任务阶段、最近 Agent 运行摘要；
- 当前项目最近 12 个版本摘要、用户批准的偏好和提醒策略。

**工具协议**：

- 共 26 个白名单工具，覆盖状态/对象查询、面板与楼层导航、仿真控制、配方和 Source 配置、Agent 任务查看、并排面板比较及生态产品深链接；
- 服务端和前端双重校验面板、任务 ID、对象引用和当前用户边界。

**安全与语音**：

```text
助手/模型动作 → 服务端校验 → 前端协议校验 → 确认门控 → 受控执行
麦克风 → ASR → rule / 可选 Qwen → 工具协议 → BT TTS / 浏览器朗读
```

AI、ASR 或 TTS 不可用时，不伪造结果，回退到规则、普通文本、浏览器 `speechSynthesis` 或 Sherpa VITS；主动提醒按用户策略、冷却和严重度升级控制，恢复后可重新提醒。

### 第 30 页｜ForgePass 与 Forge 生态：统一身份、分工协作

**生态分工**：

- ForgePass：统一注册、登录、会话和用户边界；
- ForgeMind：工厂设计、确定性仿真、诊断和方案验证；
- ForgeCloud：项目、版本、协作、设备、数据、资源和 AI 控制平面；
- ForgeLab：存档/模型开源、经验分享、帖子和回复；
- ForgeMove：移动端总览、生产监控、任务、库存和社区入口；
- ForgeHub：资产入口，当前保留预留路由，不宣称公共资源市场已完成。

**统一身份链**：ForgePass Bearer 会话 → 后端 `me` 校验 → 按用户/工作空间/项目角色授权；产品之间跳转不绕过认证。

### 第 31 页｜ForgeCloud：云端控制平面与版本账本

```text
工作空间
  → 项目版本 / 资源版本
  → 发布 / 评论 / 任务 / 审批
  → 设备 / 孪生 / 数据 / 运行质量
  → 活动流 / Outbox / 审计
  → 移动端与生态产品摘要
```

**六层能力**：Project Cloud、Device Cloud、Twin Cloud、Asset Cloud、Data Cloud、AI Cloud。

**当前可讲**：项目版本、`409 VERSION_CONFLICT`、资源 manifest/许可证/不可变版本、Blob 上传下载、成员角色、统一审批、活动流、设备心跳、遥测事件、规则 AI 任务均有真实基础闭环。

**边界**：设备命令默认只入 `pending` 审计队列；真实 OPC UA/MQTT、设备执行器、专业时序引擎、MinIO/S3 和远程模型路由仍是后续工作。

### 第 32 页｜ForgeMove 与 ForgeLab：把工厂带到移动端和社区

**ForgeMove**：

- 原生微信小程序，包含登录/演示、工厂总览、生产线监控、移动任务、库存、社区、工厂档案和设置 8 个页面；
- 复用统一 Bearer 会话和移动摘要 API；
- 在线读取真实摘要，服务不可用时显示明确标记的离线演示数据；
- 不直连 MySQL、不执行 Agent Patch、不冒充三维或逐 tick 事实。

**ForgeLab**：

- 统一身份下的开源社区，支持帖子、回复、点赞、附件、通知和许可/复现提示；
- 可关联已发布帖子和不可变项目/资源版本；
- 后端不可用时才回退当前会话缓存与规则回答。

### 第 33 页｜后端、安全与用户资源隔离

**技术点**：

- Spring Boot REST、BCrypt、Bearer Token、Token SHA-256、MySQL、Flyway V1–V30；
- workspace / project 角色（owner、admin、manager、editor、viewer）；
- 版本指纹和 `409 VERSION_CONFLICT` 并发保护；
- 资源、工厂、Agent run、任务、审批、活动和审计按授权边界过滤；
- 结构化存档 API、资源归属和 Patch 引用由服务端再次校验。

### 第 34 页｜用户资源导入：可扩展但不越权

```text
project.json + GLB
  → 字段/许可证校验
  → 模型预览、包围盒归一化、底面归零
  → 生成封面并注册私有设备
  → Asset Blob 适配层保存 SHA-256、版本和对象元数据
  → 鉴权下载 / 工厂引用
```

**边界**：用户资源与公共模型目录分离；工厂保存时验证 `resourceId` 属于当前用户。公开资源缺少许可证声明会被拒绝；当前默认本地对象存储适配层，MinIO/S3 为部署适配项。

### 第 35 页｜自动化验证体系

**测试分层**：

- 确定性仿真：基础闭环、转弯、分流、汇流、背压、Source 生命周期、跨层输送；
- 物流与交互：AGV/无人机导航、多楼层、建造拖绘、存档迁移；
- Agent/助手：26 工具协议、任务计划、Qwen 评测、提醒/记忆/指标隔离；
- 生成式工厂：A-02 3/3 候选，A-01 3 类候选及 2 个可应用方案；
- 云端：版本冲突、幂等、权限、活动流、资源版本、遥测/质量和跨 workspace 隔离；
- 资产：36 个 ForgeCore 默认物品位与生成器/许可证审计；
- 工程：Python 语法、Maven 测试/打包、前端生产构建、`git diff --check`。

### 第 36 页｜当前验证结果、性能与故障降级

**最新可展示结果（2026-09-03）**：

- 智能助手协议：26/26 通过；
- 真实 Qwen `qwen2.5:7b` 评测：8/8，得分 1.00；
- 前端生产构建：4795 modules 通过；
- WZH 正式存档：39 个对象，固定种子运行 600 秒消耗 196 件钢制毛坯、交付 58 件已检成品，Agent 审计 0 个阻塞性问题；
- 服务端：Maven 测试/打包、Flyway/MySQL 迁移和 Agent/提醒/云端回归按对应门禁通过。

**性能和降级**：模型预热、实例化、demand loop、阴影缓存、DPR/可见性预算和 FPS/P95/draw call 监控；后端离线继续本地仿真，AI 离线回退规则，TTS 回退浏览器朗读/Sherpa VITS，GLB 失败回退程序化模型，并明确显示本地/演示状态。

### 第 37 页｜当前边界与后续路线

**必须如实说明**：

- 生产效率、OEE 等没有现场数据时只是确定性仿真证据，不是现场实测；
- Spring Boot 保存结构、版本和审计，不是实时仿真服务器；
- 多输出复杂配方、视觉检测的 LLM 解读、手柄全流程仍需增强；
- Unity 桌面端尚未完成真实登录存档全对象视觉核验、端口/标签完整交互回传和 S-03 性能门禁；
- ForgeCloud 尚未完成真实 OPC UA/MQTT、设备控制执行器、专业时序引擎、MinIO/S3 和远程模型路由；
- ForgeHub 公共资源市场、完整生产级限流/角色体系和移动端生产离线队列仍在路线图；
- Agent Patch 不自动应用，自动巡检不写存档。

### 第 38 页｜项目创新点与结束语

**创新点**：

1. 工厂不仅能被看见，还能被运行；
2. 仿真采用固定步长和可复现随机数；
3. AI/Agent 必须服从工具白名单、确定性验证和人工审批；
4. 物流、机器人、视觉、仓储和质量处于同一工厂闭环；
5. 宝钗负责呈现，黛玉负责推理，ForgeCloud 负责跨产品版本与协作；
6. 用户可以导入私有工业模型，并保留许可证和版本边界；
7. 规则优先使系统在没有 AI 服务时仍可运行。

**结束语**：

> ForgeMind 让工厂从“被展示的三维模型”，变成“可以被设计、运行、理解、验证和优化的数字系统”。

## 5. 现场演示脚本

建议现场演示按以下顺序执行，主链控制在 5–8 分钟：

1. 登录并进入工厂；
2. 在建造页放置 Source、输送线和 Machine；
3. 创建或绑定物品和配方；
4. 启动仿真，展示物料流动；
5. 制造下游阻塞，展示背压；
6. 打开诊断页，查看瓶颈；
7. 开启一次自动巡检，展示证据、趋势或主动提醒；
8. 切换到 A-02，输入生产需求；
9. 展示 Recipe Graph、设备估算、3 类候选和 What-if；
10. 展示 AGV 或无人机运输；
11. 打开 Factory Agent，展示 Finding → Patch 草案 → 校验 → 人工审批，不实际冒险修改；
12. 用默认规则助手查询状态或调整仿真倍率；若现场已显式启用 Qwen，再补充自然语言理解；
13. 视时间展示视觉检测 PASS / FAIL、ForgeCloud 版本账本或 ForgeMove 移动摘要；
14. 回到架构图总结“确定性事实源 + 受控 AI + 生态协作”三条边界。

**演示前准备**：优先使用 WZH 三层轻量完整产线存档；预先确认后端/数据库是否可用、助手是否处于 `rule`、语音设备是否可用。AI、语音、云端或 Unity 任一项不可用时，直接切换到规则回答、本地存档、WebGL 或截图，不把降级状态伪装成成功。

## 6. 答辩表述红线

- 不要说 Spring Boot 是实时仿真服务器；
- 不要把固定种子仿真读数称为现场 OEE 或真实产能；
- 不要把所有工业机器人模型都称为完整运动学仿真；
- 不要把 A-01 的候选数、A-02 的回归结果外推成所有工厂都稳定通过；
- 不要说 LLM/Agent 可以直接修改工厂；Patch 必须经过服务端校验和人工审批；
- 不要说 Ollama/Qwen 是默认启动依赖，也不要把未来的 Redis、Kafka、专业时序引擎或设备执行器说成当前依赖；
- 不要把 Unity 当前投影和空场景性能写成三维全量等价或正式 500+/120 FPS 验收；
- 不要忽略用户资源和 GLB 模型的许可证边界；
- 不要把 ForgeHub 公共市场、真实工业协议、设备控制执行器和移动端生产离线队列描述成已完成；
- 不要把视觉检测的后续增强描述成已经完全闭环。

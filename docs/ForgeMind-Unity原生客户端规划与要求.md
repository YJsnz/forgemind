# ForgeMind Unity 原生客户端规划与要求

> 文档状态：2026-08-31。当前执行方案见 `ForgeMind-Unity客户端-重建计划.md`：WebView2 继续承载原 React 工作台，Unity 只替换中心三维渲染表面；命名管道仅作为 WebView2 与 Unity 的本机渲染桥，不承载业务事实。
> 更新时间：2026-08-31  
> 适用范围：Windows 原生高性能客户端；不包含 Unity WebGL 版本

## 1. 文档定位

本文是 ForgeMind Windows 混合客户端的立项和开发约束。它明确产品边界、WebView2 宿主、Unity 三维渲染桥接、数据契约、性能门禁、资产规则、Web 全功能保真范围和阶段交付。

本文是规划要求和当前构建门禁。现有 Web 已有完整业务实现；Unity U1 基准 Player、最终混合 Player 和 WebView2 宿主源码均已可重建，当前仍需真实存档视觉验收和性能门禁。最终目标是保留当前 Web 工作台全部能力，只替换 WebGL 三维画布，而不是再维护一套功能相似但会分叉的原生业务界面。

### 1.1 当前构建状态（2026-08-31）

- 已创建 `unity-client/` Tuanjie/Unity 工程骨架，包含运行时与编辑器程序集、FactorySave/SimulationSnapshot DTO、后端 API 占位边界、只读快照运行时、16 项 Web 功能覆盖目录、性能采集器和 U1 基准场景生成器。
- 当前本机实际编辑器为 Tuanjie `2022.3.62t13`，产品标识属于 Tuanjie 1.10 系列；已完成许可证激活、Package Manager 解析、场景生成、GLB 导入和 U1 Windows Player 构建。
- 首次批处理尝试曾被 `No valid Unity Editor license found` 阻断；随后 Tuanjie Personal 授权成功，工程实际完成脚本编译。U1 Player 无界面烟测使用 `-nographics` 时会强制 Null GPU，只能证明程序集/启动链路可加载，不能作为画质或 FPS 证据。
- GLB 导入当前锁定 `com.unity.cloud.gltfast` `6.16.1`；8/8 白名单模型由 `GLTFast.Editor.GltfImporter` 接管，主资源类型为 `UnityEngine.GameObject`。
- 原生调试壳已接入 `/api/auth`、`/api/factories`，支持登录/注册、会话令牌保存、项目刷新、项目打开、退出登录和只读存档载入；该壳只用于 U1 调试，最终业务 UI 不从 Web 迁移到 IMGUI。
- 已完成标准 WebView2 Controller + Unity 裁剪子窗口宿主、桌面 Web dist 加载、视口定位、Unity 启停、对象选择输入和 `forgemind.unity.bridge.v1` 命名管道桥接；混合启动时 Unity 原生调试壳与性能叠加层自动关闭，登录页保持原 Web 工作台原样。
- 已增加可重复的 Windows 安装包构建脚本，包含 Web dist、Unity Player、WebView2 loader、后端和安装脚本；当前轮已单独重建最终 Player 与宿主，未把安装包或真实存档视觉验收写成正式通过。
- 下一步是以 Web 端现有回归夹具逐项完成桌面 WebView2 功能验收，再用真实 GPU 完成原始高模、空间分区和 CPU/GPU 帧时间实测；Unity 不另起一套业务 UI。

## 2. 产品定位与边界

### 2.1 客户端定位

Unity 客户端是 ForgeMind 面向 Windows 的原生三维工作台，主要解决浏览器 WebGL 在大规模精细模型、显存管理、原生 GPU API 和本地资源流送方面的上限问题。

浏览器 Web 端继续保持现有完整工作台；Windows 客户端使用 WebView2 加载同一套 React 页面和业务代码，负责官网、认证、编辑、生产资料、物流、仿真、诊断、Agent、视觉检测、AI/语音等全部 Web 功能。Unity 作为独立原生渲染进程，仅负责 500+ 精细工业模型、高质量多楼层运行态、GPU 资源管理、异步加载和原生性能诊断。Web 页面不应被原生 IMGUI 或另一套业务菜单替代。

### 2.2 明确不做

- 不做 Unity WebGL 二次版本；
- 不在 Unity 中复制一套未经验证的物料守恒、碰撞、寻路或布局规则；
- 不让大语言模型直接决定坐标、数量、库存、碰撞、寻路或仿真指标；
- 不把 CUDA/cuDNN 当作 Unity 渲染的必需依赖；
- 不用彩色方块、不可识别的低模或无关占位物替代当前可见精细模型；
- 不在第一阶段接入 PLC 写入、自动控机或未经审批的生产指令；
- 不为了追求平均 FPS 隐藏帧时间尖峰、加载卡顿或显存溢出。

## 3. 第一阶段目标与最终覆盖范围

第一阶段先做“Web 原样运行、Unity 可接管 3D、可连接、可测量”的混合客户端，采用分阶段实现降低风险；这只是交付顺序，不是最终能力裁剪。最终发布必须覆盖本节的全部 Web 功能矩阵，覆盖来源是同一套 Web 页面和业务代码，而不是复制实现。

### 3.1 P0 必须交付

1. Windows x64 可启动程序，能够连接开发环境 ForgeMind 后端。
2. 登录、项目列表、项目打开和退出登录。
3. 读取当前工厂存档，正确显示楼层、设备、传送带、仓储、AGV、无人机和用户导入模型。
4. 当前楼层、只读上下文楼层、镜头轨道、缩放、平移、旋转和对象选择。
5. 读取仿真快照，显示物料、机器状态、AGV/无人机位置和核心运行指标。
6. 500+ 精细模型压力场景、固定镜头集和自动化性能采集。
7. 原生客户端日志、渲染统计、CPU/GPU 帧时间和显存/资源统计。
8. 不改变正式存档的只读模式和异常断线恢复。

### 3.2 P1 交付

- 建造、移动、旋转、删除和多选；
- 物品、配方、生产路线、机械制造和仓储工作区；
- 仿真启动、暂停、倍率、重置和快照刷新；
- AGV/无人机三节点运输任务编辑；
- 诊断、自动巡检、生成式方案和 Agent 运行历史只读查看；
- Patch 预览、人工审批、应用、回滚和版本冲突提示。

### 3.3 P2 交付

- 官网门户、产品介绍、官方文档和 ForgeHub 预留入口；
- 与 Web 端一致的完整工作台布局、快捷键和助手球交互；
- 离线只读缓存、资源包预缓存和大项目断点加载；
- 真实数据只读适配、事件回放和质量/维护信息展示；
- 原生客户端自动更新和崩溃诊断上报。

P1/P2 未全部完成前，不能把 Unity 客户端称为 Web 工作台的完整替代品。正式发布必须通过第 3.4 节全功能矩阵和第 11 节验收清单。

### 3.4 Web 全功能覆盖矩阵

Windows 客户端必须覆盖下表能力。“覆盖”指 WebView2 中运行同一套 Web 页面，功能行为、数据字段、权限、错误处理和业务结果与浏览器一致；页面 UI 不重写。只有 WebGL 三维画布由 Unity 原生渲染表面替换，若 Unity 不可用则必须保留 WebGL 回退并显示明确状态。

| Web 能力 | Unity 必须覆盖的内容 | 一致性要求 |
| --- | --- | --- |
| 官网门户 | 产品介绍、官方文档、ForgeHub 预留入口、Emotion Ball/助手视觉入口 | 可作为原生启动页或工作台入口，不丢失导航能力 |
| 认证与项目 | 注册/登录、退出、会话过期、项目列表、新建空白工厂、打开/保存/切换项目 | 用户隔离、权限和项目版本一致 |
| 工厂编辑 | 网格、放置、旋转、移动、删除、多选、撤销/重做、碰撞和边界校验 | 坐标、占地、旋转、失败原因和存档结果一致 |
| 多楼层 | 楼层命名、增加/切换楼层、当前层编辑、上下文层只读、跨层高度 | 楼层可见性、对象归属和空间关系一致 |
| 生产资料 | 物品详情、配方、生产路线、机械制造、货物仓储三项工作区 | CRUD 字段、引用关系和校验一致 |
| 工业物流 | 传送带拖绘、转弯、分流、汇流、存取站、货架吸附和端口标识 | 端口拓扑、方向、接缝、占地和连接语义一致 |
| 仿真运行 | 启动、暂停、重置、倍率、物料、机器状态、产出、消耗、利用率和阻塞 | 固定步长、物料守恒、背压和指标不能因客户端改变 |
| AGV | 三节点任务、供料方式、阈值、策略、优先级、导航、避让和重规划 | 车辆实体、库存扣减、路径和阻塞语义一致 |
| 无人机 | 跨层三维路线、三节点任务、库存运输、选择和运行状态 | 26 邻域路径、跨层标高、装卸和库存语义一致 |
| 诊断 Agent | 只读分析、方案设计、工具活动、Finding、历史运行、拒绝后 replan | 服务端权限、SSE、工具结果和审计一致 |
| 自动巡检 | 固定证据副本、趋势预警、瓶颈/能耗归因、定时巡检、中文报告和可选语音 | 规则结论、报告数字和 AI 失败回退一致 |
| 生成式工厂 | 候选生成、节能/平衡/高吞吐差异、布局校验、副本仿真、What-if 和应用 | 候选数量、校验、指标和人工审批一致 |
| Patch 闭环 | 预览、审批、应用、回滚、版本冲突和操作历史 | 不得绕过后端校验或直接改数据库 |
| 资源导入 | JSON/GLB 导入、字段校验、模型预览、封面、用户持久化和再次加载 | 资源归属、许可证、尺寸、端口和模型引用一致 |
| 视觉检测 | PCB Demo、视频播放、YOLO 推理状态、检测框、置信度、耗时和离线状态 | AI 服务可选；服务不可用时仍有明确降级状态 |
| AI 管家与语音 | 工具白名单、二次确认、ASR/TTS、助手状态和失败回退 | AI 不得成为前端启动门禁或事实源 |

正式发布的 Unity 客户端必须以这张矩阵为逐项签字表。任何一项暂未迁移，都必须在启动页标注“功能迁移中”，不能静默隐藏入口。

## 4. 总体架构

```text
┌─────────────────────────────────────────────┐
│ Windows Hybrid Client                        │
│ WebView2: unchanged React UI/business logic  │
│ Unity: native 3D render surface only         │
│ Host: window composition + versioned bridge  │
└───────────────┬───────────────┬─────────────┘
                │ HTTPS / SSE    │ local bridge
┌─────────────────────┼───────────────────────┐
│ ForgeMind Backend                           │
│ Auth · Projects · FactorySave · Agent/Patch │
│ MySQL · Version · Permission · Audit        │
└─────────────────────┼───────────────────────┘
                      │
          Simulation Snapshot / Evidence API
```

`*` 具体实时通道沿用当前已验证的接口；若新增 WebSocket，必须先定义协议并保留 SSE/轮询降级，不得让客户端私自读取数据库。

### 4.1 事实源原则

| 数据 | 权威来源 | Unity 职责 |
| --- | --- | --- |
| 用户、权限、项目归属 | Spring Boot/MySQL | 登录、令牌管理和权限错误展示 |
| 工厂结构、楼层、设备、物品、配方 | `FactorySave` / 后端项目接口 | 解析、缓存、版本校验和显示 |
| 物料守恒、端口拓扑、碰撞、寻路、仿真指标 | 当前确定性仿真契约 | 展示快照；迁移内核必须通过黄金用例 |
| Agent Finding、Patch、审批、回滚 | `/api/agent/**` 和后端审计 | 展示、确认和发起受权限保护的动作 |
| 模型来源、许可、缩放和锚点 | 资产审计与资产注册表 | 按注册表加载，不擅自替换来源 |
| 帧时间、显存、Draw Call | Unity 本地运行时 | 采集和报告，不写入业务存档 |

Web 页面继续拥有 API/SSE/业务状态；Unity 只接收渲染所需的只读场景投影和表现层命令。宿主桥接层不得把 token、数据库凭据或服务端事实转发给不必要的进程。Unity 的本地缓存可以保存模型包和最近渲染索引，但不能绕过服务端权限，也不能把本地预测覆盖成正式业务事实。

### 4.2 仿真迁移要求

当前项目的业务仿真事实源是 `src/game/simulation.ts`，而 Unity 使用 C#。在后端仿真服务尚未建立前，按以下顺序推进：

1. 第一阶段使用录制的 `SimulationSnapshot` 和固定测试夹具验证渲染，不在 Unity 里新写业务规则。
2. 第二阶段定义与 TypeScript 引擎等价的快照协议和黄金用例，覆盖闭环、转弯、分流、汇流、头堵、跨层、仓储和车辆。
3. 若需要 Unity 本地预览，C# 仿真只能作为经过黄金用例验证的镜像，且不得直接写正式存档。
4. 需要多人、长时间运行或正式产能结论时，仿真应迁移为可版本化的服务端/共享内核；客户端只提交控制意图和读取结果。
5. 每次仿真规则、存档版本或快照协议变化，必须同时更新实现及逐字段回归证据。

## 5. Unity 技术要求

### 5.1 版本和平台

- 当前 U0/U1 基线锁定本机 Tuanjie `2022.3.62t13`（产品标识为 Tuanjie 1.10 系列）；未经 S-01/S-02/S-03 基准回归不得升级或切换到其他 Unity/Tuanjie 版本。
- 首发平台为 Windows 10/11 x64，优先支持 DirectX 12，保留 Vulkan 回退；不以 OpenGL 作为性能基线。
- 图形管线优先评估 URP；只有经过真实画质和性能对比且确有必要时才引入 HDRP。
- 采用 IL2CPP、Release 构建、64 位地址空间和独立 Player 配置；Editor 性能不能作为交付指标。
- 目标显卡型号、驱动版本、显示器刷新率、分辨率和 Windows 电源模式必须写入每次性能报告。

### 5.2 推荐渲染路径

按“先基准、后启用”的原则评估：

1. SRP Batcher、GPU Instancing 和共享材质；
2. GPU Resident Drawer / BatchRendererGroup，用于兼容的静态重复对象；
3. 视锥裁剪、空间分区和按楼层可见性裁剪；
4. GPU Occlusion Culling，只在运行时收益大于 CPU/内存成本的场景启用；
5. Addressables 或等价的异步资源流送、预加载和卸载；
6. Jobs/Burst 处理资源索引、可见性、变换和非业务性的批量计算；
7. 原生 Profiler、Frame Debugger、RenderDoc 或 PIX 进行 CPU/GPU 分段测量。

这些机制是候选技术，不代表全部默认打开。每项优化必须有开关、前后数据和画质回归；不得把兼容性问题藏在“自动优化”里。

### 5.3 模型细节要求

- 原始 GLB/工业模型是优先资产来源，保留几何、材质、纹理、法线、动画和授权信息。
- U1 使用 `com.unity.cloud.gltfast` `6.16.1` 作为 GLB 编辑器/运行时导入器；升级导入器前必须重新验证 8 个白名单模型的主资源类型、包围盒、材质、纹理和动画。
- 所有模型进入 Unity 前必须登记 `assetId`、来源、许可证、修改声明、尺寸、原点、朝向、包围盒和目标缩放。
- 当前编辑楼层、近景对象、选中对象、故障定位对象和机械臂作业区域默认使用最高可用细节。
- LOD 只允许用于远景或像素贡献确实不可见的对象，且必须通过截图/像素差异和资产审计；不得用色块代理冒充 LOD。
- 不允许为了合批破坏原材质差异。只有相同材质、相同着色器参数和相同光照语义的对象才能合批。
- 设备、传送带、货物、AGV、无人机、端口标识和状态动画必须保持当前 WebGL 的空间语义和可识别性。
- 资产加载失败必须显示明确的资产错误状态，并保留对象 ID；不能静默替换成无关的占位物。

### 5.4 场景组织

Unity 渲染进程分为四层，业务 UI 不在 Unity 内：

1. `WebProjection`：只保存 WebView2 桥接传入的存档/快照结构化投影，不直接持有 Unity GameObject。
2. `FactorySpatialIndex`：按楼层和空间单元索引对象，服务于可见性、选择和局部刷新。
3. `FactoryRenderWorld`：管理静态模型批次、动态载具、物料池、端口标识和状态表现。
4. `NativeSurface`：管理 Unity 原生窗口、相机输入、视口尺寸、焦点和渲染统计；顶部、侧栏、工作区、指标、诊断、审批和助手球继续由 WebView2 绘制。

静态设备、直线传送带和重复货物优先使用实例化或批处理；AGV、无人机、机械臂和在途物料使用独立的动态更新路径。仿真快照刷新不得销毁并重建整个场景。

## 6. 性能预算与验收门禁

### 6.1 场景基准

必须建立三套固定基准，所有 WebGL/Unity 对比使用同一模型包、同一存档、同一镜头和同一仿真状态：

| 基准 | 内容 | 用途 |
| --- | --- | --- |
| S-01 | 39 对象、三层轻量完整产线 | 日常功能和低延迟启动 |
| S-02 | 178 对象、多个设备类型和在途物流 | 中型稳定性与交互 |
| S-03 | 500+ 原始精细模型、三层、物流和动态状态 | GPU/CPU/显存极限和 120 FPS 目标 |

S-03 不允许通过减少对象、替换模型、关闭关键细节或只测空场景来达标。基准包必须记录模型总三角形、材质数、纹理尺寸、动画数和显存估算。

### 6.2 目标帧时间

120 FPS 对应单帧预算约 `8.33ms`。正式验收必须同时记录 CPU 和 GPU frame time，不能只看平均 FPS。

建议门禁：

- 120 FPS 目标档：S-03 固定镜头 60 秒，平均 FPS ≥120，P95 帧时间 ≤8.33ms，P99 ≤12ms；
- 120 FPS 目标档：S-03 镜头平移、旋转、缩放各 30 秒，平均 FPS ≥100，不能出现持续性卡顿或资源加载阻塞；
- 60 FPS 兼容档：S-03 固定镜头和操作镜头平均 FPS ≥60，P95 帧时间 ≤16.67ms；
- 启动：分别记录启动到可交互首屏、项目打开到第一帧、项目打开到首层资源可用；
- 交互：选择、楼层切换、打开详情和暂停仿真不能触发整场景销毁重建；
- 资源：连续切换楼层和项目不得无界增长显存、GameObject、Native 内存或加载线程队列。

若目标设备显示器刷新率低于 120Hz，仍可测量渲染 frame time，但必须使用离屏或高刷新测试环境记录 120 FPS 能力，不能把显示器刷新率当作引擎性能结果。

### 6.3 画质门禁

每次性能优化必须与基线截图或录屏对比：

- 当前楼层近景设备轮廓、材质、纹理和阴影不能出现未经批准的明显退化；
- 选中对象、端口、物料、机械臂、传送带运动和设备状态灯不能消失或跳变；
- 多楼层上下文建筑不能漂浮、错层或穿透楼板；
- 传送带接缝、跨层坡道、货物路径和 AGV/无人机位置必须与存档/快照一致；
- 关闭/开启性能档位只改变已登记的采样、阴影、裁剪或资源调度，不改变业务结果。

## 7. 数据、接口与版本要求

### 7.1 客户端协议适配层

Unity 不直接在 UI 中拼接接口，必须分为 UI View、Application Service、ForgeMind API Client 三层。API 适配层统一处理令牌刷新、项目版本、存档指纹、JSON `schemaVersion`、SSE/实时快照断线重连、重复消息、错误码、超时、取消、重试和幂等键。

### 7.2 快照最小字段

快照协议至少包含：

`schemaVersion`、`projectId`、`projectVersion`、`seed`、`simTime`、`running`、`objects`、`itemLots`、`machines`、`agvs`、`drones`、`racks`、`metrics`。

运行快照中的每个动态实体必须带稳定 `id`，物料跨传送带时保持同一 ID。Unity 表现层可以插值，但不能把插值位置回写成仿真事实，也不能在断线时凭空生成或删除货物。

### 7.3 Agent 与 Patch

- Unity 只调用现有 Agent 服务和 Patch 审批链路；
- Patch 必须携带基线版本、操作摘要、校验结果和逆向操作；
- 应用前由服务端做权限、归属、状态、版本、幂等、碰撞、端口和业务校验；
- Unity 展示 Finding、方案、分支指标和审批按钮，但不能绕过审批直接改库；
- 应用或回滚成功后，以服务端返回的完整新存档重建渲染数据；
- 离线状态下允许查看缓存和历史，不允许应用 Patch。

## 8. 交互和 UI 要求

### 8.1 第一阶段交互

- 鼠标左键选择，右键平移，滚轮缩放，中键/约定手势旋转；
- 当前楼层可编辑，其他已开启楼层只读显示；
- 设备、传送带、物料、AGV、无人机和仓储对象均保留稳定 ID 选择；
- 详情窗口打开时必须有明确层级，不被 3D 标签穿透；
- 加载、重连、快照延迟、资源缺失和版本冲突必须有可见状态；
- 快捷键与 Web 端语义一致，但不能在文本输入控件中误触发删除或旋转。

### 8.2 Web UI 与 Unity 渲染边界

最终客户端必须使用 WebView2 承载现有 Web 页面，不得在 Unity 中重写顶部、侧栏、工作区、诊断、审批和助手球等业务 UI。宿主负责 WebView2 与 Unity 原生窗口/渲染表面的布局、焦点和生命周期；Unity 只接收版本化场景投影，回传选择、镜头和渲染状态。WebView2 不可用时，客户端可以进入 U1 调试壳，但不得把调试壳标记为功能完成。

当前 ForgeMind 的顶部工厂状态、左侧需求/建造、中心三维工厂、右侧运行状态、底部工作区和 BT-7274 助手球是交互参考，但 Unity 版本可以按原生窗口尺寸重新排版，不得牺牲核心流程和信息层级。

## 9. 安全、许可和运维

- 令牌放入 Windows Credential Manager 或等价安全存储，不写明文日志；
- HTTPS 证书校验不能被普通配置关闭；开发环境允许显式开发开关，但发布包必须关闭；
- 服务器密钥、AI 密钥、数据库凭据和模型服务凭据不得进入 Unity 包；
- 每个请求带客户端版本、协议版本和可追踪请求 ID；
- 崩溃日志默认脱敏，不上传项目内容、货物数据或个人信息，除非用户明确同意；
- 工业、公模、ForgeCore、用户私有模型继续分开管理；Unity 导入不能改变许可归属；
- Cels AGV 和 Count Infinity 无人机的 CC BY 4.0 署名、来源链接和修改声明必须进入客户端关于/资产信息页或随包许可文件；
- 未确认许可的工业 GLB 不得在客户端文档中声明为 ForgeMind 原创或可自由商用。

## 10. 开发阶段和交付物

### 阶段 U0：基线和工程锁定

交付 Unity LTS 版本决策、目标设备矩阵、S-01/S-02/S-03 基准包、接口清单、资产注册表和性能采集模板。

退出条件：WebGL 与基准场景的对象、模型、材质、坐标和楼层语义逐项对齐；目标显卡和显示器信息已确认。

### 阶段 U1：原生渲染 Spike

交付独立 Unity 工程、单楼层高模场景、基于 glTFast 的 GLB 导入、材质校验、空间分区、静态批处理、GPU/CPU 计时和显存统计。

退出条件：完成普通 GameObject、GPU Instancing、GPU Resident Drawer/BatchRendererGroup 候选三组对比，保留数据和截图。

### 阶段 U2：只读工厂浏览器

交付登录、项目列表、FactorySave 解析、多楼层浏览、对象选择、相机、资源异步加载和只读快照回放。

退出条件：S-01/S-02 功能流程通过；网络断开、资源缺失、旧版本存档和权限错误均有明确处理。

### 阶段 U3：运行态和性能工程

交付物料/设备/车辆运行表现、对象池、快照插值、可见性裁剪、阴影策略、性能档位、固定镜头压测和自动报告。

退出条件：S-03 500+ 精细模型不使用彩色代理；CPU/GPU/显存瓶颈有证据；120 FPS 是否达标由报告决定。

### 阶段 U4：Web 全功能与 Unity 渲染联调

交付 WebView2 中现有建造、路线、物品、仓储、AGV/无人机和仿真控制的完整运行；Unity 只完成对应场景投影、选择回传、楼层/镜头同步和原生渲染表面联调，写入动作统一经过 Web 端和服务端存档版本门禁。

退出条件：WebView2 页面与浏览器端核心回归夹具一致，Unity 桥接不改变仿真结果，Unity 不可用时 WebGL 可恢复。

### 阶段 U5：智能诊断与发布

交付官网门户、完整 Web 功能矩阵、Agent、自动巡检、生成式方案、视觉检测、AI 管家/语音、Patch 审批/应用/回滚、安装包、自动更新、崩溃上报和发布验收报告。

退出条件：第 3.4 节每一项 Web 能力均在 WebView2 中可用并有浏览器/桌面回归证据；3D 场景投影、选择和渲染状态有 Unity 回归证据；所有智能动作仍可解释、可验证、可审批、可回滚；发布包通过安全、许可、性能、存档兼容和 WebGL 降级验收。只有此时混合客户端才能作为 Web 工作台的正式桌面版本。

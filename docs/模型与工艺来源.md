# ForgeMind 模型与工艺来源

> 更新时间：2026-08-19。本文同时记录两类模型：仓库内置/公模资产，以及用户在建造页导入的私有 GLB。用户资源不会写入 `public/models/`，而是经资源包校验后进入 Spring Boot 的 `imported_resource`，按用户恢复。

## 工艺体系

当前演示链路以离散机械制造为基线：

```text
原料来料站
  → 原料仓储架 / AGV 线边搬运
  → 数控加工中心
  → 清洗去毛刺单元
  → 液压冲压机
  → 机器人装配单元
  → 机器视觉检测站
  → 成品缓存仓
```

这套链路对应真实工厂里的来料、仓储、机加工、表面处理、成型、装配、质量检验和成品入库，不再采用“矿石—熔炼—升级”的游戏化资源循环。

## 本地模型资产

本项目当前接入的高细节 GLB 资产来自公开的 realvirtual WEB 示例模型包，用于本地教学和答辩演示：

- `public/models/industrial_line_demo.glb`：真实工业产线参考源文件，已拆分为建造栏使用的独立设备资产；不再作为页面默认场景显示。
- `public/models/robot_irb2400.glb`：IRB 2400 六轴工业机器人，用于机器人装配单元与通用工艺工作站。
- `public/models/forklift_agv.glb`：叉车/AGV 物流模型，用于厂内托盘搬运展示。
- `public/models/assembly_fixture.glb`：装配夹具参考模型，作为后续夹具与工装细化的基础资产。

中心产线已按节点拆分为独立 GLB，拆分清单位于 `public/models/industrial/manifest.json`：

- `cnc_machining_center.glb`：数控加工中心本体、刀库、屏幕和运动部件。
- `robot_cell.glb`：工业机器人与机器人底座。
- `safety_fence.glb`：安全围栏、安全门和门把手。
- `roller_conveyor.glb`：进料/出料滚筒输送线，保留皮带、滚筒、电机和支脚。
- `roller_conveyor_segment.glb`：原中心拆分的单段滚筒输送线，保留作回退资产。
- `realvirtual_roll_conveyor_1m.glb`：从 realvirtual 公共模型库导入的高精度 1m 滚筒输送线，作为备用资产保留。
- `realvirtual_turntable.glb`：从同一模型库导入的高精度转台，作为备用资产保留。
- `realvirtual_high_detail.glb`：42.7MB 的单网格 CAD/PBR 高精度模型，当前映射为通用工艺工作站。
- `control_cabinet.glb`：立式控制柜与按钮组件。
- `sensor_pack.glb`：进出口传感器组件。

拆分脚本：`scripts/split-industrial-glb.mjs`。脚本按原 GLB 的节点树提取网格、材质、纹理和二进制缓冲区，不做重新建模；因此拆分后的设备仍保持原始精度和比例。

建造栏映射：

- “基础加工 / 数控加工中心” → `cnc_machining_center.glb`
- “基础加工 / 通用工艺工作站” → `realvirtual_high_detail.glb`
- “精密装配 / 机器人装配单元” → `robot_cell.glb` + `safety_fence.glb`
- “精密装配 / 机器视觉检测站” → `sensor_pack.glb` + `control_cabinet.glb`
- “物流仓储 / 滚筒输送线” → `roller_conveyor_segment.glb`

左侧建造卡片会将这些设备标记为“中心拆分资产”，详情面板会显示对应的 GLB 路径；液压冲压、清洗去毛刺、原料货架、成品缓存仓等中心模型没有对应节点的设备，会标记为“工艺结构模型”。

当前比例基准：1 个建造网格 = 1 m；单段输送线、分流器和汇流节点均按 1×1 网格处理，避免物流设备相对加工中心出现异常放大或缩小。

## 用户资源包接入

建造页支持 `.forgemind-project.json`/兼容 JSON 与 `.glb` 成对导入，入口为 `ResourceImportDialog`。导入时会：

1. 校验资源 ID、设备类别、占地、尺寸、端口和模型引用；
2. 读取 GLB 并按包围盒居中、底面归零和设备足迹做预览归一化；
3. 用预览视角生成设备卡片封面；
4. 登录后将元数据、项目 JSON 和 GLB 保存到当前用户资源目录；
5. 把设备以 `type=imported`、`resourceId=<用户资源 ID>` 注册到建造目录和工厂存档。

Spring Boot 保存工厂时会再次校验 `resourceId` 的用户归属，因此同一资源 ID 在不同用户之间不会互相可见或可引用。完整接口、字段和迁移见 [当前实现总览](ForgeMind-当前实现总览.md) 与 [后端数据库设计](ForgeMind-后端数据库设计.md)。

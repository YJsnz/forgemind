# ForgeMind 模块用户文档

> 版本：2026-09-02 · 适用 BUILD 0.1.0 / 存档 v6
>
> 本文只说明 ForgeMind 主工作台模块的实际使用方式。生态产品的独立入口见 ForgeCloud、ForgeHub、ForgeLab、ForgeMove 和 ForgePass 用户文档。

## 1. 模块定位

ForgeMind 是 Forge 生态的三维工厂设计、生产配置、确定性仿真和诊断工作台。它适合在方案落地前搭建产线、验证物料流、检查库存和发现结构问题。

ForgeMind 的事实边界是：布局、碰撞、寻路、物料数量和仿真指标由本地确定性规则计算；AI 只能作为可选解释或方案辅助，不能替代这些结论。

## 2. 进入模块

1. 打开 ForgeMind 官网，点击“进入工作台”或从 ForgePass 登录后选择 ForgeMind。
2. 登录后在“开始你的工厂”弹窗中选择“新建空白工厂”或打开已有项目。
3. 需要云端保存时保持 Spring Boot 和 MySQL 在线；只做本地编辑、演示或导入时可以使用前端模式。

## 3. 主工作区

| 入口 | 用途 |
| --- | --- |
| 总览 | 查看工厂状态、KPI、库存和辅助工作区 |
| 建造 | 放置设备、仓储、车辆和传送带 |
| 生产 | 查看产线、设备状态、物料流和产出 |
| 诊断 | 使用 Agent、自动巡检和生成式规划 |
| 生产资料 | 管理机器、物品、配方和仓储资料 |

总览页的辅助入口包括机械制造、生产路线、物品详情和仓储控制。打开某个工作区时，其他隐藏面板不会继续接收建造快捷键。

## 4. 推荐使用流程

### 4.1 先建资料，再摆设备

1. 在“物品详情”建立原料、半成品和成品。
2. 在“生产路线”建立输入、输出和加工时长。
3. 在“机械制造”建立机器并绑定生产路线。
4. 回到“建造”放置设备、仓储和传送带。

### 4.2 再运行和检查

1. 为入货仓库设置真实库存，为普通货架设置容量和库存。
2. 将传送带端口与设备输入/输出方向对齐。
3. 运行仿真，观察设备是否加工、线路是否堵塞、物料是否到达出货仓库。
4. 在“生产”或“总览”检查消耗、产出、在途批次和设备利用率。

### 4.3 最后诊断和保存

诊断页先运行只读分析，再根据 Finding 生成 Patch。需要修改存档时必须人工审批；应用后可以继续复核或回滚。确认结果后使用“手动保存存档”或项目弹窗保存版本。

## 5. 建造与楼层

- 建造模式支持鼠标放置、旋转、拖绘传送带和 Esc 取消。
- 传送带拖绘会补齐连续格、识别转角，并在合法方向吸附设备端口。
- L1、L2、L3 是独立高度的楼层；当前编辑层可修改，其他开启楼层只作为只读上下文显示。
- 设备不能越过边界，也不能与其他对象占用格重叠。
- 跨层传送使用倾斜传送带或无人机，不要把普通平面传送带当作升降线路。

## 6. 仓储和车辆

- 入货仓库是供料边界，会记录实际取出和消耗。
- 出货仓库是交付边界，会记录实际入库和产出。
- 普通货架有有限容量；缺货时运输任务等待，不会自动半载或凭空补货。
- AGV 使用同层八方向寻路，可设置起点、终点、物品、每趟数量和库存阈值。
- 无人机支持跨楼层运输，使用三维路径；暂停仿真时运输进度也暂停。

## 7. 诊断工具怎么选

| 需要回答的问题 | 使用入口 |
| --- | --- |
| 哪个端口、碰撞或线路断开 | Agent 结构诊断 |
| 最近运行窗口是否劣化 | 自动巡检 |
| 目标产能下怎样重排 | 生成式工厂 |
| 某个方案会不会提高产出 | What-if 副本仿真 |

诊断结论需要结合运行证据。没有足够样本时，系统会降低置信度或提示继续观察。

## 8. 保存与排障

手动保存的是工厂结构、资料和可恢复配置，不是每一帧运行坐标。遇到登录失败先检查 8080；遇到物料不动先检查物品、配方、端口方向和下游容量；遇到导入失败先确认 JSON/GLB 格式与资源归属。

ForgeMind 不直接控制现场设备。需要移动端查看任务、库存或社区内容时使用 ForgeMove；需要共享资源和经验时使用 ForgeLab。

## 1. 范围与权威性声明

这些图片仅作为 UI 美术风格和视觉方向的大致参考，不是高置信度的真实 UI 设计稿，也不是产品需求、页面结构或交互逻辑的事实来源。

可以严格参考的内容包括：

- 色彩倾向与明暗氛围；
- 材质、光影、纹理和视觉层次；
- 面板、边框、圆角、装饰和图标语言；
- 字体气质、信息密度和整体视觉节奏；
- 状态反馈的美术表现方式。

不得仅凭参考图片推断或照搬：

- 信息架构和页面布局；
- 功能入口、业务流程和数据结构；
- 字段名称、文案和真实业务状态；
- 交互逻辑、导航关系和权限设计；
- 精确尺寸、断点或设备适配方案。

实际 UI 设计必须以项目需求、业务逻辑、信息层级、可访问性、响应式要求和技术约束为依据。以上参考图片只约束美术方向；当参考图片与真实需求冲突时，以真实需求和可用性为准，但最终视觉风格仍需尽量保持一致。

本文件用于细化 `ForgeCore 项目方案.md` 第 52 节，不构成平行项目方案；若两者出现冲突，以项目方案为准，并同步修订本文件。

## 2. 核心视觉语言

| 维度 | 提炼结论 | 执行边界 |
| --- | --- | --- |
| 整体气质 | 洁净、理性、精密的工业控制台外壳，与高细节的工厂数字孪生内容并置 | 保留工业感与工程秩序，不把视觉复杂度等同于业务复杂度 |
| 色彩 | 黑、白、浅灰和炭灰构成中性基底；暖黄色承担品牌聚焦或当前态；青蓝、绿色用于信息、路径、选择或正向状态；橙色用于辅助区分；红色用于异常和危险 | 参考图不提供精确色值；实施时需建立语义色令牌并通过对比度验证，不得只用颜色传达状态 |
| 明暗与对比 | 大面积明亮内容区与局部深色侧栏、标题条或悬浮控制形成强对比；3D 场景或地图可偏暗，以彩色路径和标记聚焦 | 深色区应服务层级或操作聚焦，避免无意义的大面积黑底；文字与叠层必须保持可读 |
| 材质与氛围 | UI 表面以洁净浅色、细描边、轻阴影、轻微渐变或雾化为主；3D 内容强调金属、管网、设备、网格、磨损和俯视光影 | 界面材质保持克制；工业纹理主要留在内容和场景，不扩散为影响阅读的背景噪声 |
| 面板与层级 | 白色或浅灰卡片、局部炭黑面板、小到中等圆角、细边框、弱投影；深色标题条、色条、下划线和反相填充用于分层或选中 | 建立少量稳定的容器层级，统一圆角、描边和阴影语法，避免每个模块自创样式 |
| 字体气质 | 无衬线、粗壮、直接；大标题、关键数字和编号具有明显字重层级；正文紧凑但不拥挤 | 字体名称、字号和比例须另行设计；不能照搬参考图中难辨的小字、超大展示编号或疑似生成错误文案 |
| 图标与装饰 | 以黑白线性几何图标为主，必要处使用实心反相；工业设备可使用微缩 3D 缩略图；黄色短线、竖条、描边、节点、路线和轻微发光负责聚焦 | 统一线宽、尺寸与视觉重量；线性功能图标和 3D 内容缩略图应分工明确，避免无规则混用 |
| 状态反馈 | 黑白反相、暖黄选中、青蓝信息、绿色正向、红色警示，以及进度条、轮廓、标记点、区域覆盖和路径发光共同表达状态 | 状态语义需由真实产品定义；颜色之外必须有文字、图标、形状或位置等冗余线索 |
| 视觉节奏 | 常见构图是高密度中央场景配较疏朗外围面板，或暗色可视化配明亮数据面板；卡片内部留白规整，组间边界清晰 | 这只是视觉密度与层次参考，不是固定三栏布局要求；页面结构必须重新依据任务流设计 |

## 3. 可执行设计规则

### 3.1 颜色与表面

1. 先建立中性背景、主表面、次表面、深色控制表面、主文字、次文字、品牌强调、信息、成功、警示和危险等语义令牌，再确定实际色值。
2. 暖黄色作为最稳定的品牌/聚焦强调，不应与大量高饱和颜色竞争。
3. 青蓝、绿色、橙色和红色只在有明确语义时出现；同一语义在不同页面保持一致。
4. 默认表面使用细描边和弱投影建立层级；只有悬浮控制、关键对话或场景叠层可以提高阴影或明暗差。
5. 3D 场景、地图和图表背景必须为文字叠层预留安静区域，必要时使用遮罩、局部降噪或独立信息板。

### 3.2 组件语言

1. 卡片、面板、输入、按钮、标签和弹层共用有限的圆角层级，不为单个页面创建特殊圆角。
2. 主操作采用高对比实心按钮；次操作采用浅色或描边按钮；危险操作使用独立危险语义并避免与品牌黄色混淆。
3. 当前态可用反相填充、黄色色条/下划线、图标和文字共同表达；一个导航层级只使用一种主高亮语法。
4. 线性图标统一笔画、端点、包围盒和视觉尺寸。设备缩略图属于内容资产，不替代功能图标。
5. 进度、路径、告警和选区必须同时提供非颜色线索，且在缩放、弱视和色觉差异场景下仍可辨认。

### 3.3 字体与信息密度

1. 标题和关键数字可以粗重醒目，正文、字段标签和辅助信息必须优先保证长时间阅读的清晰度。
2. 使用稳定的标题、分组标题、正文、辅助文本和数据层级；表格数值应对齐，单位与状态标签应清楚关联。
3. 不复用参考图中的示例文案、编号、字段、数值或疑似错字；所有内容来自产品词汇表和真实数据模型。
4. 高密度场景旁的信息面板应更克制，避免 3D 细节、彩色路径、粗标题和大量状态色同时争夺注意力。

### 3.4 布局、响应式与可访问性

1. 先依据用户任务、信息优先级和数据关系完成信息架构，再选择单栏、分栏、抽屉、浮层或全屏画布等形式。
2. 参考图中的三栏、左右侧栏、顶部导航、底部控制条和中央大场景均为构图观察，不是固定页面模板。
3. 响应式方案必须针对实际内容定义折叠、重排、隐藏与替代交互，不从图片反推精确尺寸或断点。
4. 实施和验收时检查键盘操作、焦点可见性、语义结构、文字缩放、对比度、色觉冗余、触控可用性及动态效果降级。

## 6. UI 审计清单

每个 UI 页面、组件集合或重要视觉变更在设计评审与实现验收时均需逐项检查。未通过项不得静默放行；确需偏离时必须记录原因、影响与批准人。

- [ ] 色彩倾向、材质表现、光影层次和整体工业科技氛围与本规范一致。
- [ ] 面板、容器、边框、圆角、阴影、层级、装饰和图标语言保持一致。
- [ ] 暖黄及其他状态色遵循稳定语义，没有在页面间任意换义。
- [ ] 状态反馈除颜色外还有文字、图标、形状或位置等可辨识线索。
- [ ] 没有把参考图中的页面结构、三栏构图、导航关系或业务信息误当成产品事实照搬。
- [ ] 已根据真实需求、用户任务、数据关系和业务优先级重新完成信息架构与交互设计。
- [ ] 字段、文案、状态、功能入口、权限和流程均可追溯到项目需求或数据模型，而不是来自参考图片。
- [ ] 已检查可访问性、响应式、可读性、键盘操作、焦点状态、文字缩放、对比度和色觉冗余。
- [ ] 高密度 3D 场景、地图或图表没有遮挡关键文字，叠层信息在真实数据下仍清晰。
- [ ] 固定顶栏、通知、浮窗和工具坞没有遮挡或截获其他可见控件的点击区域；视觉上可见的主操作在实际命中测试中仍能触发自身。
- [ ] 所有偏离参考美术风格的地方均记录了原因、影响范围和替代方案。
- [ ] 评审材料只把这些图片描述为“美术风格参考”，没有称为正式设计稿、需求稿或交互原型。
- [ ] 参考图相对链接可访问，归档文件数量正确，文件 SHA-256 与本索引一致。

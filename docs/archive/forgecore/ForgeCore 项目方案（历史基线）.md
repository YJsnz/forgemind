# AI 驱动的智能工厂数字孪生设计与仿真平台项目方案

> **项目名称：ForgeCore**
>
> **中文名称：ForgeCore AI 智能工厂数字孪生平台**
>
> **项目定位：面向生产制造场景的可视化工厂设计、生产仿真、智能物流与 AI 优化平台**
>
> **核心理念：Design → Build → Simulate → Analyze → Optimize**

---

# 1. 项目概述

## 1.1 项目背景

随着数字孪生、智能制造、工业互联网、人工智能和三维可视化技术的发展，传统工厂正在逐步从单纯的信息化管理转向数字化、智能化与自动化。

现有大量工业管理系统通常侧重于设备监控、生产数据展示、订单管理或故障告警，而对于生产线本身的设计、工艺流程模拟、物流调度以及整体产能优化支持较为有限。

本项目计划开发一套以 **3D 数字工厂为核心** 的智能工厂设计与仿真系统。

用户可以在一个基于网格的三维空间中自由搭建工厂，通过放置机器、货物仓库、开放式货架、无人运输车辆、无人机等设施，并拖拽铺设支持直线与自动弯道的可运行传送带，自定义完整的生产流程，再通过系统提供的生产仿真引擎观察工厂运行情况。

平台不绑定某一种固定工业场景，而是允许用户自行定义：

- 原材料
- 半成品
- 成品
- 加工机器
- 加工关系
- 生产流程
- 仓储方式
- 运输方式

从而满足不同制造行业和实验场景的需求。

系统同时内置 AI 智能分析模块，可以根据工厂运行过程中产生的数据自动分析产线瓶颈、物流拥堵、设备利用率、仓储效率以及整体产能，并向用户提出针对性的优化建议。

长期目标是使系统进一步具备自动优化甚至自动设计生产线的能力。

# 2. 项目定位

ForgeCore 并不是一个单纯用于展示工厂状态的传统数字孪生系统。

本项目希望构建的是：

> **一个允许用户自由设计、搭建、运行、分析并优化数字工厂的通用智能制造仿真平台。**

平台主要覆盖五个阶段：

```text
设计 Design
    ↓
搭建 Build
    ↓
仿真 Simulate
    ↓
分析 Analyze
    ↓
优化 Optimize
```

用户可以从一块空白工厂区域开始，根据自己的实际需求建立完整生产系统。

# 4. 系统总体设计理念

整个系统建立在几个基础抽象之上：

```text
Item
物品

Recipe
加工配方

Machine
机器

Storage
仓储

Transport
运输

Factory Node
工厂节点
```

所有工业场景均通过这些通用对象组成。

系统不会将某种机器和具体工业用途绑定。

例如系统不会规定：

```text
Machine-A 必须加工钢材
```

而是允许用户定义：

```text
Machine-A

输入：
Item-001

输出：
Item-002
```

因此同一套系统既可以表示：

```text
铁矿石
↓
铁锭
```

也可以表示：

```text
牛奶
↓
奶酪
```

还可以表示：

```text
PCB
+
芯片
+
电子元件

↓

主板
```

这种抽象设计可以使 ForgeCore 适用于：

- 机械制造
- 汽车工业
- 食品加工
- 电子制造
- 化工生产
- 物流仓储
- 自动化生产实验
- 教学演示

等多种场景。

# 8. 多楼层工厂系统

ForgeCore 支持从地面层向上堆叠的多楼层数字工厂。首版楼层数据必须显式记录 `id`、`level`、`name`、`elevationM` 与 `heightM`；新建上层时以当前最高层顶部作为新层标高，层高允许在 `2.5–12m` 范围调整，默认 `4.5m`，从而保证任意连续楼层都具有确定的三维高度关系。

工厂编辑器左侧提供楼层选择器：

```text
Floor

5F
4F
3F
2F
1F
```

用户可新建上层并随时切换当前楼层。每个楼层条目右侧提供独立显示开关，创建或恢复楼层时默认开启；关闭后，该层对象在任何显示模式下都不得出现，但切换到该层时仍只绘制该层网格供建造。楼层面板提供三档材质范围设置：`仅当前层` 只显示当前楼层中已开启的对象；`多层透视` 显示所有已开启楼层，并把非当前层对象统一作为半透明上下文；`多层实显` 以正常材质显示所有已开启楼层。多层模式不再隐含“只显示当前层以下”的方向限制，当前层上方和下方的已开启楼层一视同仁，均按真实相对标高显示且保持只读。跨层倾斜传送带只有其两个端点所属楼层都处于开启状态时才显示，避免关闭楼层的坡面仍泄露到场景。

三档模式始终只绘制当前楼层网格，不叠加任何其他楼层网格。只要多层模式中存在至少一个已开启的非当前楼层，当前层实体地块就改为单面的半透明轻量表面，网格材质与承载面均不得写入深度缓冲；底部承托面移动到最低可见楼层下方，镜头目标与距离按最低、最高可见标高形成的完整垂直范围自动调整。可见的跨层传送带及其在途物品使用高于半透明地块与网格的透明绘制优先级，同时继续接受不透明设施的深度遮挡，保证坡面穿过网格面时连续可见而不会透过机器。切回 `仅当前层` 或关闭全部其他楼层时恢复单层构图。楼层开关只控制可见性，不删除对象、不改变碰撞、库存、任务或仿真数据；当前实现仍不提供删除楼层，避免在跨层连接和库存迁移规则尚未定义前破坏数据关系。

用户因此可以建设：

```text
1F 原材料与重型加工

2F 半成品加工

3F 装配

4F 检测

5F 成品仓储
```

等复杂工厂。

# 9. 自定义物品系统

ForgeCore 的生产系统建立在统一的 `Item` 物品对象之上。

用户可以创建任意物品。

`Item` 是业务身份，`ItemModel` 是可复用的视觉形态：多个原材料、半成品或产品可以引用同一个稳定 `modelId`，再用各自的 `modelParameters` 改变尺寸、截面、孔径、齿数、圈数、颗粒数、颜色和 PBR 材质等视觉参数，不需要为“钢板”、“铜板”和“塑料板”分别复制网格。

基本属性：

```text
Item ID

物品名称

物品编号

物品类别

描述

3D模型

图标

尺寸

重量

最大堆叠数量
```

字段边界必须保持清晰：

- `Item` 保存 `Item ID`、名称、编号、类别、描述、图标、`modelId`、`modelParameters`、质量与最大堆叠数等业务数据。
- `ItemModel` 保存稳定 `modelId`、参数 schema、默认参数、材质槽、GLB 路径、预览路径、包围盒、几何指标、版本与 SHA-256。
- `Item.modelParameters` 只保存用户明确调整过的参数覆盖，不复制整份默认参数；读取时由 `modelId` 对应 schema 补齐其余默认值。恢复旧存档时应删除未知键、业务字段，并把旧版完整且未调整的默认参数表折叠为空覆盖。显式覆盖可以等于 schema 默认数值，例如用户仍可把铜材质的金属度明确设为 `0.5`。
- `Mass` / 重量和 `Stack Size` / 最大堆叠数是 `Item` 的物流与业务属性，**不是模型参数**，不得写入几何生成器或用它们改变网格。

“物品与模型库”页面同时承担业务物品管理入口。已添加物品必须以独立清单显示名称、编码、类别、基础模型、显式参数覆盖数、质量和最大堆叠数，并提供编辑与删除操作。编辑沿用创建时的参数化建模器，允许修改名称、编码、类别、描述、基础模型、模型参数、质量和最大堆叠数；保存时保持原 `Item ID` 不变，使配方、库存、传送带与 AGV 引用继续指向同一业务物品。切换基础模型时清空旧模型参数并载入新 schema 默认值，保存后场景中所有该物品实例按新模型与参数实时重建。

物品名称和编码不能为空，同一工厂内编码不区分大小写且必须唯一；质量必须为有限非负数，最大堆叠数必须为正整数，模型必须来自当前审计目录。删除仍执行引用门禁：只要物品被配方、AGV 程序、AGV 车载货物、非零/无限/已预约库存引用，就必须拒绝并说明原因；未被引用的零库存记录随物品一起清理。

例如：

```text
Item ID：
MAT-001

名称：
铝合金板

类型：
Raw Material

重量：
2.6 kg

最大堆叠：
20
```

# 10. 自定义物品模型

系统已提供首版 **36 个 ForgeCore 原创参数化默认物品模型**。它们是项目自有的 **first-party/core** 资产，权威运行时路径为 `assets/3d/core/items/v1/`，不属于 `assets/3d/vendor/` 的上游原包，也不属于 `assets/3d/derived/` 的第三方派生资产。

首版使用五类稳定 `modelId`：

- **基础形状（basic，6）**：`BASIC_BOX`、`BASIC_CYLINDER`、`BASIC_SPHERE`、`BASIC_DISC`、`BASIC_CONE`、`BASIC_RING`。
- **原材料（material，10）**：`RAW_CHUNK`、`RAW_GRANULE`、`RAW_INGOT`、`RAW_LOG`、`MATERIAL_PLATE`、`MATERIAL_ROD`、`MATERIAL_BEAM`、`MATERIAL_PIPE`、`MATERIAL_COIL`、`MATERIAL_WIRE_COIL`。
- **机械零件（mechanical，8）**：`PART_GEAR`、`PART_SHAFT`、`PART_BEARING`、`PART_BOLT`、`PART_NUT`、`PART_SPRING`、`PART_WHEEL`、`PART_FLANGE`。
- **电子与机电部件（electronic，5）**：`ELEC_PCB`、`ELEC_CHIP`、`ELEC_BATTERY`、`ELEC_MOTOR`、`ELEC_MODULE`。
- **包装与容器（package，7）**：`PACK_BOX`、`PACK_CRATE`、`PACK_BIN`、`PACK_PALLET`、`PACK_SACK`、`CONTAINER_DRUM`、`CONTAINER_BOTTLE`。

`assets/3d/core/items/v1/catalog.json` 是运行时模型索引，包含参数 schema、默认值、材质模板、包围盒、三角形数、预览路径和文件哈希；`assets/3d/core/items/v1/SHA256SUMS` 覆盖全部 36 个 GLB、36 张 PNG 预览和 `catalog.json`。结构参数改变时应重新生成几何，非结构材质参数可在运行时复用几何。同款 Item 批量出现时应使用实例化渲染。

参数面板必须读取 schema 的类型、范围、步长、枚举和 `activeWhen` 条件依赖，而不是在前端另写一套参数规则。例如 `wallThickness` 仅在圆柱体 `hollow=true` 时生效，电池 `diameter` 仅在 `shape=cylindrical` 时生效。颜色、金属度、粗糙度、透明度和自发光可覆盖主材质；`texture` 是应用层管理的纹理绑定键，离线生成器不读取网络地址或隐式引入外部资源。

创建物品对话框已直接读取上述 schema，为 `number`、`integer`、`boolean`、`enum`、`color` 和 `string` 六类参数生成对应控件，显示范围、步长、单位和条件依赖，并提供实时三维预览与一键恢复默认值。结构、拓扑和包围盒参数通过与离线资产完全相同的 ForgeCore 原创几何定义在浏览器中重新生成网格；材质预设、颜色、金属度、粗糙度、透明度、自发光和程序纹理键实际作用于主材质。用户触碰的参数会被限幅、规范化后作为显式覆盖保存，未知参数以及 `massKg`、`maxStackSize` 等业务字段无法进入模型生成链路。

内部坐标与格式契约固定为：**米制、右手系、Y-up、落地中心轴点（ground-center）、自包含 GLB 2.0**。未修改参数的默认形态继续直接加载已审计 GLB；带参数覆盖的 first-party/core Item 允许在浏览器中复用同一原创几何定义生成 Three.js `BufferGeometry`，这不是新增外部资产格式，也不得绕过 catalog schema。第三方和用户导入的静态资产运行时仍只加载 GLB，不依赖外部 URI，不在客户端直接解析 FBX、OBJ 或松散 glTF；其他输入格式必须先转换成自包含 GLB 才能进入运行时目录。

模型库由项目自带的 Node.js 脚本确定性生成，不需要 `npm install` 或任何第三方包：

```powershell
node tools/item-models/build.mjs
node tools/item-models/validate.mjs
```

首版需求导入源 `D:/Downloads/ForgeCore 默认基础 3D 物品模型库设计清单.md` 的 SHA-256 为 `8848a43224a2c4fe8663159a4272694f4353097d76560a7558eceab35ada9b16`；该外部文件只是初始导入需求，后续产品范围和技术契约仍以本方案为唯一权威。36 个资产不含第三方网格或纹理，但 `assets/3d/core/items/v1/` 根目录当前没有独立许可文件；在项目所有者正式设定和记录许可之前，不得把该库对外宣称为 CC0、CC BY 或其他开放许可资产。

详细指标、逐文件 SHA-256、验证项和原创/许可边界见 `assets/3d/ASSET_AUDIT.md`。

同时支持用户上传自己的模型。

运行时格式：

```text
GLB
```

例如用户可以上传：

```text

```

并建立：

```text

发动机
```

之后这件发动机模型就可以真正出现在数字工厂中。

# 11. 生产配方系统

机器本身不直接绑定原材料和成品。

系统通过 `Recipe` 定义加工关系。

例如：

```text
Recipe ID：
REC-001

名称：
铁板加工

输入：

钢材 × 2

输出：

钢板 × 1

加工时间：

5秒
```

当机器使用该配方时：

```text
钢材 ×2

↓

机器加工5秒

↓

钢板 ×1
```

初版配方工作区必须提供完整的创建与维护闭环：新建、编辑、启用/停用和删除配方；每条配方包含 `1–3` 种不重复的输入物品和 `1–3` 种不重复的输出物品，并分别设置引用物品与数量，同时维护配方编码、名称、工艺说明和处理时间。界面与状态层必须共同执行三种上限、引用存在性、数量和处理时间校验，不能只依赖表单按钮。配方不能引用不存在的 Item；空物品库进入配方页面时应明确说明这一前置条件，并提供直达物品创建页面的操作入口，不得只显示无法点击或会被其他浮层遮挡的按钮。

# 12. 多原料加工

配方支持多个输入，首版上限为三种不重复原料。

例如：

```text
Recipe：

电机装配
```

输入：

```text
线圈 × 2

磁体 × 4

外壳 × 1

```

输出：

```text
电机 × 1
```

因此系统能够模拟复杂装配生产。

# 15. 机器输入与输出接口

机器拥有明确输入口和输出口。

例如：

```text
       OUTPUT
          ↓

    ┌──────────┐
→ → │ Machine  │ → →
    │          │
→ → │          │
    └──────────┘
```

首版通用机器固定提供 `3 Input / 3 Output`，这也是首版单机端口上限。未旋转时三个入料口位于机器本地 `-X` 侧，三个出货口位于本地 `+X` 侧，并按本地 Z=`-1/0/+1m` 编号为 1、2、3。传送带只能从出货口起始、在入料口结束；每个编号端口最多连接一条传送带，成功连接后立即退出吸附候选，删除该传送带后才重新变为空闲。端口占用检查必须在指针吸附和状态写入两层执行，防止并发或旧界面状态造成重复连接。

机器的 `rotationY` 改变时，模型、三条内部传送带、黑色软帘、方向箭头和六个逻辑接口作为一个整体旋转。建筑物尚在鼠标上时，滚轮向上左旋 90°、向下右旋 90°，每次有效滚轮输入只改变一个四分之一圈；落地后仍可按 `Q` 左旋 90°、按 `E` 右旋 90°，属性浮窗同时提供等价按钮。快捷键必须在编辑器文档级捕获阶段监听，同时兼容 `KeyboardEvent.code=KeyQ/KeyE` 与字母键值，避免画布或按钮焦点导致失效；输入框、文本域、下拉框、可编辑区域、输入法组合态和带 Ctrl/Meta/Alt 的组合键不得触发机器旋转。旋转后所有已登记上下游关系的传送带必须根据各自端口编号重新对齐，不得串口或仍连接旧方向。

机器属性浮窗必须按编号展示六个端口的空闲/已连接状态。绑定单输出配方时，所有已连接出货口自动输出唯一产物，不显示多余选择；绑定多输出配方时，每条已连接的出货传送带分别选择该配方允许的一种产物，未分配的出货口不派发物料。修改配方后，已失效的出货分配必须清空，不能继续输送不在新配方中的产物。

这样可以使生产线设计更加真实。

# 16. 传送带系统

传送带是整个生产系统的主要运输设施。

用户先在底部建造栏单击传送带，进入持续建造态；随后在网格上按住并沿期望线路拖动，释放后创建传送带。开始铺设时，指针接近机器任一空闲出货口即自动吸附并登记 `fromObjectId + fromPortIndex`；释放前接近另一台机器任一空闲入料口即自动吸附并登记 `toObjectId + toPortIndex`，界面明确提示端口编号与“连接成功”。已占用端口不得再次吸附。吸附使用机器旋转后的真实端口坐标，不能再用任意边界中点代替输入/输出语义。对边界 `{x:10,z:10,width:6,depth:6}`、0° 的机器，入料口 1–3 为 `(11,12)/(11,13)/(11,14)`，出货口 1–3 为 `(15,12)/(15,13)/(15,14)`；旋转 90° 后，入料口为 `(12,15)/(13,15)/(14,15)`，出货口为 `(12,11)/(13,11)/(14,11)`。端口锚点距中心 2m，处在距中心 2.37m 的黑帘之后，并与半长 2.16m 的内部带形成连续重叠，视觉上不得在机器和传送带之间留下断口。未靠近端口时仍允许创建自由传送带。

所有普通与跨层传送带的首尾端点也属于可吸附连接节点，但场景不额外绘制端点小球；可吸附状态只通过建造预览、状态文字和线路高亮反馈，保持工厂画面干净。用户从空闲输出端开始或在空闲输入端结束拖线时，系统自动建立传送带之间的 `fromObjectId` / `toObjectId` 邻接关系，并继续遵守单端点单连接和流向语义。当相邻两段在共享端点的水平投影方向不同，连接点必须改用方向匹配的 Kenney 弯道组件，并同时裁切前后两段直线或坡面，禁止用两个直线端头交叉、重叠或留下小球代替转角；普通传送带与跨层倾斜传送带的混合连接同样适用。物品到达一段传送带末端后必须原样转交给下一段 TransitItem，允许普通传送带、倾斜传送带和普通传送带组成连续链路；删除中间段只解除相邻关系，不得连带删除整条生产线。

系统记录用户实际经过的网格轨迹，而不是只根据起点和终点强制生成固定 L 形路线：直线拖动只产生直线段，只有拖动轨迹真实改变水平/垂直方向时才形成拐点并使用弯道组件。弯道组件必须独占拐点格，Kenney 弯道原件未旋转时的有效接口方向按 `-X/+Z` 处理；四向映射固定为 `-X/+Z → 0°`、`+X/+Z → +90°`、`+X/-Z → 180°`、`-X/-Z → -90°`，旋转后的两个开放接口须分别朝向前后路径。相邻直线段必须截短至接口边缘，不得穿入弯道网格或与弯道模型叠放。两个相邻拐点之间若没有足够空间容纳完整直线模块，则由弯道接口直接衔接，不得强行缩放直线模型形成畸形碎片。再次单击已选中的传送带建造项、按 `Esc` 或在建造态中单击鼠标右键，均须立即退出建造态并清除鼠标随行预览。

放置门禁按网格占用而不是只看视觉模型：任意两个建筑占地矩形不得重叠；任意两条传送带的 1m 通道不得共格、交叉或叠放；新建筑也不得覆盖已有传送带，传送带不得穿过非首尾连接建筑。建筑与传送带恰好在边界相接允许，三条相距 1m 的并行端口通道必须判为互不冲突。预览层显示不可放置只用于即时反馈，最终写入 Store 前必须再次执行同一碰撞校验。

例如：

```text
Machine A
   ↓
────────────
   ↓
Machine B
```

传送带拥有：

```text
Transport Speed

Direction

Capacity

Connected Node
```

# 22. 仓储系统

系统支持不同规模仓储设施。底部建造栏同时提供可运行的“货物仓库”和“货架”，两者是模型、占地和容量规则均不同的独立对象。货物仓库继续使用 `rack` 对象类型以兼容已有存档，开放式货架使用新的 `shelf` 对象类型，禁止再以同一种设施或同一容量规则混用。

包括：

```text
Buffer

Rack

Warehouse
```

用户可以自由放置货物仓库。首版仓库固定采用候选图第六个 Kenney `machine-window.glb`（候选 F“可视化加工舱”）作为 CC0 外壳，统一适配为 `6m × 6m` 占地和约 `5.4m × 5.4m`、高 4.8m 的可见尺寸。仓内三条输送通道位于本地 Z=`-1/0/+1m`，内部摆放已入库的 Kenney `box-small.glb` / `box-wide.glb` 纸箱作为货物容器视觉，两端在 X=`±2.37m` 设置覆盖三条通道的黑色软帘。纸箱模型只负责“仓内装有货物”的视觉表达，准确数量、品类和容量必须读取 Inventory，不得根据画面中的箱子个数反推业务库存。

货物仓库属性：

```text
Warehouse ID

仓库尺寸

格口数量

格口容量

存储类型

当前库存

已定义物品明细

有限库存 / 无限供应状态

出货口 1–3 独立出货间隔（秒 / 次）
```

选中仓库后，属性浮窗必须直接列出项目中已经定义的全部 Item，显示物品名称、编码、该仓库实际数量和供应方式，不得只显示总数或前几项摘要。没有任何 Item 时显示“先定义物品”的明确前置引导；至少存在一种 Item 后，用户可以在对应行输入数量并手动入库，也可减少误加库存。仓库的有限库存总量继续受聚合容量约束。

首版仓库拥有编号 1–3 的三个入货口和三个出货口。每个端口只能连接一条传送带；连接成功后不再参与吸附，删除传送带后恢复空闲。端口坐标、旋转、吸附、帘后锚点和碰撞规则与 6×6 通用机器共用同一协议，区别只在仓库输入端显示“入货口”而非“入料口”。仓库在手上时同样支持滚轮 90° 步进旋转。历史存档中的 `kind: rack` 始终解释为 6×6 候选 F 货物仓库并为旧连接分配不重复端口；新货架只使用 `kind: shelf`，不得通过重解释旧 `rack` 存档完成迁移。

每个仓库的三个出货口分别配置 `dispatchIntervalSecByPort[0..2]`，表示对应端口每隔多少仿真秒最多发出 1 件货物。每个端口允许 `0.25–60` 秒，默认均为 `2.5` 秒；属性浮窗不再提供覆盖整个仓库的大面板统一间隔，而是在“出货口 1–3”的端口行内分别编辑。三个端口使用独立冷却计时器，只有实际成功创建 TransitItem 的端口重置自己的冷却；无货、未选物品或线路阻塞时该端口保持可立即重试，任一端口出货不得推迟另外两个端口。间隔只控制仓库创建 TransitItem 的节奏，不改变传送带 `speedMps`、路径长度或在途运动速度。旧存档中的单值 `dispatchIntervalSec` 和仓库级冷却值必须分别复制到三个端口后再继续运行，工厂数据 schema 升级为 `4`。

开放式货架采用 mastjie `glb/rack.glb` 作为 CC0 主体视觉。运行时在世界轴执行显式 `Y +90°` 朝向修正与非等比缩放，消除旋转后长宽缩放轴互换的问题；业务占地为 `8m × 2m`，可见尺寸约为 `7.2m × 5.4m × 1.8m`，实际长度约为修复前异常拉伸外观的一半。架体上按四层、双排、五列组合摆放 40 个 Kenney `box-small.glb` / `box-wide.glb`，每组箱体以运行时层板顶面标高为基准落位，形成真正置于层板上的满载陈列；这些箱体只表达货架用途和满载感，不等同于 Inventory 数量。货架不设入货口或出货口，不参与普通/跨层传送带吸附和自动入出库；仍支持 90° 旋转，旧存档中曾连接货架的线路在恢复时自动解除货架端关系。

货架中的有限库存采用无限堆叠规则：单个 Item 和货架总量均不设业务容量上限，用户可直接上架任意非负安全整数数量，不受 Item 的 `maxStackSize` 或货物仓库 1800 件容量限制。每个“货架 × Item”记录也可独立切换为无限，并在场景标签、属性浮窗和物流页以 `∞` 明示；该设置表达货架记录无需维护有限数量，不会让无端口货架创建 TransitItem。实现层允许用 `Number.MAX_SAFE_INTEGER` 作为可持久化的无上限容量哨兵，但界面与业务语义必须显示为 `∞`，不得把该哨兵展示为实际容量或伪造库存。

例如：

```text
Warehouse A-07

A01：
钢板 ×30

A02：
钢板 ×48

A03：
电机 ×12

B01：
轴承 ×80
```

# 23. 自动入库和出库

系统为货物仓库与货架建立同一套库存记录生命周期，但只允许货物仓库参与传送带仓储逻辑。创建业务 Item 后，每个已放置仓库和货架自动建立该 Item 的零库存记录；放置仓储设施时也会为当前已有 Item 建立零库存记录。空白项目仍不注入任何默认 Item 或默认库存。

例如：

```text
Machine 出货口
↓
Conveyor
↓
Warehouse 入货口
```

或者：

```text
Warehouse 出货口
↓
Conveyor
↓
Machine 入料口 / 另一个 Warehouse 入货口
```

入货物料沿完整传送带路径运动，到达货物仓库或机器的输入锚点后才写入 Inventory 或输入缓存；货物仓库容量不足时，物料保持在传送带末端阻塞，不得凭空消失。仓库有限库存出货时，按每条出货传送带的端口配置从 Inventory 扣减一件，再创建对应 TransitItem。仓库仅有一种可供应物品时自动选择；存在多种可供应物品时，每条已连接出货带分别选择物品，未选择或所选有限库存为零时该通道不出货。三个出货口按各自间隔与冷却并行工作，某一端口等待不得冻结其他端口，所有有限库存运输必须满足物料守恒。货架库存可通过属性浮窗或物流页维护，也可由 AGV 实际取货或存货，但不进入上述传送带输送流程。

库存预约必须区分两个方向：`reservedOutboundQuantity` 只表示 AGV/无人机尚未装货但已锁定的起点现有货物，仓库和货架的可出货量按 `quantity - reservedOutboundQuantity` 计算；`reservedInboundCapacity` 只表示运输任务为终点预占的未来入库容量，货物仓库剩余容量按所有物品的 `quantity + reservedInboundCapacity` 汇总计算。入库容量预约不得减少终点已有货物的传送带可出货量，出库货物预约也不得在容量计算中把同一件现存货物重复占位。物流页应分别显示“出库预留”和“入库占位”，不再用含义混杂的单列“预留”。旧存档中的 `reservedQuantity` 必须依据活动中的 AGV/无人机运行时起点记录和终点记录重新构建两个方向的预约；无法与活动任务对应的旧值归零，不得盲目复制到两个字段。

TransitItem 的场景模型必须通过其 `itemId` 找到 Item，再以 `Item.itemModelId` 解析 `assets/3d/core/items/v1/catalog.json` 中对应的 GLB。首版 36 个稳定 `modelId` 必须全部覆盖，不能只为少数示例物品硬编码路径，正常已定义物品不得显示为白色通用方块。只有未知 `modelId` 或 GLB 加载失败时才允许显示带黄色故障标记的中性回退货物，并保留可诊断状态。

每个“仓储设施 × Item”库存记录可以显式切换为无限。货物仓库的无限供应是用户主动配置的仿真源边界：该物品可持续创建出货 TransitItem，不扣减实际数量、不占用额外有限库存容量；无端口货架的无限设置不会自行创建传送带运输，但在货架被配置为 AGV 起点时可作为显式无限源，装货不扣减实际数量。两类设置均在场景标签、属性浮窗和物流库存表中以 `∞` 明示，关闭后恢复显示并维护原有有限数量。无限状态不得用超大伪数量实现，也不得伪装成满足物料守恒的普通库存。

手动库存调整可直接在仓库或货架属性浮窗完成，并在“物流与仓储”页面保留集中管理入口，二者使用同一 Store 门禁。仿真空闲时设置的有限数量同时作为重置基线；运行中或暂停时的人工调整只改变当前数量。删除货物仓库时，其连接传送带、在途物料和所属库存记录一并清理；删除货架时清理所属库存记录。删除 Item 时只有在未被配方、非零库存或无限配置引用时才允许，并清理无引用记录。

机器需要原料时可以自动产生：

```text
Material Request
```

物流系统自动寻找库存并创建运输任务。

# 25. AGV 自动取货

当前直接编程链路以 1F 的仓库或货架作为同层装卸站点；AGV 不得在 2F 及更高楼层放置或执行运输，也不承担跨层任务。货架与货物仓库使用同一套“仓储设施 × Item”库存事实，因此货架既可以作为起点被 AGV 实际扣减库存并取货，也可以作为终点接收卸货并增加库存；货架仍不提供传送带端口，其对外运输可以通过 AGV 或无人机。程序启动时先检查触发条件、起点可用库存、物品质量、车辆最大载重和终点剩余容量，再按每趟件数创建任务。有限库存任务必须预约起点数量和终点容量，防止传送带、手工库存调整或其他运输载具抢占同一批货物；货架的有限数量允许无限堆叠，作为终点时不受货物仓库 1800 件总容量限制。无限供应保持显式仿真源语义，不扣实际数量。

例如程序配置：

```text
起点：Rack A-12

终点：Warehouse B-03

Item-024 ×10

触发：起点数量达到或超过 30
```

系统：

```text
检查触发条件、载重和终点容量

↓

预约起点库存与终点容量

↓

AGV 前往起点

↓

实际扣减有限库存并装载车载货物

↓

沿安全最短路径运输到终点

↓

卸货并写入终点实际库存
```

装货到卸货之间，物料只存在于 `AgvRuntimeState.cargoQuantity`，库存与车载量之和必须守恒。删除载货车辆时应优先退回原有限库存并释放预约；重置仿真恢复初始库存并清空预约和车载状态。后续机器自动补料可以在相同任务协议上增加机器装卸适配器，不应另建平行运输系统。

AGV 的导航空间固定为 1F 平面。建造层不是 1F 时，建造命令必须直接拒绝 AGV；旧存档或异常数据中的上层 AGV 程序必须显示不可运行原因，不得把上层坐标悄悄投影回 1F。

路径在 `0.25s` 固定仿真步长内按明确的 `m/s` 前进，车辆位置、朝向、行驶距离、阻塞时间、车载货物和任务阶段均进入可保存的仿真状态；显示层在逻辑位置之间逐帧平滑，不得瞬移、斜穿障碍或只播放无库存结算的动画。

# 27. AGV 多车调度

当前多车协调已实现：

```text
实时车辆占用检测

最小 3.8m 车心安全间距

静止或慢行车辆作为动态障碍实时重规划

确定性固定通行权

低优先级车辆自动寻找让行点

让行完成后重新规划原任务最短路

迎面冲突与交叉口冲突的边交换禁止
```

车辆发现当前路线被另一台静止、等待或慢行车辆占用时，先把其他车辆的当前位置及短时运动包络写入动态障碍图，并从当前位置到本次装卸目标重新执行八方向 A*；存在安全绕路时立即替换剩余路线并继续任务，不能因为原路线被占就永久停车。只有当前安全图确实没有绕路，或两台运动中车辆发生迎面/交叉冲突时，才进入协调等待与让行。已经处于安全间距内的历史状态只允许执行能持续增大车距的脱离动作，避免碰撞门禁反过来锁死正在离场的车辆。

两车发生无法直接绕开的路线冲突时，按稳定车辆 ID 决定唯一通行权，只有低优先级车辆进入让行状态，从而消除“两车同时礼让、随后同时前进”的对称活锁。高优先级车辆在低优先级车辆未退出安全间距前仍必须停车，不能以通行权为由穿模；低优先级车辆使用动态安全图寻找离冲突车辆及其近期路径足够远的最近可达让行点，完成让行后重新执行原任务。若物理布局没有任何安全绕路或让行点，系统保持确定性阻塞并显示原因，不允许碰撞穿越。

货架与货物仓库的 AGV 装卸区域按设施级单机服务位协调，即使 A* 在设施不同侧找到多个可达停靠格，也不得让两辆车同时装卸同一设施。多车前往同一装卸设施时，系统按“装卸区内现有车辆或正在离场车辆优先，其次剩余路线更短，最后稳定车辆 ID”确定唯一进场权；其他车辆停在设施安全等待半径之外并显示共享装卸位排队原因。完成卸货的 AGV 不得永久停在装卸格等待库存触发，而应沿刚刚通过且已经过碰撞验证的路线反向退出到安全距离，再进入下一任务或等待状态。该进场仲裁、离场优先和安全退让同时覆盖货架与货物仓库，必须保证两辆 AGV 向同一设施取货或存货时依次完成而不死锁。

# 28. 无人机运输系统

无人机与 AGV 采用完全不同的运输机制。

无人机：

```text
可以三维移动

不依赖地面道路

可以跨越机器

可以跨楼层

运输速度高

载货量较低
```

例如：

```text
1F Machine A

        ↗

      Drone

             ↘

            4F Machine B
```

因此无人机适合处理：

```text
高价值零件

紧急补料

小批量运输

跨楼层物料
```

无人机模型只承担可视外形、空间包络和经审计的语义节点，不是载荷、速度、电池、任务或运输规则的事实来源。`Drone` 与 `TransportTask` 保存业务能力和运行状态，`VehicleModel` 保存视觉资产、坐标、碰撞、LOD、动画和来源许可；不得从文件名或模型外观推断真实飞行性能。

无人机使用与 AGV 完全一致的可视化任务编程：逐机设置起点仓库或货架、终点仓库或货架、物品、每趟件数、持续运输或起点/终点库存阈值、速度和业务最大载重；区别只在可选装卸点覆盖全部楼层，且默认载重与单趟运量明显低于 AGV。货物仓库作为起点时，无人机必须飞到仓库出货口外侧装货；货物仓库作为终点时，必须飞到入货口外侧卸货。三个同侧端口均作为候选装卸航点，按仓库旋转后的真实端口方向生成，并由三维 A* 在满足建筑安全净空的候选中选择可达最短点；不得继续把仓库中心正上方作为固定装卸点。货架没有输送端口，继续使用架体上方的安全装卸点。任务仍执行库存触发、起点与终点预约、真实扣减、车载货物、真实卸货与总量守恒，不能只播放飞行动画。

无人机导航采用规则三维体素 A*。每个节点保存世界坐标 `x/y/z`，相邻集合覆盖立方体的 26 个方向：单轴直线移动代价为 `1`，两个轴同时变化的面对角移动代价为 `√2`，三个轴同时变化的体对角移动代价为 `√3`；启发式使用对应的三维对角距离。任何面对角或体对角移动都必须检查所跨越的全部轴向/边向相邻体素，禁止切过建筑棱角。工厂 X/Z 边界、最低安全高度和最高楼层上方的飞行上限共同限制搜索空间。

机器、货物仓库、货架与缓冲区按其所属楼层标高、业务占地、已登记视觉高度和无人机独立安全包络构成三维静态障碍；传送带、跨层传送带和 AGV 低于无人机安全飞行高度，不写入无人机障碍图。无人机可在有净空时从建筑上方飞越，但不得穿过建筑体积。跨层向下飞行时，下降边只允许发生在整段垂直柱体均无遮挡的位置：无人机必须先横向或斜向飞到安全净空列，再垂直下降到下一飞行高度，禁止直接穿楼层建筑或贴着障碍斜切下降。向上飞行与其他三维绕障仍可使用面对角和体对角最短移动。

无人机之间使用三维球形安全间距、短时位置预测和动态障碍重规划。候选移动若侵入另一架无人机的安全球，系统按稳定载具 ID 决定唯一通行权：低优先级无人机先把高优先级无人机及其近期位置写入动态障碍图并重新执行三维 A*，确实无路时才等待；高优先级无人机也不得穿过正在让行的机体。已经处于安全间距内的历史状态只允许执行能持续增大双方距离的脱离动作，不得因碰撞门禁把正在离场的无人机再次锁死。该规则必须消除双方同时礼让的对称活锁，并保持确定性仿真。

货架上方以及货物仓库入货口/出货口外侧的无人机装卸区域采用设施级单机服务位。同一时刻有多架无人机飞往同一仓储设施时，系统按“装卸区内现有无人机优先离场，其次剩余航程更短，最后稳定载具 ID”确定唯一进场权；其余无人机必须停在装卸区安全等待半径之外，状态显示正在等待共享装卸位，不得因为选择了不同编号端口就同时挤入同一仓库。完成装货或卸货的无人机不得永久停在装卸点：若当前运输循环已经结束，必须沿刚刚通过且已验证无静态障碍的进场航路反向退出到安全等待距离之外，再进入库存触发等待。该终点仲裁、离场优先和安全退让必须同时覆盖货架与货物仓库的输入/输出侧，并保证两架无人机向同一设施存货或取货时均能依次完成而不死锁。

场景显示无人机的实时三维规划轨迹、方向箭头、节点、终点标记、取货点/卸货点标签和剩余三维距离；路线底线、状态虚线、箭头、节点与终点标记全部采用半透明材质，选中路线只提高透明度但不得恢复为近乎不透明，避免三维路线遮挡建筑、货物和其他无人机；路径重规划后立即替换。无人机本体、车载真实 Item 模型和轨迹均以绝对楼层标高换算到当前视图，跨层飞行过程中不得瞬移、贴地穿模或在切换楼层时跳回建造坐标。

### 3D 工厂素材基线

ForgeCore 将 3D 资产明确分为 `core`、`vendor` 与 `derived` 三类：

- `assets/3d/core/`：ForgeCore 原创、可重现的 first-party 运行时资产，不是 vendor 原包，也不是第三方模型的派生件。
- `assets/3d/vendor/`：原样保留的第三方上游资产，以许可和来源可追溯为目标。
- `assets/3d/derived/`：对 vendor 资产进行减面、尺度、材质、碰撞体、LOD 或语义化后的项目派生件，必须保留来源关系和许可要求。

GitHub 仓库分发使用 Git LFS 保存不适合普通 Git 差异存储的二进制 3D 与预览资产；`.gitattributes` 对 `*.glb`、`*.fbx`、`*.obj`、`*.png` 和 `*.jpg` 启用 LFS，源码、配置、文档及轻量文本资产继续使用普通 Git。克隆者需要启用 Git LFS 才能取得完整模型和图片；LFS 只改变仓库存储与传输方式，其指针不得被当成资产内容、不得改变 `catalog.json`、`SHA256SUMS` 或 `ASSET_AUDIT.md` 中针对实际文件的校验值，也不得借此覆盖或改写 `core`、`vendor`、`derived` 的来源与许可边界。

#### ForgeCore 首版默认物品模型库（first-party/core）

`assets/3d/core/items/v1/` 内置 36 个参数化低模物品，分为 basic、material、mechanical、electronic 和 package 五类。它们由 `tools/item-models/` 中的 ForgeCore 原创零依赖生成器生成，不包含也不派生于第三方网格或纹理。运行时契约为自包含 GLB 2.0、米制、Y-up、ground-center，资产完整性由 `catalog.json` 与 `SHA256SUMS` 共同审计。

生成与验证只需要 Node.js，无 npm 包或外部建模工具依赖：

```powershell
node tools/item-models/build.mjs
node tools/item-models/validate.mjs
```

#### 第三方视觉资产（vendor）

ForgeCore 当前采用四套可追溯的第三方资产作为工厂、仓储、AGV 与货运无人机视觉资源：

1. **Kenney Factory Kit 3.0**：编辑器默认工厂设施、机器与流水线模型库，项目内权威路径为 `assets/3d/vendor/kenney-factory-kit-3.0/`，Web 端优先使用 `Models/GLB format/`。
2. **mastjie Low Poly Warehouse Kit**：提供开放式货架主体与其他仓储场景原件，项目内权威路径为 `assets/3d/vendor/mastjie-low-poly-warehouse-kit/`；`glb/rack.glb` 已作为底部建造栏独立“货架”的单实例视觉主体，并组合 Kenney 箱体形成满载陈列。封闭式货物仓库继续使用 Kenney 候选 F，mastjie 的 warehouse、crate、container、barrel 原件保持原样且暂未接入运行场景。
3. **Cels Industrial 3D AGV Trolley**：补充 AGV 无人运输车视觉资产，原始 GLB 位于 `assets/3d/vendor/cels-industrial-agv-trolley/industrial_3d_agv_trolley_free_low-poly_3d_model.glb`。
4. **Count Infinity Futuristic Delivery Drone**：补充货运无人机视觉资产，原始 GLB 位于 `assets/3d/vendor/count-infinity-futuristic-delivery-drone/futuristic_delivery_drone.glb`，署名记录位于同目录 `ATTRIBUTION.md`。

Kenney 与 mastjie 资产采用 **Creative Commons Zero（CC0）**。Cels AGV 与 Count Infinity 无人机均采用 **Creative Commons Attribution 4.0（CC BY 4.0）**。Cels AGV 使用和分发时必须注明作品名称、作者 Cels、[Sketchfab 原模型页](https://sketchfab.com/3d-models/industrial-3d-agv-trolley-free-low-poly-3d-model-016a066401a3489dafa98669d3a4b3f1)及 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)；无人机必须注明作品名 Futuristic Delivery Drone、作者 [Count Infinity](https://sketchfab.com/countinfinity)、[Sketchfab 原模型页](https://sketchfab.com/3d-models/futuristic-delivery-drone-48d0997629ee4cc9836775a523651017)及 CC BY 4.0。两者的派生版本都必须说明修改内容。GLB 作为 Web 3D 运行时首选格式；FBX 与 OBJ（若上游提供）仅作为建模软件交换、二次加工和兼容性备份。

上游原始文件必须保持只读式管理，不在 vendor 内直接覆盖、改名或制作项目定制版本。mastjie 货架已通过容器、几何、性能、依赖和离线外观检查；原始尺度约为 `4.9777 × 9.5955 × 19.9950`（X × Y × Z，模型单位），当前编辑器只把它作为经显式 `Y +90°` 轴向修正、在世界轴缩放到约 `7.2 × 5.4 × 1.8m` 的单实例视觉层，业务占地、碰撞和库存均来自 ForgeCore 数据；货架不定义输送端口。当前原件没有 LOD、碰撞体或货位语义节点；若进入规模化实例、物理碰撞、RackSlot 寻址或导航仿真，仍必须在 `assets/3d/derived/` 中完成尺度固化、材质统一、LOD、简化碰撞体与语义挂点，并记录与上游 `glb/rack.glb` 的来源关系。

Cels AGV 原始场景已通过容器、几何、依赖、来源许可和离线外观检查。AGV 主体约为 `1.0560 × 0.8884 × 0.8108`（X × Y × Z，模型单位），但原文件还包含两层输送机构、纸箱和约 `41 × 41` 的展示地板，全场景约 7.36 万三角面，且没有动画、LOD、碰撞体或导航语义节点。正式接入仿真前，必须在 `assets/3d/derived/` 中剥离展示地板、重新居中定轴、确认米制尺度、减面与合并材质、生成 LOD/简化碰撞体，并配置车体、轮组、载台和导航锚点等 AGV 语义层。

Count Infinity 无人机原件为自包含 GLB 2.0，共 3 个网格/图元、12,436 个三角形和 3 个 PBR 材质，内嵌 10 张 1024×1024 PNG，无外部 URI、动画、蒙皮、相机或 glTF 扩展。离线外观检查确认其为带大型下挂货舱、封闭圆形推进舱和翼面的未来货运无人机，未发现展示底座、明显缺面、错位、异常穿插或裁切。根节点已旋转为 Y-up，但文件未声明单位、前向轴和业务尺度；总包围盒约为 `33.318 × 58.059 × 52.500` 原始单位，不能直接按米制解释。其 `Cargo`、`Drone`、`Flaps` 只是合并网格，原件没有可独立驱动的旋翼/襟翼节点。当前 Web 单实例视觉适配在不修改 vendor 文件的前提下额外施加 `Y +180°` 固有旋转，使模型可见机头与 ForgeCore 载具航向一致；建造预览和运行实体必须共用该旋转常量，业务航向、路径和碰撞数据不随视觉修正改变。正式接入仿真前，必须在 `assets/3d/derived/` 中确认米制尺度和 +Z 前向，保留合适的飞行枢轴，压缩或降采样贴图，生成 LOD、简化碰撞体与独立导航安全包络，配置 `bodyRoot`、`navigationOrigin`、`cargoMount`，并把不存在的动画明确标记为 unavailable 或登记为程序驱动。vendor 原件技术上可单实例加载，但不作为规模化无人机运行时资产。

# 52. 项目 UI 结构

## 52.1 UI 美术方向

ForgeCore 整体采用：

> **工业数字孪生 + 科技控制中心**

视觉方向以项目归档的 10 张参考图片为大致美术依据，详细提炼、单图摘要、文件索引、SHA-256 与执行审计清单见：

- `docs/ui-art-style-reference.md`
- `docs/assets/ui-style-reference/`

这些图片仅作为 UI 美术风格和视觉方向的大致参考，不是高置信度的真实 UI 设计稿，也不是产品需求、页面结构或交互逻辑的事实来源。

可以严格参考：色彩倾向与明暗氛围；材质、光影、纹理和视觉层次；面板、边框、圆角、装饰和图标语言；字体气质、信息密度和整体视觉节奏；状态反馈的美术表现方式。

不得仅凭参考图片推断或照搬：信息架构和页面布局；功能入口、业务流程和数据结构；字段名称、文案和真实业务状态；交互逻辑、导航关系和权限设计；精确尺寸、断点或设备适配方案。

实际 UI 设计必须以项目需求、业务逻辑、信息层级、可访问性、响应式要求和技术约束为依据。参考图片只约束美术方向；当参考图片与真实需求冲突时，以真实需求和可用性为准，但最终视觉风格仍需尽量保持一致。

## 52.2 核心视觉语言

- 使用白、雾灰、浅灰和炭灰构成洁净、舒适、理性的工业中性基底；深色只用于 3D 场景、必要的控制层和文字层级，不得让大面积纯黑面板主导页面。
- 暖黄色是主要品牌高亮，承担当前态、选中态、关键操作和场景引导；青蓝、绿色、橙色和红色只按稳定的产品语义用于信息、正向、区分与警示。
- 3D 工厂是编辑工作区的第一视觉主体，必须居中并占据绝大部分可视区域；导航、工具、对象库、属性与状态信息以不挤压场景的悬浮窗或浮动工具条叠放在场景周围。
- 面板采用半透明灰白材质、克制圆角、细描边、柔和投影和少量深色标题；组件必须共用统一的圆角、边框、阴影与间距系统，并通过悬浮、展开、收起和状态过渡体现灵动感。
- 标题和关键数字可粗重醒目，正文与字段必须优先保证可读性；不得复用参考图中的示例编号、错字、小字或固定数值。
- 功能图标以统一笔画的黑白线性语言为主，3D 设备缩略图只作为内容资产；状态不能只依赖颜色表达。
- 视觉节奏采用“居中的高密度 3D 场景 + 周边疏朗浮窗”；默认只展示完成当前任务必需的信息，统计明细、许可路径和高级配置按需展开，禁止把大量数据平铺堆砌在主工作区。

## 52.3 UI 决策优先级

UI 设计与实现按以下优先级决策：

```text
真实产品需求与业务规则
→ 用户任务、信息层级与数据关系
→ 可访问性、响应式与技术约束
→ 本节规定的美术方向
→ 单张参考图中的局部构图或装饰
```

参考图中的三栏、左右侧栏、顶部导航、底部控制条或中央大场景只可作为视觉构图观察。页面的信息架构、导航、交互和响应式行为必须依据真实需求重新设计。ForgeCore 当前已经确认的产品原则是“场景优先、工具悬浮、信息渐进披露”；它来自编辑任务本身，也与参考图的灰白工业视觉方向一致。

## 52.4 主界面概念骨架

下列骨架来自 ForgeCore 当前产品功能关系，用于表达全画布 3D 工作区与浮动工具之间的概念分区，不是从参考图片推断的精确尺寸或断点：

```text
┌──────────────────────────────────────────────────────┐
│  ◇ ForgeCore / Factory A     已保存       ▶ 运行      │ ← 浮动顶栏
│                                                      │
│ ┌────┐                                   ┌─────────┐ │
│ │导航│                   3D FACTORY       │属性浮窗 │ │
│ │图标│                   CENTERED         │按需展开 │ │
│ └────┘                                   └─────────┘ │
│                                                      │
│ ┌── 机器 / 货物仓库 / 货架 / 传送带 / AGV / 无人机 / 运行 ┐ │
│ └──── 单击选择 · 鼠标随行 · 网格点击/拖绘建造栏 ───┘ │
└──────────────────────────────────────────────────────┘
```

工厂地块必须表现为有明确边界、尺寸和单元格反馈的实体网格，而不是无边界的装饰性参考线。设施占地、鼠标随行预览、碰撞校验和输送路径均以同一网格坐标为准；进入建造态后应在鼠标指向位置显示所选物体及其占地范围，并在越界或冲突时给出可辨识反馈。所有已放置的非传送带对象，包括机器、货物仓库、货架、缓冲区、AGV 和无人机，均可从场景中按下并拖动调整位置；轻微点击只负责选择，超过移动阈值后才进入拖动态，防止误操作。拖动过程必须持续吸附工厂网格，合法网格实时移动对象，冲突、越界或导致已连接线路与其他建筑/线路相交时保持上一合法位置并显示红色无效目标反馈。机器或仓库移动后，所有已登记的入料/出货传送带端点必须按原端口编号同步重算，不能留下断口，也不能把连接改挂到其他端口；货架移动只更新其占地和视觉，不存在输送端点。

机器、货物仓库、缓存区、AGV、无人机和传送带均从底部建造栏进入场景。建造栏只提供一个通用“机器”建造项，不把不同模型外观误当成不同业务设备；该通用机器统一加载候选 E `machine-fortified.glb`，新机器默认不绑定配方，用户在属性浮窗中自行命名，并从“配方工艺”页面创建的配方中选择绑定。通用机器在 1m 基准网格上采用 `6m × 6m` 偶数占地，机器中心必须落在整数网格交点；可见外壳放大到约 `5.4m × 5.4m`、高 4.8m，并在四周保留约 0.3m 的占地余量。未旋转时本地 `-X/+X` 两侧分别布置编号 1–3 的三个入料口和三个出货口，三条轴线分别偏离机器中心线 `-1/0/+1m`；传送带起点只吸附空闲出货口、终点只吸附空闲入料口，一个端口成功连接后不再参与吸附。机器在手上时用滚轮按 90° 步进旋转，落地后通过文档级 `Q/E` 快捷键或属性按钮旋转；六个端口和已有连接均按编号随机器更新。旧存档中的较小通用机器在恢复时统一迁移为 `6m × 6m`、把中心吸附到当前工厂网格、把视觉引用迁移为候选 E，并为旧连接分配不重复的 1–3 号端口；超过三条的同侧旧连接解除机器端关系，等待用户重新布线。

货物仓库使用候选 F `machine-window.glb` 和 Kenney 纸箱模型组成，采用相同的 6×6 占地、三通道和六端口网格协议。仓库属性浮窗直接列出所有已定义物品、当前数量、手动入库控件和逐物品无限供应开关，同时展示三个入货口和三个出货口的连接状态；每个出货口行内独立提供 `0.25–60` 秒出货间隔，并可分别选择该出货带运输的物品，不再设置仓库级统一节拍。没有物品时提供前往物品定义页的引导。场景仓库上方标签同步显示有限库存总量、无限供应项数和前两项物品名称，使用户不打开物流页也能识别仓库内容。纸箱、黑帘、内部带和库存标签属于场景表现，Inventory 才是数量事实来源。用户单击任一建造项后进入持续建造态，所选物体随鼠标在网格上吸附预览；在任意有效网格位置单击即可放置，并可继续放置同类物体。再次单击当前建造项、按 `Esc` 或单击鼠标右键均立即取消建造；单击另一建造项则直接切换。建造栏卡片本身不是需要拖入场景的对象，各卡片使用统一的灰白容器底色，仅用黄色表达选中、可操作和运行等高亮状态，传送带卡片不得使用独立的常驻黄色背景。

货架在建造栏中与货物仓库并列，采用 mastjie 开放架体、8×2 占地、约为修复前异常拉伸长度一半的架体、四层双排五列共 40 个满载箱体和独立的 `shelf` 业务类型。箱体底面必须按四层层板顶面标高校准，横向覆盖架体而不是挤在两端或悬在架外。其属性浮窗显示“无限堆叠”、实际有限数量和逐物品无限设置，不显示出货间隔、入货口或出货口；有限数量不受总容量上限限制，物流页的容量列显示 `∞`。场景陈列箱体不得替代 Inventory，仓库的 1800 件有限容量规则也不得套用到货架。

底部浮动操作栏采用具有明确职责的多标签结构，不设置含义模糊的“快捷”杂项页。“建造”标签承载建筑和传送带工具，并保留持续建造与取消规则；切换离开该标签时必须退出当前建造态，避免用户在调节其他参数时误放建筑。“运行”标签直接提供启动/暂停、`1×/2×/5×/10×` 倍速、重置、仿真时间、逻辑步数和在途数量，仍保留“空白项目没有有效物流或生产链时禁止启动”的业务门禁。“视图”标签只调整本地场景表现，包括地块网格、端口/库存/对象标签、高质量阴影和当前对象属性面板，不修改工厂业务数据、模型参数或存档内容。标签使用 ARIA `tablist/tab/tabpanel` 语义，当前态只用克制的黄色高亮表达，并在窄屏下重新排布而不挤压中央 3D 画面。

传送带既是可铺设的实体设施，也是连接上下游设备的业务关系。用户单击传送带建造项后，在地块网格上按住指针开始铺设，沿网格拖动并在释放时完成。系统把用户实际经过的格点序列整理为连续水平/垂直段：同方向格点合并为直线，只有轨迹方向真实改变时才自动识别拐点并使用弯道模型；不得为纯直线路径凭空补拐弯，也不得把自由拖绘退化为只看起终点的固定 L 形算法。弯道按模型真实开放边确定朝向，并占用拐点中心的完整转向模块；渲染层以弯道接口为直线段端点，统一裁切两侧直线，禁止直线穿心、弯头反向、模型重叠、断口和极短直线模型缩放畸变。路径可包含零个、一个或多个拐点，可在未连接设备时独立存在；若起点或终点接近机器或货物仓库端口，则自动登记 `fromObjectId/fromPortIndex` 与 `toObjectId/toPortIndex`，并使用位于黑帘之后的对应机内锚点绘制首尾段，不能只连接到占地外轮廓。场景预览与 Store 写入均执行统一的建筑/传送带占用检测，阻止建筑重叠、传送带共格或交叉、建筑覆盖传送带和传送带穿越无关建筑。仿真中的物料必须按各段实际长度沿整条折线路径推进，不能穿过拐角直线插值；多输出机器按每条已连接出货带配置的 `outputItemId` 分流，单输出配方自动映射唯一产物；货物仓库在 TransitItem 抵达帘后锚点时入库，有限库存从出货口发车前扣减并保持跨设施物料守恒，显式开启的无限供应则作为可审计仿真源创建货物且不扣实际数量。

运输的业务结算继续使用 `0.25s` 固定仿真步长，以保证不同帧率下的库存、到货和加工结果一致；显示层不得直接把离散的 `TransitItem.progress` 当作唯一画面坐标。传送带黄色流动标记、机器/仓库内部带面标记和在途物品均应在相邻逻辑状态之间按渲染帧连续推进，并以各段实际长度计算位置，在拐点处沿折线进入下一段且平滑转向，不得表现为逐格跳动或斜切拐角。视觉推进速度必须同步 1×/2×/5×/10×仿真倍速，暂停时立即冻结，重置、恢复或时间回退时重新对齐逻辑状态；插值仅负责表现，严禁提前修改库存、完成到货或绕过固定步长业务判定。

运行时性能采用“固定业务步长、低频状态发布、逐帧视觉插值”的分层契约。应用以 `200ms` 为界面发布周期，在一次隔离的运行时草稿内完成其中全部 `0.25s` 固定步；工厂尺寸、楼层、配方、物品 schema、输送路径等静态设计数据保持引用稳定，只复制会发生变化的仿真、库存和设施状态，禁止按每个固定步深拷贝整份项目。Zustand 页面只订阅所需字段，顶层壳体不得因车辆位置或在途进度变化而整页重绘。AGV 二维 A* 与无人机三维 A* 使用确定性最小堆维护开放集，并按工厂尺寸、楼层与静态设施布局缓存二维阻塞格和三维阻塞体素；动态载具仍实时写入临时障碍。阻挡对象改变时立即重规划，持续动态阻挡按 `8` tick 节流，无静态可达路线时按 `20` tick 重试，避免同一失败搜索每秒重复执行且不牺牲及时绕行。

场景运行时自动关闭实时投影并把渲染像素比压低到约 `0.75–1.15`，暂停后恢复用户“高质量阴影”设置和约 `1–1.5` 像素比；详细 HTML 标签仅为当前选中且可交互的设施显示。机器/仓库内部流动标记、每条传送带的流动标记以及 AGV/无人机路线箭头和中间节点使用 `InstancedMesh` 批量绘制；车辆路线只删除严格同向共线的冗余节点，长路线对未选中车辆均匀稀疏为最多 `12` 个箭头和 `32` 个中间节点，选中车辆提高到 `48/96`，终点、转折、半透明状态色和由车辆向目标外流的方向语义保持不变。本轮性能调整不得改变逐层开关、“仅当前层 / 多层透视 / 多层实显”、上下楼层对称显示或当前层唯一建造网格规则，也不引入新的多层 LOD 行为。

## 52.5 UI 评审门禁

用户可以自行创建任意原料、半成品和成品，但不必为每一个物品重复建模。ForgeCore 以“稳定基础模型 + 参数化变体 + Item 业务数据”为核心：首版 36 个 first-party/core 模型覆盖基础形状、原材料、机械零件、电子部件和包装容器，同一 `modelId` 可通过尺寸、截面、孔径、齿数、圈数、材质和颜色等参数表示大量物品。

官方模型不足时，用户仍可上传自己的 GLB；但物品重量、堆叠数、配方身份和库存状态始终与模型参数分离。这使模型网格能在大量 Item 间复用和实例化，同时保留用户对具体业务物品的自由定义能力。

# 67. 项目核心价值总结

ForgeCore 与普通数字孪生系统最大的区别在于：

传统数字孪生主要解决：

> **“如何把现实中的工厂显示出来？”**

而 ForgeCore 希望进一步解决：

> **“如何自由设计一个工厂？”**

> **“这个工厂能否正常运行？”**

> **“它能生产多少产品？”**

> **“生产瓶颈在哪里？”**

> **“物流系统是否合理？”**

> **“怎样调整才能生产得更快？”**

并最终让 AI 帮助用户回答：

> **“怎样设计一个更好的工厂？”**

因此项目最终不是单纯的：

> 3D 工厂展示系统

而是逐渐发展成为：

# AI-Powered Digital Factory Design, Simulation & Optimization Platform

即：

# AI 驱动的数字工厂设计、仿真与优化平台
